## 접근성

W3C WAI 는 2026년 9월 10일 [WCAG 3 워킹 드래프트 검토 요청](https://www.w3.org/WAI/news/2026-09-10/wcag3/)을 공지했습니다. 2차 소개 자료에 따르면 이번 초안은 기존에 AAA 에 머물던 일부 요건(예: 오디오·비디오의 캡션뿐 아니라 대본 제공)을 필수 계층으로 옮기고, 결과 기반 점수와 Bronze/Silver/Gold 등급을 쓰며 인지·저시력 요구 범위를 넓힙니다([Accessible Web](https://accessibleweb.com/wcag/wcag-3-working-draft-changes/)).

일정 면에서는 W3C 가 완성 표준까지 수년이 더 걸릴 것으로 본다고 알려져 있고, WCAG 2.x 도 폐기되지 않습니다. 즉 지금 컴플라이언스 기준은 여전히 WCAG 2.1/2.2 입니다. 초안은 방향성 파악용으로 읽고, 세부 요건은 바뀔 수 있다는 점을 전제하세요.

현황 데이터는 나쁜 쪽으로 움직였습니다. [WebAIM Million 2026](https://webaim.org/projects/million/)에 따르면 상위 100만 홈페이지에서 총 56,114,377개 오류가 감지됐고 페이지당 평균 56.1개로 전년(51개)보다 10.1% 늘었습니다. WCAG 2 실패가 감지된 페이지는 95.9%(전년 94.8%)이며, 홈페이지당 요소 수는 1,437개로 1년 새 14.3% 늘었습니다. 저대비 텍스트는 83.9%의 페이지에서 나타났고, 대체 텍스트 누락은 절반 이상, 라벨 없는 폼 입력은 약 51%였습니다(요약: [Change in Content](https://www.changeincontent.com/web-accessibility-2026-webaim-report/) 등 2차 보도 기준).

한계: WebAIM 은 자동 검사로 감지 가능한 오류만 셉니다. 자동 도구가 잡지 못하는 키보드 흐름·스크린리더 맥락 문제는 이 수치에 없으므로 실제 접근성은 더 나쁠 수 있습니다.

## 성능

Core Web Vitals 기준은 LCP 2.5초 미만, INP 200ms 미만, CLS 0.1 미만이며 실사용자 75번째 백분위로 판정합니다([Prooflytics](https://prooflytics.io/blog/core-web-vitals-thresholds-2026-lcp-inp-cls)). INP 는 2024년 3월 FID 를 대체했고([web.dev](https://web.dev/blog/inp-cwv-launch)), 모든 상호작용의 지연을 보기 때문에 FID 보다 엄격합니다.

2026년에도 INP 는 가장 자주 실패하는 지표로 언급됩니다. 다만 검색 결과에서 실패율은 "사이트의 43%"와 "2026년 5월 데이터 기준 28%"처럼 출처마다 달랐습니다. 집계 대상·기간이 다르므로 숫자 하나를 벤치마크로 못 박지 말고, 자사 CrUX 데이터로 직접 확인하세요.

## 기술 표준

- WCAG 3 는 워킹 드래프트 단계로, 후보 권고안은 2027년 4분기경, 최종 권고는 2028년 이후로 전망됩니다(2차 자료 기준, W3C 공식 확정 일정 아님).
- 이번 초안에 의견을 낼 수 있는 검토 기간이 열려 있으니 접근성 담당자는 [WAI 공지](https://www.w3.org/WAI/news/2026-09-10/wcag3/)를 확인할 만합니다.

## 오늘 바로 적용할 것

1. 텍스트 대비를 우선 점검한다: 가장 흔한 실패(83.9%)이며 디자인 토큰 한 곳에서 고칠 수 있다.
2. 폼 입력마다 `label` 연결 여부와 이미지 `alt` 를 린트·CI 에 넣는다.
3. 자동 검사(axe, pa11y 등) 통과를 접근성 완료로 보지 말고, 핵심 흐름은 키보드와 스크린리더로 수동 확인한다.
4. CrUX/Search Console 에서 INP 75번째 백분위를 확인하고 200ms 를 넘는 상호작용부터 줄인다.
5. 동영상·오디오 콘텐츠에 캡션과 함께 대본 제공을 검토한다(WCAG 3 방향성 대비).
