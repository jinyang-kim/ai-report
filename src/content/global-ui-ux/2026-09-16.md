## 접근성 — 6년 만의 퇴보, 그리고 미국은 오히려 기한을 늦췄다

[WebAIM Million 2026 보고서](https://webaim.org/projects/million/)(2026년 2월 조사, 3월 30일 공개)는 상위 100만 개 홈페이지를 자동 분석해 **95.9%에서 WCAG 2 결함을 발견**했다고 밝혔습니다. 2025년의 94.8%보다 높아진 수치로, 페이지당 평균 오류도 56.1건으로 전년(51.0건) 대비 10.1% 늘었습니다. 전체 오류는 5,611만 건을 넘었고, 이는 6개 연속 연도 동안 이어지던 개선 추세가 처음으로 꺾인 결과입니다. 가장 흔한 오류는 저대비 텍스트(83.9%, 전년 79.1%)였고, 이미지 대체 텍스트 누락(53.1%)·폼 라벨 누락(51%)·빈 링크(46.3%)·빈 버튼(30.6%)·언어 속성 누락(13.5%)이 뒤를 이었습니다. 같은 기간 페이지당 평균 요소 수가 1,437개로 22.5% 늘어난 점을 함께 보면, 페이지가 복잡해지는 속도를 접근성 관리가 따라가지 못하고 있다는 해석이 가능합니다.

역설적으로 규제 쪽은 속도를 늦췄습니다. 미국 DOJ는 [2026년 4월 20일 발효된 Interim Final Rule](https://www.duanemorris.com/alerts/doj_extends_ada_title_ii_digital_accessibility_deadlines_one_year_0426.html)로 ADA Title II 대상 주·지방정부의 WCAG 2.1 AA 준수 기한을 1년 늦췄습니다 — 인구 5만 이상 관할은 2027년 4월 26일, 미만은 2028년 4월 26일로 조정됐고, 원래 기한을 불과 나흘 앞두고 나온 조치입니다. 다만 이 규칙은 **기술 기준의 적용 시점만 늦춘 것**이며, WCAG 도입 이전부터 접근성 소송의 근거가 돼 온 Title II 본연의 비차별·효과적 소통 의무는 그대로 유지됩니다. 공개 의견수렴은 2026년 6월 22일 마감이었으므로, 이 기한 자체가 최종 확정판인지는 후속 규칙 제정을 지켜볼 필요가 있습니다. 민간 부문에는 이 연장이 적용되지 않으므로, 미국 공공기관을 상대하는 벤더가 아니라면 WebAIM 수치가 보여주는 실제 결함 추세 쪽을 기준으로 삼는 편이 안전합니다.

## 성능 — Core Web Vitals, 모바일 통과율 48%는 여전히 절반 밑

[HTTP Archive의 2025 Web Almanac 성능 챕터](https://almanac.httparchive.org/en/2025/performance)에 따르면 Core Web Vitals 3종(LCP·INP·CLS)을 모두 통과한 사이트는 모바일 48%(2024년 44%에서 소폭 개선), 데스크톱 56%였습니다. 항목별로 보면 격차의 원인이 뚜렷합니다 — **LCP 통과율이 모바일 62%·데스크톱 74%로 세 지표 중 가장 낮아 여전히 최대 병목**이고, INP는 모바일 77%·데스크톱 97%로 기기 간 차이가 가장 컸습니다. 반대로 CLS는 모바일(81%)이 데스크톱(72%)보다 오히려 높아, 레이아웃 안정성만큼은 모바일 환경에서 상대적으로 잘 관리되고 있다는 뜻입니다.

이 데이터는 최적화 우선순위를 명확히 시사합니다. 모바일 트래픽 비중이 큰 서비스라면 LCP 개선(이미지 지연 로딩 최소화, 렌더링 차단 리소스 정리, 서버 응답 시간 단축)에 자원을 먼저 배분하는 편이 통과율을 가장 빠르게 끌어올립니다. INP는 이미 모바일에서도 77%가 통과선을 넘긴 만큼, 남은 23%는 대개 무거운 메인 스레드 작업이 원인인 경우가 많아 개별 인터랙션 프로파일링이 필요합니다.

## 디자인 트렌드 — "AI 피로감" 시대, UI보다 리서치 기반 판단력이 자산이다

[Nielsen Norman Group의 State of UX 2026](https://www.nngroup.com/articles/state-of-ux-2026/)은 2025~2026년 사이 AI에 대한 태도가 "기대"에서 "피로감"으로 옮겨갔다고 진단합니다. 대충 붙인 AI 기능("AI slop")이 흔해지면서 사용자 반응이 식고 있고, 실무자들도 대체 위협·통합 부담·출시 압박에 지쳐가고 있다는 것입니다. 보고서는 "AI 경험에서 신뢰 확보가 2026년의 핵심 디자인 과제가 될 것"이라 짚으며, 이를 위한 조건으로 투명성·통제권·일관성·실패 시 지원 네 가지를 꼽았습니다.

동시에 보고서는 "UI 자체는 점점 차별화 요소가 되기 어렵다"고 말합니다. 디자인 시스템과 컴포넌트 표준화가 보편화되면서 표면적인 화면 디자인만으로는 경쟁 우위를 만들기 어렵고, 대신 **사용자에 대한 깊은 이해에서 나오는 취향(taste)과 판단력, 리서치 기반 통찰**이 남은 차별화 지점이라는 진단입니다. 채용 시장은 UXPA·User Interviews 설문을 인용해 "팀 규모가 안정화되고 있고 향후 성장 가능성도 있다"고 전하지만, 신입 채용 문은 여전히 좁다는 점도 함께 짚었습니다. 이 흐름을 종합하면, 조직 차원에서 AI 기능을 붙이기 전에 사용자 신뢰를 어떻게 쌓을지부터 설계하고, 리서치 역량에 대한 투자를 UI 다듬기보다 우선하는 편이 장기적으로 유리해 보입니다.

## 기술 표준 — Baseline 2026, XSS 방어와 CSS 신기능이 나란히 "안전권" 진입

[web.dev의 Baseline 2026 페이지](https://web.dev/baseline/2026)는 올해 새로 Baseline(주요 브라우저 공통 지원) 지위를 얻은 기능들을 정리했습니다. 보안 쪽에서는 DOM 기반 XSS를 막는 **Trusted Types API**와 압축 효율이 높은 **Zstandard(zstd)** 가 포함됐고, CSS 쪽에서는 컨테이너 스타일 쿼리(`@container style()`), `:open` 셀렉터, `contrast-color()`, `@scope`, `shape()`, 폰트 상대 단위(`rcap`·`rch`·`rex`·`ric`) 등이 이름을 올렸습니다. JS/웹 API 쪽은 `WebTransport`, Navigation API, 공유 워커에서의 ES 모듈, `Map.getOrInsert()`, `Iterator.concat()` 등이 대상입니다.

Trusted Types와 컨테이너 스타일 쿼리처럼 그동안 폴리필이나 우회 구현으로 대응해 온 기능이 다수 포함된 만큼, 해당 폴리필을 네이티브 구현으로 교체할 시점을 검토할 만합니다. 다만 Baseline "Newly available"은 최신 버전 브라우저 기준 지원을 뜻하고 "Widely available"(30개월 경과)과는 실무 적용 안전선이 다르므로, 프로덕션 도입 전 web.dev 페이지에서 각 기능의 정확한 상태를 확인하는 절차를 거치는 편이 좋습니다.

## 오늘 바로 적용할 것

1. **저대비 텍스트부터 먼저 점검하세요.** WebAIM Million 2026에서 가장 흔한 오류(83.9%)이자 자동 검사 도구로 바로 잡아낼 수 있는 항목입니다 — 본문·버튼·폼 라벨의 명도 대비를 WCAG AA(4.5:1) 기준으로 다시 재보는 것만으로도 최다 오류 유형을 줄일 수 있습니다.
2. **미국 공공기관 대상 서비스가 아니라면 DOJ 기한 연장을 "여유"로 오독하지 마세요.** 연장은 공공기관의 기술 기준 적용 시점만 늦췄을 뿐 Title II의 비차별 의무 자체는 유지되고, 민간 사업자에는 애초에 적용되지 않는 규정입니다.
3. **모바일 성능 예산은 LCP 개선에 먼저 배분하세요.** Web Almanac 데이터상 LCP가 모바일에서 가장 낮은 통과율(62%)을 보이는 지표이므로, INP·CLS보다 LCP 최적화(이미지 우선순위 힌트, 렌더링 차단 리소스 제거)가 CWV 종합 통과율을 가장 빠르게 끌어올립니다.
