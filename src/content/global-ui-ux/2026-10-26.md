## 접근성: 2026 WebAIM Million 이 보여준 후퇴

상위 100만 홈페이지를 자동 검사하는 WebAIM Million 2026 판에서 홈페이지의 95.9% 가 탐지 가능한 WCAG 2 위반을 갖고 있었습니다(2025년 94.8%). 페이지당 평균 오류는 56.1개로 전년보다 10.1% 늘었습니다. ([Priority Pixels 정리](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/))

| 오류 유형 | 영향 받은 홈페이지 |
| --- | --- |
| 저대비 텍스트 | 83.9% (2025년 79.1%) |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 선언 누락 | 13.5% |

이 여섯 유형이 탐지된 오류의 96% 를 차지합니다. ([Priority Pixels](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/))

- ARIA 사용량은 1년 새 27% 늘었지만, ARIA 가 있는 페이지의 평균 오류는 59.1개로 없는 페이지(42개)보다 많았습니다. ARIA 를 쓴다고 접근성이 좋아지는 것은 아니며 복잡도 증가의 신호일 수 있습니다. ([Priority Pixels](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/))
- 홈페이지 평균 요소 수는 1,437개로 1년 새 22.5% 늘었습니다. 오류 증가의 배경으로 지목되지만 인과관계가 확인된 것은 아닙니다.
- 한계: 자동 검사는 전체 접근성 문제의 일부만 잡습니다. 실제 비준수 비율은 이 수치보다 높을 가능성이 큽니다. 또한 수치는 2차 보도에서 확인한 것으로, WebAIM 원문과 대조가 필요합니다.

## 기술 표준: WCAG 3.0 은 아직 초안

W3C 는 2026년 3월 3일 WCAG 3 Working Draft 갱신본을 의견 수렴용으로 공개했습니다. 공지는 변경 내용을 직접 나열하지 않고 WCAG 3 소개 페이지의 "In-progress drafts" 항목으로 안내하며, 확정 일정도 제시하지 않습니다. ([W3C WAI](https://www.w3.org/WAI/news/2026-03-03/wcag3))

> 컴플라이언스 근거는 당분간 WCAG 2.2 이고, WCAG 3 는 방향을 미리 파악하는 용도입니다.

검색 결과에는 2026년 9월자 새 버전이 목록에 있다는 언급도 있으나 내용은 확인하지 못했습니다. 공식 문서 [W3C Accessibility Guidelines (WCAG) 3.0](https://www.w3.org/TR/WCAG30/)에서 최신 상태를 직접 확인하세요.

## 성능: Core Web Vitals 기준

2026년에도 Core Web Vitals 기준은 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하이며, 모바일·데스크톱 각각 사용자의 75번째 백분위로 평가합니다. 데이터는 CrUX 의 28일 롤링 창을 씁니다. ([eseospace](https://eseospace.com/blog/core-web-vitals-in-2026-what-changed-what-still-matters-and-how-to-pass/))

## 오늘 바로 적용할 것

1. 본문·UI 텍스트 색 대비를 점검해 일반 텍스트 4.5:1 미달 토큰을 고치세요. 가장 흔한 오류(83.9%)입니다.
2. 아이콘 전용 링크·버튼에 접근 가능한 이름(`aria-label` 또는 숨김 텍스트)이 있는지, 폼 입력에 `label` 이 연결됐는지 확인하세요.
3. `<html lang>` 선언과 이미지 `alt` 를 린트로 CI 에 넣으세요.
4. 불필요한 ARIA 를 걷어내고 네이티브 요소(`button`, `details`)를 먼저 쓰세요.
5. 자동 검사 통과를 접근성 완료로 보지 말고, 스크린리더·키보드 수동 점검을 병행하세요.
