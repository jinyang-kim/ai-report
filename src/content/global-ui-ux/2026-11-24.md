## 접근성

2026년 2월 상위 100만 홈페이지를 자동 검사한 [WebAIM Million](https://webaim.org/projects/million/)에 따르면 페이지당 평균 오류는 56.1개로 전년(51개)보다 약 10% 늘었고, WCAG 2 실패가 탐지된 페이지 비중도 94.8%에서 95.9%로 올랐습니다. 개선 추세가 꺾인 해입니다.

가장 흔한 오류 6가지는 [WebAIM Million](https://webaim.org/projects/million/) 기준 아래와 같습니다.

| 오류 | 홈페이지 비중 |
| --- | --- |
| 낮은 텍스트 대비 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 라벨 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

ARIA 사용 페이지는 82.7%로 늘었고, ARIA가 있는 페이지의 평균 오류는 59.1개로 없는 페이지(42개)보다 많았습니다. ARIA 메뉴가 있는 홈페이지의 22%는 오히려 장벽을 만들었습니다([WebAIM Million](https://webaim.org/projects/million/)). 다만 이는 상관관계이며, ARIA가 오류의 원인이라는 증거는 아닙니다.

**한계**: 자동 검사는 탐지 가능한 오류만 셉니다. 오류가 0개여도 WCAG 적합성이 보장되지 않고, 홈페이지만 대상이라 서비스 내부 화면의 상태를 대표하지 못합니다.

## 성능

[Chrome UX Report 릴리스 노트](https://developer.chrome.com/docs/crux/release-notes)의 2026년 10월 데이터(11월 11일 공개)에서 good 판정을 받은 origin 비율은 다음과 같습니다.

| 지표 | 2026년 1월 | 2026년 10월 |
| --- | --- | --- |
| Core Web Vitals 전체 | 55.7% | 56.3% |
| INP | 87.1% | 85.2% |
| LCP | 68.3% | 68.8% |
| CLS | 80.9% | 81.6% |

전체 통과율은 10개월간 55.3～56.5% 범위에 머물렀습니다. INP는 1월 87.1%에서 10월 85.2%로 소폭 내려갔고, LCP가 가장 낮은 지표입니다([CrUX 릴리스 노트](https://developer.chrome.com/docs/crux/release-notes)). 10월 수치는 소프트 내비게이션을 제외한 값입니다. 릴리스 노트는 2027년 5월부터 이를 포함할 예정이며, 포함 시 전체 통과율이 60.3%로 추정된다고 밝혔습니다.

**한계**: CrUX는 Chrome 사용자의 실사용 데이터이고 origin 단위 집계라, 개별 페이지나 다른 브라우저 사용자의 경험과 다를 수 있습니다.

## 기술 표준

W3C는 [2026년 3월 WCAG 3 워킹 드래프트](https://www.w3.org/WAI/news/2026-03-03/wcag3)의 검토를 요청했고, 이후 9월에도 드래프트가 갱신된 것으로 검색에서 확인됩니다. 다만 9월 판 본문은 직접 열어 확인하지 못했으므로 세부 내용은 인용하지 않습니다. [WCAG 3 소개 페이지](https://www.w3.org/WAI/WCAG3)에 따르면 WCAG 3은 WCAG 2를 대체하지 않으며, 최종 확정 후에도 WCAG 2는 수년간 폐기되지 않습니다. 즉 현재 컴플라이언스 기준은 WCAG 2.x입니다.

## 오늘 바로 적용할 것

- **대비**: 가장 흔한 오류(83.9%)부터 점검하세요. 디자인 토큰 단계에서 텍스트 대비 4.5:1을 라이트·다크 모드 양쪽에 검증합니다.
- **이름 없는 컨트롤**: 아이콘만 있는 링크·버튼에 접근 가능한 이름이 있는지, 폼 입력에 라벨이 연결됐는지 CI 자동 검사에 포함하세요.

- **자동 검사 보완**: 자동 도구는 일부만 잡으므로 키보드 탐색과 스크린리더 수동 점검을 릴리스 체크리스트에 두세요.
