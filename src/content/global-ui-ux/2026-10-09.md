## 접근성: 2026 WebAIM Million 은 악화를 보였다

2026 WebAIM Million 에서 자동 검사로 잡히는 WCAG 2 위반이 있는 홈페이지는 95.9%로, 2025년의 94.8%에서 늘었다. 페이지당 평균 오류는 56.1개로 10.1% 증가했다([Priority Pixels 요약](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/)). 같은 요약에 따르면 페이지당 평균 요소 수는 1,437개로 1년 새 22.5% 늘었다. 페이지가 복잡해지는 속도를 접근성 개선이 따라가지 못하는 셈이다.

오류 유형은 7년째 거의 같다. 아래 여섯 가지가 검출 오류의 96%를 차지한다([Priority Pixels 요약](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/)).

| 오류 유형 | 해당 홈페이지 비율 |
| --- | --- |
| 저대비 텍스트 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 레이블 누락 | 51% |
| 텍스트 없는 링크 | 46.3% |
| 텍스트 없는 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

**한계**: 자동 검사는 접근성 문제의 일부만 잡으므로 실제 미준수 비율은 더 높을 가능성이 크다. 또 출처마다 적용 기준(WCAG 2 A/AA 등) 표기가 달라, 정확한 기준은 WebAIM 원문 확인이 필요하다.

## 성능: Core Web Vitals 는 개선 중이지만 절반 남짓

2026년 8월 CrUX 릴리스에서 18,294,881개 오리진 중 55.6%가 Core Web Vitals 양호 판정을 받았다. 2021년 2월에는 약 22%였다([Core Web Vitals in 2026](https://anim.hr/en/blog/core-web-vitals-2026)). INP 는 2024년 3월 12일 FID 를 대체했고, 양호 기준은 200ms 미만이다(200～500ms 개선 필요, 500ms 초과 불량). 판정은 실사용자 75번째 백분위수 기준이다.

**한계**: CrUX 는 Chrome 사용자만 표본으로 삼는다. 랩 도구(Lighthouse)는 한 번의 로드만 보므로 INP 를 신뢰성 있게 재현하지 못한다. 검색 순위에 미치는 영향 정도도 업계에서 의견이 갈린다.

## 기술 표준: WCAG 3.0 은 아직 작업 초안

W3C 는 2026년 3월 3일 WCAG 3 작업 초안을 검토용으로 공개했다([W3C WAI 공지](https://www.w3.org/WAI/news/2026-03-03/wcag3)). 문서 자체가 "진행 중인 작업 외의 것으로 인용하기 부적절하다"고 경고한다([WCAG 3.0 초안](https://www.w3.org/TR/2026/WD-wcag-3.0-20260303/)). 검색 결과에는 9월 날짜의 후속 초안 주소도 보였으나 내용은 확인하지 못했다. 법적·조달 준수는 지금처럼 WCAG 2.2 를 기준으로 두고, WCAG 3.0 은 중장기 계획용으로 보는 것이 안전하다.

## 오늘 바로 적용할 것

- 우리 사이트의 상위 여섯 오류(대비·대체 텍스트·폼 레이블·링크/버튼 이름·`lang`)를 자동 검사로 먼저 0 으로 만든다.
- 자동 검사 통과 후 키보드 조작과 스크린리더로 핵심 흐름을 수동 점검한다.
- CrUX/PageSpeed Insights 에서 INP 필드 데이터를 확인하고, 200ms 를 넘는 상호작용을 찾아 개선한다.
- WCAG 3.0 은 모니터링만 하고 계약·감사 기준은 WCAG 2.2 로 유지한다.
