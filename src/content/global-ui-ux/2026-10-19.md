## 접근성: 자동 검사로 보이는 부분조차 나빠졌다

[WebAIM Million](https://webaim.org/projects/million/) 2026년 2월 분석(상위 100만 홈페이지)에서 **95.9%** 가 자동 검사로 감지되는 WCAG 2 실패를 가졌습니다(2025년 94.8%). 페이지당 평균 오류는 **56.1개**로 전년 51개에서 10.1% 늘었고, A/AA 완전 준수는 4.1% 미만입니다.

| 오류 유형 | 해당 페이지 비율 |
| --- | --- |
| 저대비 텍스트 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 라벨 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

이 여섯 유형이 감지 오류의 96% 를 차지합니다([WebAIM](https://webaim.org/projects/million/)). 즉 대부분은 새로운 문제가 아니라 오래된 기본기 문제입니다.

ARIA 사용도 늘었습니다. 82.7% 의 페이지가 ARIA 를 쓰고(전년 79.4%), ARIA 가 있는 페이지는 평균 59.1개 오류로 없는 페이지의 42개보다 많았습니다([WebAIM](https://webaim.org/projects/million/)). 상관관계일 뿐 인과는 아니지만, 복잡한 UI 일수록 오류가 많다는 신호입니다.

**한계**: 자동 검사는 WCAG 위반의 일부만 잡습니다. 실제 비준수율은 이 수치보다 높을 가능성이 큽니다. 또 이 조사는 홈페이지만 대상이라 로그인 이후 화면은 반영하지 않습니다.

## 성능: INP 는 양호, LCP 가 발목

[Chrome UX Report 릴리스 노트](https://developer.chrome.com/docs/crux/release-notes)의 2026년 9월 데이터(10월 13일 게시)는 다음과 같습니다.

| 지표 | 좋음 origin 비율 |
| --- | --- |
| LCP | 68.3% |
| CLS | 81.7% |
| INP | 85.4% |
| 전체 Core Web Vitals | 55.9% |

세 지표 중 LCP 가 가장 낮아 전체 통과율의 병목입니다. 전월 대비 변화는 0.1～0.5%p 로 완만합니다. 이 수치는 origin 단위 필드 데이터(CrUX)이므로 페이지 단위나 실험실 측정과는 다를 수 있고, Chrome 사용자만 포함된다는 한계가 있습니다.

## 기술 표준: WCAG 3 은 아직 초안

W3C WAI 는 2026년 3월 3일 [WCAG 3 작업 초안 갱신](https://www.w3.org/WAI/news/2026-03-03/wcag3)을 공지하고 피드백을 요청했습니다. 변경 내역은 해당 문서의 "In-progress drafts" 항목에서 확인하도록 안내하고 있습니다. 작업 초안은 규범 문서가 아니므로 법규·계약상 준수 기준은 계속 WCAG 2.2 로 두는 것이 안전합니다.

## 오늘 바로 적용할 것

- 대비: 디자인 토큰의 텍스트 색을 4.5:1(큰 글자 3:1) 기준으로 일괄 점검합니다. 가장 흔한 오류(83.9%)를 가장 싸게 줄이는 방법입니다.
- 이름 없는 컨트롤: 아이콘 버튼·링크에 접근 가능한 이름이 있는지, 폼 입력에 `label` 이 연결됐는지 확인합니다.
- ARIA: 네이티브 요소로 대체 가능한 곳의 `role`·`aria-*` 를 제거합니다.
- 성능: 자사 CrUX 에서 LCP 가 나쁘다면 INP 보다 LCP 요소(히어로 이미지·폰트)부터 손봅니다.
- 자동 검사 통과를 끝으로 보지 말고 키보드·스크린리더 수동 점검을 병행합니다.
