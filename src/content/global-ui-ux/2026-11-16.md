## 접근성

| --- | --- |
| 저대비 텍스트 | 83.9% |

([WebAIM Million](https://webaim.org/projects/million/)) 이 여섯 유형이 검출 오류의 96% 를 차지합니다. 즉 소수의 고질적 실수만 고쳐도 효과가 큽니다.

ARIA 사용도 늘었습니다. 홈페이지의 82.7% 가 ARIA 를 쓰고 페이지당 133개 넘는 속성을 가지며, ARIA 가 있는 페이지의 평균 오류(59.1개)가 없는 페이지(42개)보다 많았습니다. 다만 보고서는 ARIA 가 많은 페이지가 대체로 더 복잡하다는 점을 들어 ARIA 자체가 원인이라고 단정하지 않습니다 ([WebAIM Million](https://webaim.org/projects/million/)).

한계: 자동 도구는 스크린리더 사용성, 키보드 흐름, 문맥상 적절한 대체 텍스트를 판정하지 못하며, 홈페이지만 스캔하므로 로그인 뒤 화면이나 결제 흐름은 반영되지 않습니다.

모바일의 최대 병목은 LCP 입니다. LCP 요소는 모바일 페이지의 76% 가 이미지이고, LCP 이미지의 57% 가 JPG, WebP 는 11% 입니다. `fetchpriority="high"` 는 모바일 약 17%, preload 는 약 2% 만 쓰며, 약 16～17% 의 페이지는 LCP 이미지를 지연 로딩해 오히려 불리해질 수 있습니다 ([Web Almanac 2025](https://almanac.httparchive.org/en/2025/performance)).

## 기술 표준

[WCAG 3.0 작업 초안](https://www.w3.org/TR/wcag30/)이 2026년 9월 10일자로 게시됐습니다. 'Developing' 상태에 도달한 요구사항만 담고 있고, W3C 의 승인을 뜻하지 않으며 언제든 바뀔 수 있습니다. WCAG 3 은 WCAG 2.2 의 후속이지만 **WCAG 2 를 폐기하지 않으며**, WCAG 2 는 많은 나라에서 오랫동안 요구될 것이라고 명시합니다. WCAG 2.2 A·AA 를 충족한 콘텐츠는 WCAG 3 최소 적합 수준의 대부분을 충족할 것으로 기대되지만, 새 테스트와 점수 방식 때문에 추가 작업이 필요합니다 ([W3C](https://www.w3.org/TR/wcag30/)).

## 오늘 바로 적용할 것

- 디자인 토큰의 텍스트·배경 조합을 WCAG 2.2 AA(일반 텍스트 4.5:1) 기준으로 CI 에서 계산해 검사합니다.
- 모든 `input` 에 연결된 `label` 이 있는지, 아이콘만 있는 링크·버튼에 접근 가능한 이름이 있는지 점검합니다.
- `<html lang>` 이 지정돼 있는지 확인합니다.
- LCP 이미지에는 `loading="lazy"` 를 빼고 `fetchpriority="high"` 를 검토합니다.
- WCAG 3.0 은 모니터링만 하고, 규정 준수 기준은 당분간 WCAG 2.2 로 유지합니다.
