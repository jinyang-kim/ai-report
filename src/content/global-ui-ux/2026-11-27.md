## 접근성: 상위 100만 홈페이지는 오히려 나빠졌다

2026년 2월 스캔 기준 [WebAIM Million](https://webaim.org/projects/million/)은 홈페이지당 평균 오류를 56.1개로 집계했다. 전년 51개에서 약 10% 늘었고, 자동 검사로 WCAG 2 실패가 잡힌 홈페이지 비율도 94.8%에서 95.9%로 올랐다.

| 오류 유형 | 영향받은 홈페이지 비율 |
| --- | --- |
| 낮은 텍스트 대비 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

출처: [WebAIM Million](https://webaim.org/projects/million/)

ARIA 사용은 계속 늘고 있다. 홈페이지당 평균 133개 이상의 ARIA 속성이 검출됐고 1년 새 27% 증가했다. 같은 보고서에서 ARIA 를 쓴 페이지의 평균 오류는 59.1개로, 쓰지 않은 페이지의 42개보다 많았다 ([WebAIM Million](https://webaim.org/projects/million/)). 이는 ARIA 가 오류를 만든다는 인과가 아니라, 복잡한 페이지일수록 ARIA 를 많이 쓰고 오류도 많다는 상관일 가능성이 크다.

**한계**: 이 수치는 자동 검사가 잡을 수 있는 오류만 센 것이다. 키보드 조작성, 스크린리더 읽기 순서처럼 사람이 확인해야 하는 문제는 포함되지 않아 실제 접근성 수준은 더 낮을 수 있다. 또 홈페이지만 대상이라 로그인 뒤 화면이나 결제 흐름은 반영하지 못한다.

## 성능: 전체 통과율은 56%대, 병목은 LCP

[Chrome UX Report 릴리스 노트](https://developer.chrome.com/docs/crux/release-notes)에 따르면 2026년 10월 데이터(2026년 11월 11일 공개)에서 세 지표를 모두 통과한 origin 은 56.3%다. 지표별로는 다음과 같다.

| 지표 | 좋음 비율(origin) |
| --- | --- |
| LCP | 68.8% |
| INP | 85.2% |
| CLS | 81.6% |

출처: [CrUX release notes](https://developer.chrome.com/docs/crux/release-notes)

INP 는 도입 초기의 우려와 달리 통과율이 80%대 중반이고, 전체 통과를 가로막는 쪽은 LCP 다. 이미지 우선순위 지정, 서버 응답 시간, 렌더 차단 리소스 점검이 가장 효과가 큰 영역이라는 뜻이다.

**한계**: CrUX 는 Chrome 사용자 중 데이터 공유에 동의한 방문만 집계하고, 수치는 페이지가 아닌 origin 단위다. 트래픽이 큰 소수의 페이지가 나머지 페이지의 문제를 가릴 수 있다.

## 기술 표준: WCAG 3.0 은 아직 초안

W3C 는 [2026년 3월 3일 WCAG 3 Working Draft 갱신](https://www.w3.org/WAI/news/2026-03-03/wcag3)을 공개하고 의견을 받았다. [WCAG 3 소개 페이지](https://www.w3.org/WAI/WCAG3)에 따르면 이 초안에는 Developing 단계에 도달한 가이드라인과 요구사항이 담기고, Exploratory 단계 항목은 Editor's Draft 에 남아 있다. 이후 개정본이 나왔다는 2차 자료도 있었으나 W3C 공식 페이지에서 직접 확인하지 못해 여기서는 다루지 않는다.

실무 결론은 단순하다. 컴플라이언스 대응은 계속 WCAG 2.2 AA 를 기준으로 하고, WCAG 3 은 방향성을 읽는 참고 자료로 보면 된다.

## 오늘 바로 적용할 것

- **대비 점검**: 가장 흔한 오류(83.9%)다. 본문·보조 텍스트·placeholder 색을 4.5:1 기준으로 점검한다.
- **레이블·빈 요소 정리**: 아이콘 전용 버튼과 링크에 접근 가능한 이름이 있는지, 폼 입력마다 `label` 이 연결돼 있는지 확인한다.
- **ARIA 줄이기**: 네이티브 HTML 요소로 해결되는 곳의 ARIA 를 걷어낸다.
- **LCP 요소 확인**: 주요 템플릿의 LCP 요소를 찾아 우선순위 힌트와 서버 응답 시간부터 점검한다.
- **자동 검사 뒤 수동 검사**: 자동 도구를 통과해도 키보드만으로 핵심 흐름을 끝까지 수행해 본다.
