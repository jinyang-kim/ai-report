## 접근성 — WCAG 3.0, AAA 전용이던 요구사항이 핵심 등급으로 올라간다

[W3C WAI 가 9월 10일 갱신한 WCAG 3.0 워킹 드래프트](https://www.w3.org/WAI/news/2026-09-10/wcag3/)는 컨포먼스 모델을 손보는 동시에, 지금까지 최고 난이도인 AAA 에서만 요구되던 항목 여럿을 **필수(Core) 등급으로 올렸습니다**. [Accessible Web 의 변경점 정리](https://accessibleweb.com/wcag/wcag-3-working-draft-changes/)에 따르면 새로 핵심 등급에 들어간 항목은 자막뿐 아니라 오디오·영상 콘텐츠의 **텍스트 전사본**, 화면에는 나오지만 말로는 언급되지 않는 내용을 설명하는 **오디오 설명**, "HTML"처럼 이미 굳어진 단어가 아닌 약어가 처음 나올 때 붙이는 **평문 설명**, 장문 기사 상단의 **검색 가능한 요약**입니다.

컨포먼스 모델 자체도 바뀝니다. 기존 A/AA/AAA 3단계 대신 **핵심(Core, 필수 최저선)·보완(Supplemental, 기본선 초과)·단언(Assertions, 합격/불합격이 아닌 정책·프로세스 문서화)** 구조로 재편했고, W3C 는 이 접근과 대안 채점 모델에 대한 의견을 공개적으로 수집 중입니다. 다만 당장 바뀌는 것은 없습니다 — WCAG 2.1 Level AA 는 ADA Title II 준수 기한(2027년 4월 26일·2028년 4월 26일)이 걸린 현행 법적 기준으로 남아 있고, WCAG 3.0 은 여전히 초안이라 W3C 는 2.x 버전을 폐기할 계획이 없다고 밝혔습니다. 지금 당장 실무 체크리스트를 바꿀 필요는 없지만, 전사본·오디오 설명처럼 지금은 "있으면 좋은" 항목이 몇 년 안에 필수가 될 방향성은 미리 알아둘 가치가 있습니다.

## 성능 — Chrome, CrUX 에 광고 부하 측정치 4종을 실험적으로 얹다

[Chrome 개발자 블로그(9월 15일, Alex Cone)](https://developer.chrome.com/blog/crux-ad-metrics)는 Chrome UX Report(CrUX)에 **실험적 광고 메트릭 4종**을 추가했다고 밝혔습니다. 뷰포트 안에 동시에 보이는 광고 개수(**Ad Count**), 뷰포트 면적 중 광고가 차지하는 비율(**Ad Density**), 광고가 소비하는 네트워크 자원을 바이트로 잰 값(**Ad Weight: Network**), CPU 자원을 밀리초로 잰 값(**Ad Weight: CPU**)입니다. 광고주·퍼블리셔가 특정 사이트의 광고 경험을 공개 데이터로 확인할 수 있게 하려는 목적이며, CrUX API·CrUX History API·Chrome DevTools 의 Ads 패널을 통해 접근할 수 있습니다.

네 지표 모두 데이터셋에 "experimental" 로 표시돼 있고, Chrome 은 **벤치마크 수치를 제시하지도 검색 랭킹 요소로 규정하지도 않았다**고 명시했습니다. 데이터 가용성은 발표 시점부터 한 달에 걸쳐 점진적으로 확대될 예정입니다. Core Web Vitals 와는 별개 지표이지만, 광고 밀도가 높은 페이지에서 LCP·INP 저하 원인을 진단할 때 참고할 수 있는 보조 신호로 쓰일 가능성이 있습니다.

## 디자인 트렌드 — "AI 기능"을 넣기 전에 물어야 할 세 가지 질문

[Nielsen Norman Group 이 9월 18일 낸 스터디 가이드](https://www.nngroup.com/articles/designing-ai-study-guide/)(Tanner Kohler)는 **"Powered by AI" 자체는 가치 제안이 아니다**라는 전제에서 출발합니다. AI 기능을 넣기 전에 실제 사용자 문제를 해결하는지, 기존 기능으로는 불가능한 일인지, 투자 대비 가치가 명확한지 **세 가지를 먼저 판단**하라고 권합니다.

> "'Powered by AI'는 가치 제안이 아닙니다."

가이드는 AI 가 특히 강점을 보이는 영역을 콘텐츠 생성·요약·기초 데이터 분석·관점 제시 네 가지로 좁히고, 사이트 챗봇을 설계할 때는 기능을 명확히 표시하고, 관련 프롬프트를 미리 제안하고, 대화보다 직결된 답변을 우선하고, 투명성을 유지하라는 식으로 구체적인 지침을 제공합니다. 프롬프트 입력창 역시 맥락에 맞는 제안을 곁들이고 사용자의 숙련도에 따라 그래픽 UI 와 자유 입력을 함께 배치하라고 조언합니다. 기술을 앞세우기보다 사용자 니즈에서 거꾸로 설계하라는 원칙은, 이번 주 앞서 다룬 "AI 생성 속도가 UX 평가 속도를 앞지른다"는 문제의식과도 맞닿아 있습니다.

## 기술 표준 — Interop 2027 제안, 오늘 접수 마감

[web.dev 공지](https://web.dev/blog/interop-2027-proposals)에 따르면 Apple·Google·Microsoft·Mozilla·Igalia 가 공동 운영하는 **Interop 2027** 제안 접수가 9월 3일부터 진행돼 **오늘(9월 23일) 마감**됩니다. 제안은 이미 최소 한 브라우저에 구현돼 있고 반대 의견 없는 안정된 사양(stable specification)이어야 하며, 검증을 위한 충분한 테스트 스위트를 갖춰야 한다는 조건이 걸려 있습니다. [GitHub 의 2027 선정 프로세스 문서](https://github.com/web-platform-tests/interop/blob/main/2027/selection-process.md)는 마감 후 제출된 기능들을 같은 기준으로 심사한다고 설명합니다.

webstatus.dev 로 적합한 후보 기능을 찾고 developer-signals 저장소로 실제 개발자 요구를 확인하라는 안내가 이번 공모의 새로운 점입니다. 최종 스코프 공개는 **2027년 2월 초** 예정이라, 오늘 접수된 제안이 실제 반영 여부를 확인하려면 넉 달 넘게 기다려야 합니다.

## 오늘 바로 적용할 것

1. **접근성 로드맵에 텍스트 전사본·오디오 설명 항목을 미리 올려두세요.** 지금은 AAA 전용이라 선택 사항이지만, WCAG 3.0 워킹 드래프트에서 핵심 등급으로 이동해 향후 요구사항이 될 가능성이 큽니다. 단, 지금 당장의 법적 준수 기준은 여전히 WCAG 2.1 AA 입니다.
2. **광고 비중이 큰 페이지의 성능 저하를 진단할 때 CrUX 의 새 Ad Weight/Density 지표를 참고하세요.** 실험적 지표라 벤치마크는 없지만, 광고 스크립트가 LCP·INP 에 미치는 영향을 정량으로 확인할 수 있습니다.
3. **AI 기능을 기획하기 전에 "사용자 문제를 푸는가·기존 기능으로 불가능한가·투자 대비 가치가 있는가" 세 질문부터 던지세요.** NN/G 가이드의 체크리스트를 초기 기획 단계에 끼워 넣으면 "AI 를 위한 AI" 기능을 걸러낼 수 있습니다.
4. **표준화하고 싶은 웹 플랫폼 기능이 있다면 오늘 안에 GitHub 이슈로 제출하세요.** Interop 2027 제안 접수가 오늘 마감되며, 다음 기회는 2027년까지 없습니다.
