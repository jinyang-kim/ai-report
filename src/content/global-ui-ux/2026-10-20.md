## 접근성

2026년 2월에 수행한 [WebAIM Million](https://webaim.org/projects/million/) 은 상위 100만 개 홈페이지 중 **95.9%** 에서 WCAG 2 실패가 감지됐다고 보고합니다(2025년 94.8%). 페이지당 평균 오류는 **56.1개**로 2025년의 51개에서 늘었습니다.

| 오류 유형 | 해당 홈페이지 비율 |
| --- | --- |
| 낮은 대비 텍스트 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

이 여섯 유형이 감지된 오류의 96% 를 차지합니다([WebAIM](https://webaim.org/projects/million/)). 사용자 영향으로 보면 이름 없는 링크·버튼은 스크린리더 사용자가 해당 컨트롤의 용도를 알 수 없게 만들고, 레이블 없는 폼은 입력 자체를 막습니다.

ARIA 사용률은 82.7%(2025년 79.4%)까지 올랐지만, ARIA 가 있는 페이지의 평균 오류는 59.1개로 없는 페이지의 42개보다 많습니다([WebAIM](https://webaim.org/projects/million/)). 상관관계일 뿐 인과는 아니며(복잡한 페이지일수록 ARIA 를 더 쓰는 경향), 그래도 네이티브 HTML 우선 원칙을 뒷받침하는 수치입니다.

**한계:** 이 수치는 자동 검사로 잡히는 항목만 센 것이고, 홈페이지만 대상이라 하위 페이지·로그인 후 화면은 빠져 있습니다. 실제 비준수율은 더 높을 가능성이 큽니다.

## 성능

[web.dev](https://web.dev/articles/inp) 에 따르면 INP 는 클릭·탭·키보드 상호작용의 지연(입력 지연 + 핸들러 처리 + 렌더 지연)을 방문 전체에 걸쳐 재고, 50회당 하나의 이상치를 제외한 최악 값을 페이지 조회들의 **75퍼센타일**로 보고합니다.

- 좋음: 200ms 이하
- 개선 필요: 200～500ms
- 나쁨: 500ms 초과

FID 가 첫 입력만 보던 것과 달리 INP 는 세션 내내의 반응성을 봅니다. 실측 수집은 `web-vitals` 라이브러리가 `visibilitychange` 처리까지 맡아 줍니다. 2차 블로그들이 인용하는 통과율 통계(약 48% 등)는 1차 출처에서 확인하지 못해 이 리포트에는 싣지 않습니다.

## 기술 표준

W3C 는 [WCAG 3 작업 초안을 2026년 3월 3일에 갱신](https://www.w3.org/WAI/news/2026-03-03/wcag3)하고 이메일(wai@w3.org)과 GitHub 이슈로 의견을 받고 있습니다. 작업 초안은 언제든 바뀌거나 폐기될 수 있는 문서이므로 법적·계약상 준수 기준은 계속 WCAG 2.2 로 보는 것이 안전합니다. 이번 갱신의 세부 변경 내용은 확인한 1차 페이지에 나와 있지 않아 다루지 않습니다.

## 오늘 바로 적용할 것

- 자사 페이지에서 상위 6개 오류(대비·alt·폼 레이블·빈 링크·빈 버튼·`lang`)를 자동 검사 규칙으로 CI 에 넣기
- 아이콘 전용 버튼·링크에 접근 가능한 이름이 있는지 점검하기
- 불필요한 ARIA 를 걷어내고 네이티브 요소(`button`, `label`, `a`)로 대체하기
- 실사용자 데이터(RUM)로 INP 75퍼센타일을 확인하고 200ms 를 넘는 상호작용 찾기
- 자동 검사 통과 뒤에도 키보드·스크린리더 수동 점검을 병행하기
