## 접근성

[WebAIM Million](https://webaim.org/projects/million/) 2026 년판에 따르면 상위 홈페이지의 **95.9%** 에서 자동 검출 가능한 WCAG 2 실패가 발견됐다(2025년 94.8%). 페이지당 평균 오류는 **56.1개**로 전년 51개보다 10.1% 늘었다. 자동 검출 기준으로도 WCAG 2 A/AA 를 충족하는 홈페이지는 4.1% 미만이다.

| 오류 유형 | 영향받은 홈페이지 비율 |
| --- | --- |
| 저대비 텍스트 | 83.9% |
| 대체 텍스트 누락 | 53.1% |
| 폼 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

위 여섯 유형이 전체 검출 오류의 96%를 차지한다([WebAIM](https://webaim.org/projects/million/)). 즉 새로운 기법이 아니라 **대비, 레이블, 대체 텍스트 같은 기본기**만 지켜도 대부분의 오류가 사라진다. 사용자 영향도 직접적이다. 레이블 없는 폼과 이름 없는 버튼은 스크린리더 사용자가 기능 자체를 쓸 수 없게 만들고, 컴플라이언스 리스크로도 이어진다.

ARIA 사용은 늘었다. 페이지의 82.7%가 ARIA 를 쓰며(전년 79.4%), ARIA 가 있는 페이지의 평균 오류는 59.1개로 없는 페이지(42개)보다 많았다. 다만 보고서는 ARIA 페이지가 더 복잡해서 생기는 차이일 수 있다고 밝힌다([WebAIM](https://webaim.org/projects/million/)).

**방법론의 한계**: WAVE 로 렌더된 DOM 을 검사하는 자동 분석이며, 보고서 스스로 "검출된 오류가 없다는 것이 접근 가능하거나 규격에 부합한다는 뜻은 아니다"라고 명시한다. 샘플은 Tranco 순위 기반 홈페이지로, 로그인 뒤 화면이나 실제 사용 흐름은 포함하지 않는다.

## 성능

Google 의 [INP 문서](https://web.dev/articles/inp)에 따르면 INP 는 방문 중 모든 클릭·탭·키보드 상호작용의 지연을 측정하며, 가장 느린 상호작용(50회마다 하나의 이상치 제외)이 보고된다. 기준은 모바일·데스크톱 각각 필드 데이터 75번째 백분위에서 **200ms 이하 양호, 500ms 초과 불량**이다. INP 는 첫 입력만 보던 FID 의 후속 지표로, 처리 시간과 다음 프레임 렌더까지 포함한다.

이번 조사에서는 신뢰할 만한 1차 자료의 2026년 통과율 수치를 확인하지 못했다. 2차 블로그의 수치는 서로 달라 인용하지 않는다.

## 기술 표준

W3C 는 [2026년 3월 3일 WCAG 3 작업 초안을 갱신](https://www.w3.org/WAI/news/2026-03-03/wcag3)하고 검토를 요청했다. 이 공지는 변경 내용 자체는 설명하지 않고 WCAG 3 소개 페이지의 진행 상태 항목을 안내한다. 확정 일정도 이 출처에서는 확인되지 않으므로, 현재 실무 기준은 WCAG 2.2 로 보는 것이 안전하다.

## 오늘 바로 적용할 것

- 사이트의 텍스트 색 대비를 점검한다(일반 텍스트 4.5:1). 가장 흔한 오류(83.9%)다.
- 모든 폼 입력에 `label` 을 연결하고, 아이콘 버튼과 링크에 접근 가능한 이름을 단다.
- `<html lang>` 이 있는지 확인한다.
- 자동 검사 통과를 접근성 완료로 간주하지 말고, 키보드와 스크린리더로 핵심 흐름을 직접 확인한다.
- 필드 데이터(CrUX 등)로 INP 75번째 백분위가 200ms 이하인지 확인한다.
