## 접근성

[WebAIM Million](https://webaim.org/projects/million/) 2026년판(2026년 2월 수집, 상위 100만 홈페이지)에 따르면 **95.9%의 페이지에서 WCAG 2 위반이 자동 검출**됐다(전년 94.8%). 페이지당 평균 오류는 56.1건으로 전년(약 51건)보다 약 10% 늘었다. [출처](https://webaim.org/projects/million/)

| 위반 유형 | 비율 |
| --- | --- |
| 저대비 텍스트 | 83.9% |
| 대체 텍스트 누락 | 53.1% |
| 폼 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

이 여섯 범주가 검출 오류의 96%를 차지한다. 즉 소수의 반복되는 기본기 문제를 고치면 효과가 크다. 실제 영향은 스크린리더 사용자가 이름 없는 링크·버튼을 만나 기능을 쓸 수 없게 되는 것이며, 컴플라이언스 리스크로도 이어진다.

ARIA 사용도 늘어 페이지당 평균 133개 이상의 속성이 검출됐고(전년 대비 약 27% 증가), **ARIA를 쓰는 페이지의 평균 오류는 59.1건으로 쓰지 않는 페이지(42건)보다 많았다.** [출처](https://webaim.org/projects/million/) 다만 이는 상관관계이며 ARIA가 오류를 일으킨다는 인과 증거는 아니다. 또한 자동 검사는 전체 장벽의 일부만 잡으므로 95.9%는 하한선에 가깝고, 같은 보고서도 오류 밀도만으로 접근성을 판단하는 것은 신뢰하기 어렵다고 밝힌다.

## 성능

[CrUX 릴리스 노트](https://developer.chrome.com/docs/crux/release-notes/?hl=en)의 2026년 9월 데이터(2026-10-13 게시)에서 "좋음" 판정 origin 비율은 다음과 같다.

| 지표 | 좋음 비율 |
| --- | --- |
| LCP | 68.3% |
| CLS | 81.7% |
| INP | 85.4% |
| Core Web Vitals 전체 | 55.9% |

INP는 비교적 안정적이고, **LCP가 통과율을 끌어내리는 병목**이다. 이번 릴리스에는 **소프트 내비게이션을 포함한 실험적 LCP·INP·CLS**도 추가됐다. 이를 포함하면 LCP 72.1%, CLS 85.1%, INP 87.4%, 전체 59.5%로 올라간다. SPA는 기존 방식에서 과소평가됐을 수 있다는 뜻이다. [출처](https://developer.chrome.com/docs/crux/release-notes/?hl=en)

한계: CrUX는 Chrome 사용자 중 동의한 방문자의 실측치이며 origin 단위 집계라, 개별 페이지나 다른 브라우저 사용자의 경험을 그대로 대표하지 않는다.

## 기술 표준

W3C WAI는 2026년 3월 3일 [WCAG 3 Working Draft 갱신](https://www.w3.org/WAI/news/2026-03-03/wcag3)을 공개하고 의견을 받고 있다. 최종 표준이 아닌 초안이며, [초안 문서](https://www.w3.org/TR/2026/WD-wcag-3.0-20260303/)는 최종 요구사항이 현재와 달라질 수 있음을 명시한다. 따라서 실무 기준은 당분간 WCAG 2.x(2.2)다. 확정 일정은 이번 조사에서 1차 출처로 확인하지 못했으므로 단정하지 않는다.

## 오늘 바로 적용할 것

- 자사 홈·핵심 플로우에서 WebAIM이 꼽은 6대 오류(대비, alt, 폼 레이블, 빈 링크·버튼, `lang`)를 자동 검사로 먼저 점검한다.
- ARIA는 네이티브 HTML로 해결되지 않을 때만 쓰고, 도입 후에는 스크린리더로 수동 확인한다.
- CrUX에서 LCP를 우선 점검하고, SPA라면 소프트 내비게이션 포함 지표와 기존 지표를 나란히 비교해 본다.
- WCAG 3 초안은 모니터링만 하고, 현행 규제 대응은 WCAG 2.2 기준을 유지한다.
