## 접근성

[WebAIM Million](https://webaim.org/projects/million/) 2026년판(2026년 2월, 상위 100만 홈페이지 자동 분석)에서 홈페이지의 95.9%가 WCAG 2 위반을 하나 이상 보였다. 2025년 94.8%에서 올랐고, 페이지당 평균 오류도 51개에서 56.1개로 10.1% 늘었다. 지난 7년간 이어진 개선 흐름이 처음 꺾인 셈이다.

| 오류 유형 | 영향받은 홈페이지 |
| --- | --- |
| 낮은 텍스트 대비 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

출처: [WebAIM Million](https://webaim.org/projects/million/). 이 여섯 유형이 검출 오류의 96%를 차지한다.

ARIA 사용률은 82.7%(전년 79.4%)로 늘었지만, ARIA 를 쓴 페이지의 평균 오류는 59.1개로 쓰지 않은 페이지(42개)보다 많았다([WebAIM](https://webaim.org/projects/million/)). 다만 상관관계일 뿐이며, 복잡한 페이지일수록 ARIA 도 오류도 많아지는 효과가 섞여 있을 수 있다.

**한계**: 이 수치는 자동 검사로 잡히는 오류만 센다. 자동 도구는 WCAG 위반의 일부만 찾으므로, 오류가 0이어도 접근성이 충분하다는 뜻은 아니다.

## 기술 표준

[WCAG 3.0](https://www.w3.org/TR/wcag-3.0/) 의 최신 워킹 드래프트는 2026년 9월 10일 자이며, 'Developing' 단계에 도달한 요구사항을 모두 담았다. 문서는 "WCAG 3 does not replace WCAG 2" 라고 밝히고 WCAG 2.2 의 후속이지만 WCAG 2 를 폐기하지 않는다고 설명한다. 초안은 언제든 바뀌거나 대체될 수 있다. 따라서 규정 준수 목적의 기준은 당분간 WCAG 2.x 다.

## 성능

Chrome [CrUX 릴리스 노트](https://developer.chrome.com/docs/crux/release-notes)의 2026년 5월 데이터(6월 9일 공개)에 따르면 원본의 86.6%가 INP 양호(전월 대비 0.6%p 하락), 81.3%가 CLS 양호, 55.9%가 Core Web Vitals 3개 지표를 모두 통과했다(0.8%p 하락). 최신 11월 시점의 수치는 확인하지 못했다.

브라우저 지원 측면에서는 [web.dev](https://web.dev/blog/lcp-and-inp-are-now-baseline-newly-available)가 LCP 와 INP 가 Baseline Newly available 이 되었다고 발표했다. 반면 CLS 는 Chromium 계열 밖에서는 지원되지 않는다. CrUX 는 Chrome 사용자 필드 데이터라 다른 브라우저 이용자의 경험은 반영하지 못한다는 한계가 있다.

## 오늘 바로 적용할 것

- 사이트를 점검할 때 위 여섯 가지 흔한 오류(대비, 대체 텍스트, 폼 레이블, 빈 링크·버튼, `lang`)부터 자동 검사로 확인한다.
- 자동 검사 통과 후에도 스크린리더·키보드 수동 점검을 병행한다.
- 성능은 실험실 점수가 아니라 CrUX 필드 데이터(75번째 백분위)의 INP·LCP·CLS 로 판단한다.
- WCAG 3.0 은 모니터링만 하고, 준수 기준은 WCAG 2.2 로 유지한다.
