## 접근성 — WCAG 3.0, 등급제를 버리고 3단 준수 모델을 제안했지만 핵심 수치는 아직 빈칸

[W3C가 2026년 9월 10일 공개한 WCAG 3.0 Working Draft](https://www.w3.org/WAI/news/2026-09-10/wcag3/)는 지금의 A·AA·AAA 등급 체계를 대체할 새 준수 모델의 세부안을 담았습니다. [문서 본문](https://www.w3.org/TR/wcag-3.0/)에 따르면 새 모델은 기본 적합성에 필수인 **핵심 요구사항(Core requirements)**, 추가 지원 기능인 **보충 요구사항(Supplemental requirements)**, 사용성 테스트·조직 정책 같은 입증 가능한 활동인 **주장(Assertions)** 세 축으로 구성됩니다. WCAG 2.x의 성공 기준보다 훨씬 세분화된 항목을 기술별 구현 방법과 함께 제시한다는 점도 차이입니다.

다만 완성도는 아직 멀었습니다. 텍스트 모양(text appearance) 기준값은 "values to be determined"로 비어 있고, 특히 비라틴 문자·다국어 지원에 대해 문서는 "전문가의 도움이 필요하다"고 직접 밝히고 있습니다. 색맹(CVD) 대응 여부를 포함한 **대비 알고리즘 자체도 미정**이며, 음성 없는 영상 콘텐츠의 오디오 설명 처리 방식도 정해지지 않았습니다. W3C는 이 초안이 여전히 "Developing" 단계이며 WCAG 2.2를 대체하지 않는다는 점을 명시하고, 그때까지는 **WCAG 2.2 Level A·AA 준수를 유지하라**고 권고합니다. 의견 제출은 공개 메일링리스트(wai@w3.org)나 GitHub을 통해 가능합니다. 지금 당장 준수 전략을 바꿀 근거는 아니지만, 향후 보고 체계가 등급이 아니라 '핵심+보충+주장' 조합으로 바뀐다는 방향성만은 미리 파악해 둘 만합니다.

## 성능 — Core Web Vitals, INP만 나 홀로 넉 달째 하락

[CSS Wizardry의 Web-Perf Wednesday 시리즈](https://csswizardry.com/2026/09/web-perf-wednesday-008-good-inp-rates-keep-falling/)가 최신 Chrome UX Report(CrUX) 데이터를 정리한 결과, 전 세계 오리진 기준 INP(Interaction to Next Paint) 양호 비율이 8월 85.3%로 떨어졌습니다 — 7월 85.7%에 이어 3월 87.2%부터 넉 달 연속 하강입니다. 같은 기간 다른 지표는 거의 흔들리지 않았습니다.

| 지표 (CrUX, 전 세계 오리진) | 2026년 7월 | 2026년 8월 |
| --- | --- | --- |
| INP 양호 비율 | 85.7% | 85.3% |
| LCP 양호 비율 | 68.3% | 68.1% |
| CLS 양호 비율 | 81.5%대 유지 | 81.5% |
| 3종 모두 통과 | 55.7% | 55.6% |

> "계속된 회귀가 우려스럽지만, 아직 명확한 이유가 없다" — Chrome 팀

Chrome 팀조차 원인을 특정하지 못했다는 점이 이 데이터의 핵심입니다. 필자는 전역 하락이 사이트·브라우저·기기·트래픽 구성·측정 적격성 변화 중 무엇 때문인지 CrUX 집계만으로는 알 수 없다고 지적하며, **CrUX 전역 추세를 원인으로 지목하지 말고 자체 RUM(실사용자 모니터링) 데이터로 경로·상호작용·기기·브라우저 버전·애플리케이션 릴리스를 직접 비교**하라고 권고합니다. `web-vitals` 라이브러리의 어트리뷰션(attribution) 빌드와 Long Animation Frames API를 함께 쓰면 어떤 상호작용이 느려졌는지 구성 요소 단위로 좁힐 수 있습니다.

## 디자인 트렌드 — Baymard: "반품에 프린터가 필요 없어야" 기본값이 됐다

[Baymard Institute의 신규 연구](https://baymard.com/blog/accounts-and-self-service-ux-research-2026)는 계정·셀프서비스 UX를 주제로 4,000시간 이상의 정성 조사와 1,400개 이상의 사용성 문제 관찰, 미국 성인 1,000명 이상 대상 정량 조사를 거쳐 **가이드라인 57개**를 새로 만들거나 갱신했습니다(모바일 테스트 관찰 최초 포함). 로그인·보안 영역에서는 참여자의 81%가 자주 방문하는 사이트에 신용카드 정보를 저장해 두고 있었고, 60%는 2단계 인증(2FA) 기능을 긍정적으로 평가했습니다 — 기존 비밀번호 로그인의 불편함을 패스키·일회용 비밀번호(OTP) 같은 현대적 인증 수단이 상당 부분 대체하고 있다는 뜻입니다.

셀프서비스 기능 중에서는 **주문 추적이 가장 중요하게 꼽혔고**, 예상 배송일·배송업체명·배송 단계 같은 정보가 빠지면 불만으로 직결됐습니다. 반품 경험의 기준 자체도 바뀌었습니다 — 2018년 조사에서는 라벨을 인쇄해 직접 포장하고 배송업체를 방문하는 절차가 당연했지만, 지금 사용자는 **프린터가 필요 없는 반품, 픽업 서비스, 즉각적인 환불**을 기본으로 기대합니다. 반품 자격을 명확히 안내하고 최소 1개 이상의 무료 반품 옵션을 포함한 복수의 반품 방식을 제공하는 것이 새 기준선이라는 뜻이므로, 셀프서비스 UX를 다시 점검할 때는 '2018년 기준'이 아니라 이 최신 기대치에 맞춰야 합니다.

## 기술 표준 — Chrome, 4주에서 2주 릴리스 주기로 — 연 테스트 횟수가 두 배로

[Chrome for Developers 공식 발표](https://developer.chrome.com/blog/chrome-two-week-start)에 따르면 Chrome은 2026년 9월 8일 버전 153부터 데스크톱·Android·iOS 전 플랫폼에서 **4주 주기를 2주 주기로 전환**했습니다. Google은 전환 이유로 기능·성능 개선·버그 수정을 더 빠르게 전달하는 것 외에, 패치되지 않은 취약점이 노출되는 "N-day" 간격을 최소화해 보안을 강화하고, Microsoft·Mozilla·Brave 등 경쟁 브라우저들이 비슷한 방향으로 움직이는 흐름에서 업계 표준을 주도하려는 목적을 꼽았습니다.

개발자 입장에서는 **연간 메이저 릴리스가 13회에서 26회로 늘어난다**는 뜻이라, 자동화된 CI/CD 회귀 테스트 없이 수동 QA에 의존해 온 팀은 대응 부담이 커집니다. 기업 환경처럼 변경 빈도를 낮추고 싶다면 8주 주기로 메이저 기능이 들어오는 Extended Stable 채널(예: Chrome 156·160)을 대안으로 검토할 수 있습니다 — 보안 패치는 이 채널에서도 매주 백포트됩니다. Google은 릴리스당 변경 범위가 작아지는 만큼 회귀 격리(regression isolation)가 오히려 빨라진다는 점을 강점으로 내세우지만, 실제 체감은 팀의 테스트 자동화 수준에 달려 있습니다.

## 오늘 바로 적용할 것

1. **WCAG 3.0 초안을 근거로 지금 준수 전략을 바꾸지 마세요.** 대비 알고리즘과 텍스트 모양 수치가 아직 미정인 "Developing" 단계 문서이며, W3C 스스로 WCAG 2.2 Level AA 유지를 권고하고 있습니다.
2. **INP가 나빠졌다면 CrUX 전역 추세 탓으로 돌리지 말고 자체 RUM부터 뜯어보세요.** Chrome 팀도 원인을 특정하지 못한 만큼, `web-vitals` 어트리뷰션 빌드로 어떤 경로·상호작용이 느려졌는지 직접 좁혀야 합니다.
3. **셀프서비스 UX에 '프린터 없는 반품' 같은 2026년 기준 기대치를 반영하세요.** Baymard 데이터가 보여주듯 사용자는 이미 즉각 환불·픽업 반품을 당연하게 여기므로, 오래된 반품 플로우는 그 자체로 이탈 요인이 됩니다.
4. **Chrome 2주 릴리스 주기에 맞춰 회귀 테스트를 자동화하세요.** 연간 테스트 대상 릴리스가 두 배로 늘어난 만큼, 수동 QA 체제라면 지금이 최소한의 CI 스모크 테스트라도 갖출 시점입니다.
