## 접근성

[WebAIM Million](https://webaim.org/projects/million/) 2026년판(2026년 2월 수집)에 따르면 상위 100만 홈페이지의 **95.9%** 에서 자동 검사로 잡히는 WCAG 실패가 있었습니다(2025년 94.8%). 페이지당 평균 오류는 **56.1개**로 전년 51개에서 10.1% 늘었습니다.

| 오류 유형 | 영향 받은 홈페이지 비율 |
| --- | --- |
| 낮은 텍스트 대비 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

출처: [The WebAIM Million](https://webaim.org/projects/million/)

### ARIA 의 역설

같은 보고서에서 홈페이지의 82.7%가 ARIA 를 사용했고(전년 79.4%), ARIA 속성 수는 1년 새 27% 늘었습니다. 그런데 ARIA 를 쓰는 페이지는 평균 59.1개 오류, 쓰지 않는 페이지는 42개였습니다. 보고서는 ARIA 사용 증가가 검출 오류 증가와 연관된다고 밝혔고, `role="menu"` 가 있는 페이지의 22%는 필수 마크업·상호작용이 빠져 오히려 장벽을 만들었습니다. ([WebAIM Million](https://webaim.org/projects/million/))

한계: 이 수치는 자동 검사로 검출 가능한 오류만 센 것이라 실제 장벽의 하한선에 가깝고, 상관관계가 ARIA 의 인과를 뜻하지는 않습니다(복잡한 페이지일수록 ARIA 도 오류도 많을 수 있음).

## 성능

Core Web Vitals 는 LCP·INP·CLS 세 지표 체제입니다. 일반적으로 알려진 "좋음" 기준은 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하(75퍼센타일)입니다. 다만 이번 조사에서는 web.dev·CrUX 1차 문서를 직접 확인하지 못했고 2차 자료에 의존했으므로, 기준 수치는 적용 전에 web.dev 에서 재확인하세요. 또 "2026년에 지표가 바뀌었다"는 일부 글의 주장도 확인되지 않았습니다.

## 기술 표준

W3C WAI 는 [2026년 3월 3일 WCAG 3.0 작업 초안 갱신](https://www.w3.org/WAI/news/2026-03-03/wcag3)을 공지하고 검토 의견(wai@w3.org 또는 GitHub)을 요청했습니다. [WCAG 3.0 문서](https://www.w3.org/TR/wcag30/)는 아직 미완성 초안이며 최종 요구사항은 달라질 수 있습니다. 따라서 법규·조달 대응의 기준은 당분간 WCAG 2.2 입니다. 최종 권고 시점에 대한 추정은 2차 자료뿐이라 여기서는 다루지 않습니다.

## 오늘 바로 적용할 것

- 텍스트·배경 대비를 4.5:1 이상으로 점검하세요(가장 흔한 실패, 83.9%).
- 모든 `<img>` 에 의미 있는 `alt`(장식용은 빈 `alt=""`), 모든 입력에 `<label>` 을 연결하세요.
- 아이콘 전용 링크·버튼에 접근 가능한 이름을 부여하세요(빈 링크 46.3%, 빈 버튼 30.6%).
- ARIA 보다 네이티브 HTML(`<button>`, `<details>`)을 먼저 쓰고, `role="menu"` 는 키보드 상호작용을 갖출 때만 쓰세요.
- `<html lang>` 를 지정하세요.
