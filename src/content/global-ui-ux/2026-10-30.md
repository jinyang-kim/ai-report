## 접근성: 오류는 줄지 않고 늘었다

[WebAIM Million](https://webaim.org/projects/million/)의 2026년 보고서(2026년 2월 수집, 상위 100만 개 홈페이지 대상)에 따르면 홈페이지의 **95.9%**에서 자동 검사로 잡히는 WCAG 2 위반이 발견됐다. 2025년은 94.8%였다. 페이지당 평균 오류는 **56.1개**로, 전년의 약 51개보다 약 10% 늘었다.

| 오류 유형 | 해당 홈페이지 비율 |
| --- | --- |
| 낮은 텍스트 대비 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 라벨 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

출처: [WebAIM Million](https://webaim.org/projects/million/)

실제 영향은 분명하다. 대비가 낮은 텍스트는 저시력 사용자뿐 아니라 야외 화면에서도 읽기 어렵다. 라벨 없는 입력창과 이름 없는 버튼은 스크린리더 사용자가 폼을 완료하지 못하게 만든다.

## ARIA: 많이 쓴다고 접근성이 좋아지지 않는다

[WebAIM Million](https://webaim.org/projects/million/)에서 ARIA를 쓴 홈페이지는 82.7%(랜드마크 역할 제외)로, 2025년 79.4%에서 늘었다. 페이지당 ARIA 속성은 평균 133개를 넘어 1년 새 27% 증가했다. 그런데 ARIA가 있는 페이지는 평균 오류가 **59.1개**로, 없는 페이지(42개)보다 많았다. `role="menu"`가 쓰인 페이지는 5.7%였고 그 메뉴의 22%가 접근성 장벽을 만들었다.

> 상관관계일 뿐 인과는 아니다. 복잡한 페이지일수록 ARIA도 오류도 늘어난다는 해석이 가능하다.

다만 네이티브 HTML로 충분한 자리에 ARIA를 덧씌우지 않는다는 원칙은 이 수치와 방향이 일치한다.

## 성능: Core Web Vitals 통과율

2차 인용 자료([shno.co 정리](https://www.shno.co/marketing-statistics/core-web-vitals-statistics))에 따르면 HTTP Archive 기준 모바일 CWV 통과율은 2023년 36%, 2024년 44%, 2025년 48%로 올랐고, 데스크톱은 48%, 55%, 56%였다. 지표는 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하(75백분위)다.

한계: 위 수치는 원자료(Web Almanac)가 아니라 2차 정리 글에서 가져왔다. 원문 대조 전에는 참고치로만 보는 편이 안전하다. 2026년 최신 Web Almanac 수치는 이번에 확인하지 못했다.

## 기술 표준: WCAG 3.0은 아직 초안

W3C는 [2026년 3월 3일 WCAG 3.0 작업 초안 갱신](https://www.w3.org/WAI/news/2026-03-03/wcag3)을 공지하고 GitHub와 메일링 리스트로 의견을 받는다. [작업 초안 본문](https://www.w3.org/TR/2026/WD-wcag-3.0-20260303/)은 최종 요구사항이 초안과 다를 수 있는 미완성 문서다. 현재 규정 준수 기준으로는 WCAG 2.2를 쓰고, WCAG 3.0은 모니터링 대상으로 두면 된다. 완료 시점은 W3C 기준 아직 몇 년 뒤로 알려져 있다.

## 오늘 바로 적용할 것

- 사이트 텍스트·UI 색의 대비 비율을 점검한다(4.5:1, 큰 글자 3:1). 가장 흔한 오류다.
- 아이콘 전용 링크·버튼에 접근 가능한 이름(텍스트 또는 `aria-label`)이 있는지 확인한다.
- 모든 입력창에 `<label>` 을 연결하고, `<html lang>` 이 설정돼 있는지 본다.
- `role="menu"` 등 복합 ARIA 위젯은 네이티브 요소(`<details>`, `<button>`)로 대체할 수 있는지 먼저 검토한다.
- 자동 검사는 일부 위반만 잡는다. 키보드 탐색과 스크린리더 점검을 수동으로 병행한다.
