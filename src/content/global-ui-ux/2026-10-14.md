## 접근성

[WebAIM Million 2026](https://webaim.org/projects/million/)에 따르면 방문량 상위 100만 홈페이지의 **95.9%**에서 WCAG 2 위반이 자동 탐지됐다(2025년 94.8%). 페이지당 평균 오류는 **56.1개**로 전년(51개)보다 약 10% 늘어, 몇 해간 이어진 완만한 개선 추세가 뒤집혔다. 홈페이지 평균 요소 수는 1,437개로 늘었고, 요소 약 26개 중 1개꼴로 오류가 있었다.

| 오류 유형 | 영향 받은 홈페이지 |
| --- | --- |
| 저대비 텍스트 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

출처: [The WebAIM Million](https://webaim.org/projects/million/). 이 6개 유형이 전체 탐지 오류의 96%를 차지한다.

- **ARIA 역설**: ARIA 를 쓰는 페이지(82.7%)는 평균 59.1개 오류로, 쓰지 않는 페이지(42개)보다 오류가 많았다([WebAIM](https://webaim.org/projects/million/)). 인과가 아니라 상관이다 — 복잡한 페이지일수록 ARIA 를 많이 쓰기 때문일 수 있다.
- **구조 문제**: 41.8%가 제목 단계를 건너뛰고, 18.1%가 `<h1>` 을 둘 이상 쓰며, 스킵 링크가 있는 페이지는 17.1%에 그쳤다([WebAIM](https://webaim.org/projects/million/)).
- **업종 편차**: 정부 사이트가 평균 42.4개로 가장 적었고 스포츠가 71.4개로 가장 많았다([WebAIM](https://webaim.org/projects/million/)).
- **한계**: WebAIM 스스로 "탐지된 오류가 없다고 접근성이 확보된 것은 아니다"라고 밝힌다. 자동 검사는 일부 문제만 잡으므로 실제 비적합 비율은 더 높을 가능성이 크다([Priority Pixels 요약](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/)). 또 홈페이지만 대상이라 서비스 내부 화면은 반영되지 않는다.

## 성능

2차 자료 기준으로 CrUX 상 전 세계 origin 의 약 55.7%가 Core Web Vitals 세 지표를 모두 통과하고, 2026년 1월 지표별 양호 비율은 LCP 68.3%, INP 87.1%, CLS 80.9% 로 보고된다([shno.co 통계 정리](https://www.shno.co/marketing-statistics/core-web-vitals-statistics)). 즉 병목은 INP 가 아니라 LCP 다. 다만 이 수치는 블로그 집계라 Google 의 CrUX 원자료로 직접 확인하지 못했으므로 방향성 참고용으로만 보는 것이 안전하다. 판정은 실사용자 75번째 백분위 기준이다.

## 디자인 트렌드

이번 조사에서 신뢰할 만한 1차 데이터를 확보한 항목이 없어 다루지 않는다. 대신 WebAIM 결과가 시사하는 바는 분명하다. 페이지 복잡도(요소 수)가 늘수록 오류도 늘어나므로, 새 패턴을 추가할 때마다 대비·레이블·대체 텍스트 기본기를 컴포넌트 단계에서 보장하는 접근이 효율적이다.

## 기술 표준

W3C WAI 는 2026년 3월 3일 자로 [WCAG 3 워킹 드래프트를 검토용으로 공개](https://www.w3.org/WAI/news/2026-03-03/wcag3)했다. 공지 페이지는 변경 내역을 직접 설명하지 않고 WCAG 3 소개 문서를 가리키며, 의견은 wai@w3.org 나 GitHub 로 받는다. 어디까지나 진행 중인 초안이므로 준수 기준은 현행 WCAG 2.2 를 유지하는 것이 맞다. 확정 시점에 대한 전망은 자료마다 달라 여기서는 단정하지 않는다.

## 오늘 바로 적용할 것

1. **대비 점검**: 본문·메타 텍스트의 색 토큰을 라이트·다크 모드 모두 4.5:1 이상으로 계산해 본다(가장 흔한 오류, 83.9%).
2. **빈 링크·버튼 찾기**: 아이콘 전용 컨트롤에 `aria-label` 또는 보이는 텍스트가 있는지 확인한다.
3. **폼 레이블**: 모든 입력에 `<label for>` 를 연결하고, placeholder 로 대체하지 않는다.
4. **ARIA 줄이기**: 네이티브 요소(`<button>`, `<details>`)로 대체 가능한 ARIA 를 걷어낸다.
5. **제목 단계·스킵 링크**: `h1 → h2 → h3` 순서와 페이지당 `h1` 하나, 작동하는 스킵 링크를 점검한다.
6. **자동 검사 + 수동 검사 병행**: pa11y·Lighthouse 통과 뒤에도 키보드 탐색과 스크린리더로 핵심 흐름을 직접 확인한다.
