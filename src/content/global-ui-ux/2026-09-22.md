## 접근성 — WebAIM Million, 6년 만에 개선세가 꺾였다

[WebAIM Million 2026](https://webaim.org/projects/million/)은 상위 100만 개 홈페이지를 자동 검사한 연례 리포트입니다. 이번 결과는 홈페이지당 평균 감지 오류가 **56.1개로 전년(51개) 대비 10.1% 늘었고**, WCAG 2 위반이 하나 이상 발견된 홈페이지 비율도 **95.9%로 전년 94.8%에서 상승**했다고 밝혔습니다. 그동안 매년 조금씩 줄어들던 오류·실패율이 처음으로 반등한 것인데, 리포트는 홈페이지 구조와 ARIA 코드의 복잡도 증가, 서드파티 프레임워크 의존, AI 보조 코딩 확산을 유력한 배경으로 지목합니다.

오류 유형별로는 **저대비 텍스트가 83.9%**로 압도적 1위이고, 이미지 대체 텍스트 누락(53.1%), 폼 입력 레이블 누락(51%), 빈 링크(46.3%), 빈 버튼(30.6%), 문서 언어 속성 누락(13.5%) 순입니다. 이 여섯 가지가 전체 오류의 96%를 차지합니다. 대체 텍스트·언어 속성 누락은 오히려 줄었지만, 저대비 텍스트·레이블 누락·빈 링크·빈 버튼은 늘어 개선이 항목별로 엇갈렸습니다. 자동 검사가 잡아내는 이 여섯 가지만 체크리스트로 관리해도 감지 가능한 오류 대부분을 걷어낼 수 있다는 뜻입니다.

## 성능 — Web Almanac 기준 모바일 통과율 48%, CrUX 와는 다른 그림

[HTTP Archive 2025 Web Almanac Performance 챕터](https://almanac.httparchive.org/en/2025/performance)(2026년 1월 15일 공표, 2025년 7월 크롤링 데이터)는 페이지 단위로 가중한 Core Web Vitals 통과율을 **모바일 48%·데스크톱 56%**로 집계했습니다. 전년 대비 모바일은 4%p, 데스크톱은 1%p 올랐습니다. 지난주 브리핑에서 다룬 CrUX 8월 데이터(원점 기준 통과율 55.6%)와 수치가 다른데, CrUX 는 origin(도메인) 단위 집계인 반면 Web Almanac 은 크롤링한 개별 페이지를 가중 평균한다는 방법론 차이 때문입니다 — 같은 현상을 다른 단위로 보는 두 지표로 이해하는 편이 정확합니다.

지표별로는 **모바일 INP 양호율이 74%→77%로 개선**되며 모바일·데스크톱 격차가 23%p 에서 20%p 로 좁혀졌고, LCP 는 모바일 62%·데스크톱 74%(격차 12%p), CLS 는 오히려 모바일(81%)이 데스크톱(72%)보다 9%p 앞섭니다. 상위 1,000개 인기 사이트의 INP 개선(53%→63%)이 가장 두드러졌지만, 인기도 중간 구간 사이트들의 성능이 가장 낮은 **U 자형 분포**가 여전하다고 리포트는 지적합니다. 이미지 크기를 지정하지 않은 모바일 페이지가 62%에 달한다는 점도 CLS 관리에서 가장 손쉬운 개선 여지로 남아 있습니다.

## 디자인 트렌드 — AI 가 만든 화면, UX 평가 속도가 못 따라가는 "UX 부채"

[Nielsen Norman Group 의 8월 28일 자 글](https://www.nngroup.com/articles/ai-ux-debt/)(Anna Kaley·Raluca Budiu)은 AI 가 하루 만에 워크플로 5개를 만들어낼 수 있지만 **어느 것이 실제로 사용자를 돕는지 판단하려면 여전히 사람의 이해와 평가가 필요하다**고 짚습니다. 이 격차가 방치되면 기술적으로는 작동하지만 불필요하게 복잡하거나, AI 생성 티가 나서 신뢰를 깎거나, 사용자가 원하지 않는 기능이 쌓이는 **"UX 부채"**가 됩니다. UX 팀이 맞닥뜨리는 작업의 성격도 바뀌었습니다 — 빈 화면에서 설계를 시작하는 대신, 이미 존재하는 AI 생성 프로토타입·기능 중 무엇을 남기고 무엇을 고칠지 판단하는 일이 늘었다는 것입니다.

> "AI 는 워크플로 5개를 하루 만에 만들 수 있지만, 어느 것이 사용자를 돕는지 판단하는 데는 이해와 평가가 필요합니다."

글은 대응 방향으로 세 가지를 제시합니다. 각 기능이 실제 사용자 문제를 푸는지와 "만들 수 있다"를 구분하는 **공유된 판단 기준 세우기**, 위험도에 맞춘 사용자 테스트와 평가 체크리스트로 **평가 속도 높이기**, 디자인 시스템과 UX 가이드라인을 AI 프롬프트 단계에 미리 넣어 **생성 단계부터 UX 개입시키기**입니다. AI 프로토타이핑 도구 도입 속도가 빠른 팀일수록 이 세 가지를 먼저 점검할 필요가 있습니다.

## 기술 표준 — Interop 2027 제안, 내일(9월 23일)이 접수 마감

[web.dev 공지](https://web.dev/blog/interop-2027-proposals)와 [WebKit 블로그](https://webkit.org/blog/18283/submit-your-ideas-for-interop-2027/)에 따르면 Apple·Google·Microsoft·Mozilla·Igalia 가 공동 운영하는 **Interop 2027** 제안 공모가 9월 3일 시작해 **9월 23일 마감**됩니다. 제안은 GitHub 이슈로 제출하며, 이미 있는 제안과 겹치면 새 이슈 대신 댓글로 보강하는 편이 권장됩니다. 좋은 제안의 조건은 두 가지로 압축됩니다 — 표준화가 이미 상당히 진행돼 최소 한 브라우저에 구현된 기능일 것, 웹 플랫폼 테스트(WPT)로 자동 검증할 수 있을 것. "타이포그래피 개선"처럼 넓은 요청보다는 `font-size-adjust` 처럼 기능 하나를 좁게 짚는 제안이 선정되기 쉽다고 두 공지 모두 강조합니다.

2026년까지는 개발자 설문에서 상위로 꼽힌 항목 위주로 대상을 골랐다면, 2027년부터는 webstatus.dev 와 developer signals 저장소의 실사용 데이터를 함께 참고하도록 권장한다는 점이 이번 공모의 변화입니다. 최종 스코프는 2027년 2월 초 공개 예정입니다.
