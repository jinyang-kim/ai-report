## 접근성

[WebAIM Million 2026](https://webaim.org/projects/million/)은 상위 100만 개 홈페이지에서 평균 **56.1개**의 오류를 검출했고, 이는 전년 대비 10.1% 증가한 수치다. **95.9%** 의 페이지에 WCAG 2 실패가 있었다. 홈페이지당 평균 요소 수는 1,437개로 1년 새 14.3% 늘어, 페이지가 복잡해질수록 접근성 유지가 어려워지는 흐름이 보인다.

오류의 96% 는 여섯 범주에 몰려 있다([WebAIM](https://webaim.org/projects/million/)).

| 오류 유형 | 해당 페이지 비율 |
| --- | --- |
| 낮은 텍스트 대비 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 라벨 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

ARIA 사용이 있는 페이지는 평균 59.1개 오류로, 없는 페이지(42개)보다 많았다. 상관관계일 뿐 인과는 아니지만, ARIA 를 덧붙이기보다 네이티브 HTML 을 우선하라는 오랜 원칙을 뒷받침한다. 같은 보고서에서 Astro 로 만든 사이트는 평균보다 오류가 84% 적었다.

**한계**: 자동 검사는 전체 적합성 실패의 일부만 잡기 때문에 [WebAIM](https://webaim.org/projects/million/) 도 실제 상황이 통계보다 나쁠 가능성이 높다고 밝힌다. 또 대상이 홈페이지에 한정되어 로그인 이후 화면은 반영하지 못한다.

## 성능

[2026년 5월 CrUX 집계](https://www.digitalapplied.com/blog/core-web-vitals-benchmarks-2026-pass-rate-reference)에서 세 지표를 모두 통과한 origin 은 **55.9%** 로 전월보다 0.8%p 낮았다. 기기별로는 데스크톱 56%, 모바일 48% 로 8%p 차이가 난다. 모바일에서 좋음 비율은 LCP 62%, INP 77%, CLS 81% 로 **LCP 가 주된 병목**이다.

- 임계값(75백분위): LCP ≤ 2,500ms, INP ≤ 200ms, CLS ≤ 0.1 ([출처](https://www.digitalapplied.com/blog/core-web-vitals-benchmarks-2026-pass-rate-reference))
- 같은 5월 CrUX 릴리스에서 개별 통과율은 LCP 68.6%, CLS 81.3%, INP 86.6% 로 보고됐다 ([MonsterMegs](https://monstermegs.com/blog/core-web-vitals-update/)).
- 플랫폼별 격차도 크다. 2025년 11월 데이터에서 Duda 84.87% 대 WordPress 46.28% 였고, WordPress 는 INP(85.89%)가 아니라 로딩이 약점이었다 ([Digital Applied](https://www.digitalapplied.com/blog/core-web-vitals-benchmarks-2026-pass-rate-reference)).

**한계**: 위 수치는 제3자 블로그가 CrUX 를 재가공한 것이라 집계 기준(origin 단위, 모바일·데스크톱 합산 여부)이 글마다 다를 수 있다. 정확한 값은 CrUX 원본 대시보드로 확인해야 한다. 트래픽이 적은 사이트는 CrUX 에 아예 잡히지 않는다는 점도 감안해야 한다.

## 기술 표준

[Centre for Accessibility Australia](https://www.accessibility.org.au/new-2026-update-for-the-wcag-3-0-working-draft/) 는 W3C 가 2026년 9월 10일 WCAG 3.0 작업 초안을 새로 공개했다고 전한다. 제안된 적합성 모델은 기존 A/AA/AAA 대신 단일 적합 수준과 그 위아래 보고 단계를 두는 구조다. 아직 집행 가능한 표준이 아니며, 현재 기준은 **WCAG 2.2 A·AA** 다. 일정(후보 권고안 2027년 4분기 전후, 최종 권고 2028년 이후)은 2차 출처의 전망이므로 W3C 공식 일정으로 재확인이 필요하다.

## 오늘 바로 적용할 것

1. 라이트·다크 양쪽에서 텍스트 대비 4.5:1 을 자동 검사에 포함한다. 대비 실패가 83.9% 로 가장 흔하다.
2. 아이콘 전용 링크·버튼에 접근 가능한 이름(텍스트 또는 `aria-label`)이 있는지 점검한다. 빈 링크·빈 버튼이 각각 46.3%, 30.6% 다.
3. `<html lang>` 과 폼 `<label>` 연결을 템플릿 수준에서 고정한다.
4. 모바일 실측(CrUX·RUM)으로 LCP 를 먼저 본다. 히어로 이미지 우선 로드와 불필요한 렌더 차단 자원 제거가 출발점이다.
5. WCAG 3.0 대비 재작업은 보류하고, WCAG 2.2 AA 기준 체크리스트를 유지한다.
