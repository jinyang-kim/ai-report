## 접근성

상위 100만 개 홈페이지를 자동 검사하는 [WebAIM Million](https://webaim.org/projects/million/) 2026년판에 따르면, 홈페이지 평균 탐지 오류는 56.1개로 2025년 51개에서 약 10% 늘었고, 95.9%의 페이지에서 WCAG 2 위반이 탐지됐다(전년 94.8%). A/AA 완전 준수 페이지는 4.1% 미만이다.

| 오류 유형 | 해당 홈페이지 비율 |
| --- | --- |
| 낮은 대비 텍스트 | 83.9% |
| 대체 텍스트 누락 | 53.1% |
| 폼 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

출처: [WebAIM Million](https://webaim.org/projects/million/)

ARIA 사용 페이지의 평균 오류는 59.1개로, 미사용 페이지(42개)보다 많다. ARIA 속성 수도 페이지당 평균 133개 이상으로 1년 새 27% 늘었다 ([WebAIM Million](https://webaim.org/projects/million/)). 다만 이는 상관관계일 뿐이다. ARIA 가 오류를 만든다고 단정할 수는 없고, 복잡한 페이지일수록 ARIA 도 오류도 많아지는 교란이 있을 수 있다. 또 자동 검사는 홈페이지의 탐지 가능한 오류만 세므로 실제 사용성 문제 전체를 대변하지 않는다.

## 성능

[Chrome UX Report 릴리스 노트](https://developer.chrome.com/docs/crux/release-notes/)에 따르면 2026년 9월분(10월 13일 공개)에서 INP 양호 origin 비율은 85.4%, Core Web Vitals 전체 통과는 55.9%다. 1월(INP 87.1%, CWV 55.7%)과 비교하면 INP 는 약 1.7%p 낮아졌고, CWV 전체 통과율은 55～56%대에서 제자리다.

| 월(릴리스) | INP 양호 | CWV 양호 |
| --- | --- | --- |
| 2026년 1월 | 87.1% | 55.7% |
| 2026년 3월 | 87.2% | 56.5% |
| 2026년 6월 | 85.9% | 55.3% |
| 2026년 9월 | 85.4% | 55.9% |

출처: [CrUX release notes](https://developer.chrome.com/docs/crux/release-notes/)

9월 릴리스는 SPA 의 소프트 내비게이션을 포함한 실험적 LCP·INP·CLS 지표를 BigQuery 와 CrUX API 에 추가했다. 이를 포함하면 INP 양호 87.4%, CWV 양호 59.5%로 계산된다 ([CrUX release notes](https://developer.chrome.com/docs/crux/release-notes/)). SPA 의 라우트 전환 체감이 기존 지표에서 누락돼 왔음을 시사하지만, 실험적 지표이므로 순위나 SEO 영향으로 해석하면 안 된다.

## 기술 표준

W3C WAI 는 2026년 3월 3일 [WCAG 3 작업 초안 업데이트를 검토용으로 공개](https://www.w3.org/WAI/news/2026-03-03/wcag3)하고 이메일(wai@w3.org)과 GitHub 로 의견을 받고 있다. 이번 조사에서 확인한 범위에서는 초안 단계이며, 법규·조달 기준으로 쓰이는 것은 여전히 WCAG 2.x 다. 확정 시점에 대한 전망은 1차 출처에서 확인하지 못해 싣지 않는다.

## 오늘 바로 적용할 것

- 자사 홈페이지를 자동 검사해 가장 흔한 여섯 가지(대비, alt, 폼 레이블, 빈 링크·버튼, lang)부터 0 으로 만든다.
- ARIA 를 추가하기 전에 네이티브 요소로 해결 가능한지 먼저 검토한다.
- CrUX 에서 자사 origin 의 INP 75퍼센타일을 확인하고, SPA 라면 소프트 내비게이션 포함 실험 지표도 함께 본다.
- 자동 검사 통과를 접근성 완료로 보지 말고 키보드·스크린리더 수동 점검을 병행한다.
