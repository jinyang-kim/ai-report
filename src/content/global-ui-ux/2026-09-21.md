## 접근성 — WCAG 3.0, "A/AA/AAA" 대신 핵심·보충·주장 3단 구조로

[W3C WAI 뉴스](https://www.w3.org/WAI/news/2026-09-10/wcag3/)에 따르면 2026년 9월 10일 **WCAG 3.0 워킹드래프트**의 새 버전이 공개됐습니다. 가장 큰 변화는 적합성 모델 자체입니다 — [Accessible Web 의 정리](https://accessibleweb.com/wcag/wcag-3-working-draft-changes/)를 보면 기존 A/AA/AAA 3등급 대신 **핵심(Core)**(모든 적합성 주장이 반드시 충족해야 하는 항목), **보충(Supplemental)**(기본선을 넘는 항목), **주장(Assertions)**(통과·불통과 대신 조직의 정책·프로세스를 문서화하는 항목)으로 구조가 바뀌었습니다. 내용 면에서는 WCAG 2.x 에서 AAA(선택)로 묶여 있던 항목 다수가 핵심으로 올라갔습니다 — 캡션이 아닌 **오디오·비디오용 스크립트**, 화면에 나오지만 말로는 설명되지 않는 내용을 알려주는 **오디오 설명**, 약어가 처음 등장할 때(HTML 처럼 이미 단어화된 경우는 예외) 붙는 **평문 설명**이 대표적입니다. 성공 기준 수도 WCAG 2.0 61개 → 2.1 78개 → 2.2 86개로 계속 늘어난 흐름이 3.0 에서도 이어질 전망입니다.

다만 아직은 워킹드래프트일 뿐이라 실무에 바로 적용할 의무는 없습니다. 같은 정리 글은 미국 ADA Title II 의 기술 기준이 여전히 **WCAG 2.1 AA**(주·지방정부 마감은 인구 규모별로 2027~2028년)에 머물러 있다는 점을 확인해 줍니다. W3C 는 메일링 리스트(wai@w3.org)와 GitHub 로 이번 드래프트에 대한 피드백, 특히 새 적합성 모델에 대한 의견을 받고 있습니다. 지금 당장 기준을 바꿔야 하는 팀은 없지만, 자막만 달고 스크립트·오디오 설명을 생략해 온 미디어 콘텐츠가 있다면 3.0 이 확정되기 전에 격차를 메워 두는 편이 안전합니다.

## 성능 — INP, 두 달째 원인 불명으로 나빠지는 중

[Chrome UX Report 릴리즈 노트](https://developer.chrome.com/docs/crux/release-notes)가 9월 8일 공개한 2026년 8월 데이터는 좋지 않은 흐름을 보여줍니다. 조사 대상 원점(origin)은 1,829만 4,881개(전월 대비 1.3%↑)로 늘었지만, **Core Web Vitals 3종을 모두 통과한 비율은 55.6%로 전월보다 0.2%p 더 떨어졌습니다.** LCP 양호율은 68.1%(0.2%p↓)로 정체했고, CLS 는 81.5%로 변화가 없었던 반면 **INP 양호율은 85.3%로 0.5%p 하락**했습니다. 7월 데이터(원점 1,805만 9,068개, CWV 통과율 55.7%·INP 85.7%)까지 포함하면 INP 는 두 달 연속 악화인데, Chrome 팀 스스로도 "지속적인 회귀가 우려되지만 명확한 원인을 파악하지 못했다"고 공식 인정했습니다.

> "원인을 특정하지 못한 채로 INP 가 두 달째 나빠지고 있습니다."

인터랙션 지표가 팀 차원의 코드 변경 없이도 악화될 수 있다는 뜻이므로, 자체 RUM(실사용자 모니터링)이 있는 팀이라면 지금 시점을 기준선으로 INP 추이를 별도로 관찰해 둘 만합니다. 원인이 브라우저·OS 레벨의 변화일 가능성도 있는 만큼, 자사 코드 배포와 무관하게 INP 가 흔들린다면 CrUX 전체 추세와 비교해 원인을 오판하지 않는 것이 중요합니다.

## 디자인 트렌드 — 개인화는 옵션이 아니라 기본값이 됐다

[UX Design Institute 의 2026 트렌드 분석](https://www.uxdesigninstitute.com/blog/the-top-ux-design-trends-in-2026/)은 BCG 글로벌 설문을 인용해 **소비자의 약 80%가 이제 기업이 개인화된 경험을 제공하는 것을 당연하게 기대한다**고 짚습니다. 개인화가 "있으면 좋은 기능"에서 "없으면 이탈하는 기본값"으로 넘어갔다는 뜻입니다. 같은 글은 온디바이스 AI(Apple Intelligence, Google Tensor, Qualcomm Snapdragon 등)가 서버 왕복 없이 실시간 개인화·협업형 AI 기능을 뒷받침하는 하드웨어 기반으로 부상하고 있다고 설명합니다.

동시에 디지털 웰빙이 별도 트렌드로 다뤄집니다. 87건의 연구를 검토한 2023년 문헌(Wiley Online Library)은 인터페이스 디자인이 사용자의 디지털 웰빙에 직접 영향을 준다는 결론을 냈고, 최근 연구(MDPI)는 AI 기반 플랫폼의 추천 루프가 특히 젊은 사용자층의 강박적 사용을 심화시킬 수 있다고 지적합니다. 개인화를 밀어붙일수록 몰입도뿐 아니라 웰빙에 미치는 영향도 함께 측정해야 한다는 것이 두 흐름을 관통하는 메시지입니다.

## 기술 표준 — progress(), 계산 없이 "지금 몇 %인지"를 바로 구하는 CSS

[MDN 의 progress() 문서](https://developer.mozilla.org/en-US/docs/Web/CSS/progress)에 따르면 CSS **progress() 함수**가 2026년 9월 1일 자로 Chrome 138·Firefox 155·Safari 26·Edge 138 네 브라우저 엔진 모두에서 **Baseline Newly Available**을 달성했습니다. `progress(값, 시작값, 종료값)` 형태로 써서 `(값 - 시작값) / (종료값 - 시작값)` 을 계산해 단위 없는 숫자를 돌려주며, 기본적으로 0~1 범위로 클램프되고 필요하면 범위를 벗어나는 계산도 가능한 no-clamp 옵션이 있습니다. 예를 들어 `opacity: progress(5, 0, 10)` 은 0.5 를 반환합니다.

지금까지는 스크롤 진행률이나 슬라이더 값에 따라 스타일을 바꾸려면 JavaScript 로 퍼센트를 계산해 CSS 변수에 주입해야 했는데, progress() 는 이 계산을 CSS 안에서 끝냅니다. sibling-index()·sibling-count() 같은 최근 Baseline 편입 함수와 조합하면 "리스트에서 몇 번째 항목인가"에 따라 투명도·크기를 자동으로 보간하는 효과도 JavaScript 없이 만들 수 있습니다.

## 오늘 바로 적용할 것

1. **미디어 콘텐츠에 스크립트·오디오 설명이 빠져 있는지 점검하세요.** WCAG 3.0 이 확정되면 자막만으로는 부족해집니다 — 아직 법적 의무는 아니지만 격차를 지금 메워 두면 나중이 편합니다.
2. **INP 를 별도로 관찰선에 올려두세요.** CrUX 전체가 두 달째 원인 불명으로 하락 중이므로, 자사 배포와 무관한 하락까지 자체 코드 문제로 오판하지 않으려면 지금 수치를 기준선으로 남겨야 합니다.
3. **개인화 기능을 늘릴 때는 이탈·과몰입 지표도 함께 재세요.** 개인화 기대치가 80%까지 올라간 만큼 압박은 크지만, 추천 루프가 강박적 사용을 유발할 수 있다는 연구도 함께 나와 있습니다.
4. **스크롤·슬라이더 기반 동적 스타일링이 있다면 progress() 로 교체를 검토하세요.** 4대 브라우저 모두 Baseline 이 확보된 상태라 JavaScript 로 퍼센트를 계산해 CSS 변수에 주입하던 코드를 걷어낼 수 있습니다.
