## 성능

Chrome UX Report(CrUX) 릴리스 노트에 따르면 2026년 9월 데이터(10월 13일 공개)에서 세 가지 Core Web Vitals 를 모두 통과한 origin 은 55.9%, INP 가 양호한 origin 은 85.4%였다 ([CrUX release notes](https://developer.chrome.com/docs/crux/release-notes)). 4월 릴리스(CWV 56.4%, INP 87.1%)와 비교하면 INP 는 1.7%p 내려갔다.

| 릴리스 | CWV 통과 origin | INP 양호 origin |
| --- | --- | --- |
| 2026년 4월 | 56.4% | 87.1% |
| 2026년 6월 | 55.3% | 85.9% |
| 2026년 8월 | 55.6% | 85.3% |
| 2026년 9월 | 55.9% | 85.4% |

- 8월 릴리스 노트는 INP 의 지속적 후퇴를 "우려할 만하다"고 적었고, 뚜렷한 원인은 확인되지 않았다고 밝혔다 ([CrUX release notes](https://developer.chrome.com/docs/crux/release-notes)).
- 9월 릴리스에는 실험적 soft-navigation 변형(LCP·INP·CLS)이 추가됐다. 이를 포함하면 CWV 통과 59.5%, INP 양호 87.4%로 계산된다 ([CrUX release notes](https://developer.chrome.com/docs/crux/release-notes)). SPA 의 화면 전환을 어떻게 측정하느냐에 따라 수치가 달라지므로 비교 시 정의를 맞춰야 한다.
- 한계: origin 단위 통과율은 트래픽이 큰 사이트와 작은 사이트를 동일하게 센다. 사용자 경험 전체의 비율이 아니다.

## 접근성

2026 WebAIM Million(상위 100만 홈페이지 자동 검사)에서 홈페이지의 95.9%가 검출 가능한 WCAG 2 오류를 가졌다. 2025년 94.8%에서 올랐고, 페이지당 평균 오류는 56.1개로 10.1% 늘었다 ([Priority Pixels 요약](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/)).

- 저대비 텍스트 83.9%, 이미지 대체 텍스트 누락 53.1%, 폼 라벨 누락 51%, 빈 링크 46.3%, 빈 버튼 30.6%, 문서 언어 누락 13.5%. 이 여섯 유형이 검출 이슈의 96%를 차지하며 7년째 상위권이다 ([Priority Pixels 요약](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/)).
- ARIA 사용은 1년 새 27% 늘었지만, ARIA 를 쓴 페이지의 평균 오류는 59.1개로 쓰지 않은 페이지(42개)보다 많았다 ([Priority Pixels 요약](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/)). 상관관계일 뿐 인과는 아니며, ARIA 를 쓰는 페이지가 더 복잡하다는 점이 섞여 있을 수 있다.
- 한계: 자동 검사로 잡히는 오류만 센 값이라 실제 비준수는 더 많다. 이 수치는 2차 요약 기사 기준이므로 원문 보고서와 대조해 인용하는 것이 안전하다.

실제 영향 측면에서, 저대비·빈 링크·라벨 누락은 저시력·스크린리더 사용자가 핵심 흐름(검색, 결제, 로그인)을 끝내지 못하게 하는 직접 원인이며 소송·컴플라이언스 리스크로도 이어진다.

## 기술 표준

W3C 는 2026년 3월 3일 WCAG 3 작업 초안(Working Draft)을 갱신하고 검토를 요청했다 ([W3C WAI](https://www.w3.org/WAI/news/2026-03-03/wcag3)). 공지문 자체는 변경 목록을 싣지 않고 WCAG 3 소개 문서의 "Status: In-progress drafts" 를 가리킨다. 아직 초안이라 법적·계약상 기준은 계속 WCAG 2.x 이며, WCAG 3 의 세부 요건(등급 체계 등)은 바뀔 수 있어 이 리포트에서는 확인된 사실만 적는다.

## 오늘 바로 적용할 것

- 대비: 디자인 토큰 단위로 본문·보조 텍스트 대비 4.5:1 을 CI 에서 검사한다(라이트·다크 모두).
- 이름 없는 컨트롤: 아이콘 버튼·아이콘 링크에 접근 가능한 이름이 있는지 전수 점검한다. 가장 흔하고 고치기 쉬운 오류군이다.
- 폼: 모든 입력에 `<label>` 을 연결하고, `<html lang>` 이 있는지 확인한다.
- ARIA: 네이티브 요소로 해결되는 곳에는 ARIA 를 덧붙이지 않는다.
- INP: 필드 데이터(CrUX)에서 INP 를 월 단위로 추적하고, 긴 작업(long task)을 쪼개는 것부터 시작한다.
