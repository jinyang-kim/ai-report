## 접근성: 2026년에는 오히려 나빠졌다

2026년 2월 분석을 담은 [WebAIM Million](https://webaim.org/projects/million/)에 따르면 상위 100만 홈페이지의 95.9%에서 자동 검사로 잡히는 WCAG 2 위반이 발견됐다(2025년 94.8%). 페이지당 평균 오류는 56.1건으로 전년 51건보다 늘었다.

| 오류 유형 | 영향 페이지 비율 |
| --- | --- |
| 저대비 텍스트 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 라벨 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

출처: [WebAIM Million](https://webaim.org/projects/million/)

ARIA 사용은 늘었지만(페이지의 82.7%, 페이지당 평균 133개 이상) ARIA 를 쓴 페이지의 평균 오류는 59.1건으로, 쓰지 않은 페이지의 42건보다 많았다([WebAIM Million](https://webaim.org/projects/million/)). 상관관계일 뿐 인과는 아니지만, 네이티브 HTML 로 해결 가능한 곳에 ARIA 를 덧씌우는 것이 안전하지 않다는 기존 권고와 일치한다.

**한계**: 이 수치는 자동 검사 결과이며 홈페이지만 대상으로 한다. 자동 도구는 WCAG 위반의 일부만 잡으므로 실제 비준수 비율은 이보다 높을 가능성이 크다.

## 기술 표준: WCAG 3.0 은 아직 초안

W3C 는 [2026년 3월 3일 WCAG 3.0 워킹 드래프트](https://www.w3.org/WAI/news/2026-03-03/wcag3)에 대한 검토 의견을 받고 있으며, 의견은 wai@w3.org 또는 GitHub 로 낼 수 있다. [드래프트 본문](https://www.w3.org/TR/2026/WD-wcag-3.0-20260303/)은 워킹 드래프트 게재가 W3C 와 회원사의 승인을 뜻하지 않는다고 명시한다. 이번 조사에서 3월 이후의 더 새로운 드래프트는 확인하지 못했다. 따라서 현 시점의 준수 기준은 계속 WCAG 2.x(현행 권고안 2.2)로 두는 것이 합리적이다.

## 성능: INP 가 여전히 가장 약한 고리

2차 자료에 따르면 2026년 초 CrUX 기준 약 43%의 사이트가 INP 200ms 기준을 넘긴다. 기준값은 LCP 2.5초, INP 200ms, CLS 0.1(75퍼센타일)이다([Core Web Vitals in 2026](https://anim.hr/en/blog/core-web-vitals-2026) 등 블로그 종합). 다만 이는 Google 1차 자료로 직접 검증하지 못한 2차 블로그 수치이므로 참고용으로만 보고, 실제 판단은 자사 CrUX·RUM 데이터로 해야 한다.

## 오늘 바로 적용할 것

- 본문 텍스트 대비를 4.5:1 이상으로 점검한다(가장 흔한 실패, 83.9%).
- 의미 있는 이미지에 alt, 모든 입력에 연결된 `<label>`을 확인한다.
- 텍스트 없는 링크·버튼(아이콘 전용)에 접근 가능한 이름을 부여한다.
- ARIA 를 추가하기 전에 네이티브 요소로 대체 가능한지 먼저 본다.
- `<html lang>` 을 확인한다.
- Lighthouse 점수가 아니라 CrUX 필드 데이터로 INP 를 확인한다.
