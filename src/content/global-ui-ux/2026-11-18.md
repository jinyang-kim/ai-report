## 접근성: 상위 100만 홈페이지는 오히려 나빠졌다

2026년 2월에 상위 100만 개 홈페이지를 스캔한 [The WebAIM Million](https://webaim.org/projects/million/)에 따르면 검출된 오류는 총 56,114,377건으로 페이지당 평균 56.1개입니다. 2025년의 51개보다 10.1% 늘었습니다. WCAG 2 위반이 자동 검출된 홈페이지 비율도 94.8%에서 95.9%로 올랐습니다. 페이지당 평균 요소 수는 1,437개로 14.3% 늘었으며, 페이지가 복잡해지는 속도를 접근성 개선이 따라가지 못하는 모양새입니다.

| 오류 유형 | 영향받은 홈페이지 비율 |
| --- | --- |
| 낮은 대비 텍스트 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

출처: [The WebAIM Million](https://webaim.org/projects/million/)

ARIA 사용도 늘었습니다. 82.7%의 페이지가 ARIA를 쓰고(전년 79.4%) 페이지당 133개 이상 속성이 검출됩니다. ARIA를 쓴 페이지의 평균 오류는 59.1개로, 쓰지 않은 페이지의 42개보다 많습니다([WebAIM](https://webaim.org/projects/million/)). 다만 이는 상관관계일 뿐이고, ARIA가 오류를 일으킨다는 뜻으로 읽으면 안 됩니다. 보고서도 자동 검사는 모든 실패를 잡지 못하며 "오류가 검출되지 않았다고 해서 접근성이 있거나 적합하다는 뜻은 아니다"라고 한계를 밝힙니다.

## 성능: Core Web Vitals 기준은 그대로

[web.dev](https://web.dev/articles/vitals)에 따르면 세 지표 모두 현재 Stable 상태이고 기준은 다음과 같습니다.

- **LCP**(로딩): 2.5초 이내
- **INP**(상호작용): 200ms 이하
- **CLS**(시각적 안정성): 0.1 이하

각 지표는 모바일·데스크톱별로 페이지 로드의 75번째 백분위에서 측정하며, 세 지표를 모두 충족해야 통과입니다([web.dev](https://web.dev/articles/vitals)). 검색해 보면 "2026년 INP 샘플링 강화" 같은 2차 블로그 주장이 보이지만 공식 문서에서는 확인하지 못했으므로 이 리포트에서는 다루지 않습니다. 변경 여부는 web.dev 와 Search Central 에서 직접 확인하세요.

## 기술 표준: WCAG 3는 아직 초안

W3C는 2026년 3월 3일 [WCAG 3 작업 초안을 검토용으로 갱신](https://www.w3.org/WAI/news/2026-03-03/wcag3)했고, 의견은 공개 메일링 리스트나 GitHub으로 받습니다. 공지문은 최종화 시점을 밝히지 않습니다. 따라서 규정 준수와 조달 요건은 계속 WCAG 2.2 기준으로 맞추는 것이 안전합니다. 이 항목은 W3C 공지문 범위에서만 확인한 내용이며, 이후 초안 공개 여부는 확인하지 못했습니다.

## 오늘 바로 적용할 것

- 색 대비부터 점검합니다. 가장 흔한 오류(83.9%)이면서 디자인 토큰 수준에서 한 번에 고칠 수 있습니다.
- 아이콘 전용 링크·버튼에 접근 가능한 이름이 있는지, 모든 입력에 레이블이 연결돼 있는지 CI 자동 검사(pa11y, axe 등)에 넣습니다. 단, 자동 검사는 일부만 잡는다는 점을 전제로 키보드·스크린리더 수동 점검을 병행합니다.
- ARIA는 네이티브 HTML로 해결되지 않을 때만 사용합니다.
- LCP·INP·CLS 는 실사용자 데이터의 75번째 백분위로 확인하고, 실험실 수치만으로 통과를 판단하지 않습니다.
