## 접근성

WebAIM 이 2026년 2월 상위 100만 개 홈페이지를 자동 검사한 결과, 평균 오류는 페이지당 56.1개로 2025년(51개)보다 10.1% 늘었고, 95.9%의 페이지에서 WCAG 2 실패가 감지됐다 ([WebAIM Million](https://webaim.org/projects/million/)).

| 오류 유형 | 영향받은 홈페이지 비율 |
| --- | --- |
| 낮은 텍스트 대비 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

출처: [WebAIM Million](https://webaim.org/projects/million/)

ARIA 사용 홈페이지는 82.7%(2025년 79.4%)로 늘었지만, ARIA 를 쓴 페이지의 평균 오류는 59.1개로 쓰지 않은 페이지(42개)보다 많았다 ([WebAIM Million](https://webaim.org/projects/million/)).

> ARIA 가 많을수록 접근성이 좋아지는 것이 아니라, 오히려 오류가 많은 페이지와 함께 나타난다.

한계: 이 조사는 자동 검사 결과라서 키보드 사용성이나 스크린리더 경험처럼 도구가 잡지 못하는 문제는 반영하지 못한다. 또 ARIA 와 오류 수의 관계는 상관관계이며, 원인이라고 단정할 수 없다. (이 해석은 본 리포트의 주석이다.)

## 성능

Core Web Vitals 는 LCP, INP, CLS 세 가지이고 INP 는 2024년 3월 FID 를 대체했다. 이 세부 수치는 SEO 업체 블로그의 2차 정보로만 확인했고, HTTP Archive 의 Web Almanac 원문은 확인하지 못했으므로 이 리포트에서는 수치를 인용하지 않는다. 임계값과 최신 통과율은 Google 의 web.dev 와 Web Almanac 원문에서 직접 확인하길 권한다.

## 기술 표준

W3C 는 2026년 3월 3일 WCAG 3 작업 초안 갱신을 공개하고 의견을 받고 있다. 의견은 wai@w3.org 메일링 리스트나 GitHub 이슈로 낼 수 있다 ([W3C WAI 공지](https://www.w3.org/WAI/news/2026-03-03/wcag3)). 문서 자체는 아직 Working Draft 상태다 ([WCAG 3.0](https://www.w3.org/TR/WCAG30/)). 규제 기준이 WCAG 2.x 에서 바뀐다고 볼 근거는 현재 확인한 범위에 없다.

## 오늘 바로 적용할 것

- 텍스트 대비를 먼저 점검한다. 가장 흔한 실패(83.9%)다.
- 이미지 `alt`, 폼 `label`, 링크·버튼의 접근 가능한 이름 누락을 CI 자동 검사로 걸러낸다.
- 네이티브 HTML 로 해결되는 곳에는 ARIA 를 덧붙이지 않는다.
- 자동 검사 통과 후에도 키보드와 스크린리더로 핵심 흐름을 직접 확인한다.
- 기준은 계속 WCAG 2.2 로 두고, WCAG 3 는 의견 제출 여부만 검토한다.
