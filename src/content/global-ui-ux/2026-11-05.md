## 접근성

[WebAIM Million](https://webaim.org/projects/million/) 2026 결과, 상위 100만 홈페이지의 95.9%에서 자동 검출 가능한 WCAG 2 위반이 발견됐다(2025년 94.8%). 페이지당 평균 오류는 56.1개로 전년 51개에서 약 10% 늘었다.

| 오류 유형 | 해당 홈페이지 비율 |
| --- | --- |
| 낮은 텍스트 대비 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 라벨 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

([WebAIM Million](https://webaim.org/projects/million/))

ARIA 사용은 늘고 있지만 품질로 이어지지 않는다. 홈페이지의 82.7%가 ARIA를 쓰고 페이지당 평균 133개 넘는 속성이 있다(전년 대비 27% 증가). ARIA를 쓰는 페이지의 평균 오류는 59.1개, 쓰지 않는 페이지는 42개였다. ARIA 메뉴가 있는 페이지의 22%는 마크업이나 상호작용이 빠져 오히려 장벽을 만들었다. ([WebAIM Million](https://webaim.org/projects/million/))

> 자동 검사로 잡히는 오류만 집계한 수치이므로, 실제 장벽은 이보다 많다고 봐야 한다.

한계: WebAIM은 자동 검사 기반이라 키보드 흐름, 스크린리더 읽기 순서, 문맥상 적절한 대체 텍스트는 평가하지 못한다. 표본도 홈페이지에 한정된다.

## 성능

[web.dev](https://web.dev/articles/vitals)의 Core Web Vitals 기준은 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하다. 모바일·데스크톱 각각 75번째 백분위에서 세 지표를 모두 충족해야 통과한다. 평균이 아니라 대다수 사용자가 기준을 맞춰야 한다는 뜻이다.

## 기술 표준

W3C WAI는 2026년 3월 3일 [WCAG 3.0 작업 초안 갱신본](https://www.w3.org/WAI/news/2026-03-03/wcag3)을 검토용으로 공개하고 피드백을 받고 있다. 해당 공지에는 확정 시점이 나와 있지 않다. 따라서 WCAG 3.0은 아직 표준이 아니며, 실무 기준은 WCAG 2.2로 보는 것이 안전하다(이 판단은 위 공지가 일정을 밝히지 않았다는 점에 근거한 해석이다).

## 오늘 바로 적용할 것

- 팀 사이트에서 대비 비율 4.5:1 미만 텍스트를 먼저 점검한다. 가장 흔한 오류(83.9%)다.
- 아이콘 전용 버튼·링크에 접근 가능한 이름(텍스트 또는 `aria-label`)이 있는지, 폼 입력에 `<label>`이 연결돼 있는지 확인한다.
- ARIA를 추가하기 전에 네이티브 HTML 요소(`button`, `details`, `nav`)로 해결되는지 검토한다.
- 성능은 실사용자 데이터(CrUX 등)의 75번째 백분위로 LCP·INP·CLS를 확인한다.
