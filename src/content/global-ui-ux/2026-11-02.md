## 접근성

WebAIM 이 2026년 2월에 상위 100만 홈페이지를 자동 검사한 결과, 페이지당 평균 검출 오류는 56.1개로 전년(51개)보다 10.1% 늘었고 95.9%의 페이지에서 WCAG 2 위반이 검출됐습니다. 오류가 5개 이하인 페이지는 20.5%에 그쳤습니다. ([WebAIM Million](https://webaim.org/projects/million/))

| 오류 유형 | 해당 홈페이지 비율 |
| --- | --- |
| 낮은 대비 텍스트 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

이 여섯 유형이 검출 오류의 96%를 차지합니다. ([WebAIM Million](https://webaim.org/projects/million/)) 즉 소수의 반복 패턴만 고쳐도 자동 검출 오류 대부분이 사라집니다.

ARIA 사용은 계속 늘고 있습니다. ARIA 를 쓰는 페이지(랜드마크 역할 제외)는 82.7%로 전년 79.4%보다 늘었고, ARIA 를 쓴 페이지의 평균 오류는 59.1개로 쓰지 않은 페이지(42개)보다 많았습니다. ARIA 메뉴가 있는 페이지는 5.7%였고 그 메뉴의 22%가 오히려 장벽을 만들었습니다. ([WebAIM Million](https://webaim.org/projects/million/))

한계: 이 수치는 자동 검사로 잡히는 항목만 센 것입니다. ARIA 사용량과 오류 수의 상관은 인과를 뜻하지 않습니다(복잡한 페이지일수록 ARIA 도 오류도 많을 수 있음). 자동 검사는 키보드 조작성이나 스크린리더 실사용 경험은 판단하지 못하므로, 오류 0 이 곧 접근성 확보는 아닙니다.

## 성능

Chrome UX Report(CrUX) 월별 릴리스 노트 기준 2026년 9월 좋음 판정 오리진 비율은 LCP 68.3%, CLS 81.7%, INP 85.4%이고 세 지표를 모두 통과한 비율은 55.9%입니다. ([CrUX release notes](https://developer.chrome.com/docs/crux/release-notes))

| 2026년 | LCP | CLS | INP | 전체 통과 |
| --- | --- | --- | --- | --- |
| 1월 | 68.3% | 80.9% | 87.1% | 55.7% |
| 3월 | 69.0% | 81.2% | 87.2% | 56.5% |
| 6월 | 67.7% | 81.4% | 85.9% | 55.3% |
| 9월 | 68.3% | 81.7% | 85.4% | 55.9% |

전체 통과율은 1월부터 9월까지 55.3～56.5% 범위에서 움직였고, INP 는 87.1%에서 85.4%로 소폭 낮아졌습니다. LCP 가 가장 낮은 지표라 전체 통과율의 병목입니다. 9월 릴리스에는 소프트 내비게이션을 포함한 실험적 수치(전체 59.5%)도 함께 실렸습니다. ([CrUX release notes](https://developer.chrome.com/docs/crux/release-notes))

한계: CrUX 는 Chrome 사용자 중 충분한 트래픽이 있는 오리진만 집계하므로 전체 웹이나 트래픽이 적은 사이트를 대표하지 않습니다. 또 오리진 단위 비율이어서 페이지·방문 단위 경험과는 다릅니다.

## 기술 표준

W3C 는 2026년 3월 3일 WCAG 3 작업 초안(Working Draft)을 갱신하고 의견을 받고 있습니다. ([W3C WAI](https://www.w3.org/WAI/news/2026-03-03/wcag3), [WCAG 3.0 초안](https://www.w3.org/TR/2026/WD-wcag-3.0-20260303/)) 의견은 wai@w3.org 메일링 리스트나 GitHub 이슈로 보낼 수 있고, 해당 안내 페이지에는 마감일이 적혀 있지 않았습니다. 초안은 확정 표준이 아니므로 법규·계약상 준수 기준은 현재 W3C 권고안인 WCAG 2.2 로 보는 것이 안전합니다.

## 오늘 바로 적용할 것

- 색 대비: 본문과 UI 텍스트 토큰을 대비 4.5:1 기준으로 점검하고, 다크 모드까지 같은 기준을 적용합니다. 가장 흔한 오류(83.9%)입니다.
- 이름 없는 요소: 아이콘 버튼과 아이콘 링크에 접근 가능한 이름이 있는지, 이미지에 `alt`, 폼 입력에 `label` 이 있는지 확인합니다.
- `<html lang>` 이 설정돼 있는지 확인합니다.
- ARIA 는 네이티브 요소로 해결되지 않을 때만 쓰고, 메뉴류는 `<details>` 같은 네이티브 패턴을 우선 검토합니다.
- CrUX 필드 데이터로 LCP 를 먼저 점검합니다(통과율이 가장 낮음).
- 자동 검사에 더해 키보드 단독 조작과 스크린리더 점검을 릴리스 체크리스트에 넣습니다.
