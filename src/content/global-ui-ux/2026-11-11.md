## 접근성: 자동 검사로 잡히는 오류조차 늘었다

[WebAIM Million](https://webaim.org/projects/million/) 2026 결과, 상위 100만 사이트 홈페이지의 평균 오류는 56.1개로 전년 51개에서 약 10% 늘었고, 95.9%가 감지 가능한 WCAG 실패를 하나 이상 갖고 있었다(전년 94.8%). 같은 보고서에서 홈페이지당 평균 요소 수는 1,437개로 전년(1,257개)보다 14.3% 늘었다. 페이지가 복잡해질수록 오류도 같이 늘어난 셈이다.

가장 흔한 오류 6종은 [WebAIM](https://webaim.org/projects/million/)이 집계한 비율로 아래와 같다.

| 오류 유형 | 홈페이지 비율 |
| --- | --- |
| 낮은 텍스트 대비 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

실제 영향은 분명하다. 레이블 없는 입력창과 빈 버튼은 스크린리더 사용자에게 용도를 알 수 없는 컨트롤이 되고, 이는 곧 유럽 접근성법(EAA) 등 컴플라이언스 리스크로 이어진다.

**한계:** 이 수치는 자동 검사 도구가 감지한 오류만 센다. 키보드 조작 순서, 의미 있는 대체 텍스트의 품질 같은 항목은 자동화로 잡히지 않으므로, 오류 0개가 곧 접근성 충족은 아니다. 또 홈페이지만 대상이라 서비스 내부 화면의 상태는 반영하지 못한다.

## 성능: Core Web Vitals 통과율은 정체 상태

[CrUX 릴리스 노트](https://developer.chrome.com/docs/crux/release-notes)에 따르면 Core Web Vitals가 모두 양호한 오리진 비율은 2026년 1월 55.7%에서 9월 55.9%로 거의 움직이지 않았다. INP 양호 비율은 같은 기간 87.1%에서 85.4%로 약간 내려갔다.

| 월 | CWV 양호 | INP 양호 |
| --- | --- | --- |
| 2026-01 | 55.7% | 87.1% |
| 2026-05 | 55.9% | 86.6% |
| 2026-09 | 55.9% | 85.4% |

9월 항목에는 소프트 내비게이션을 포함한 실험 수치(CWV 59.5%, INP 87.4%)도 함께 실려 있다. SPA 중심 사이트는 측정 방식에 따라 결과가 달라질 수 있다는 뜻이다.

**한계:** 이 수치는 페이지가 아니라 오리진 단위 집계이고 Chrome 사용자 데이터만 반영한다. 방문이 적은 사이트는 CrUX에 포함되지 않는다.

## 기술 표준: WCAG 3.0은 아직 작업 초안

[W3C의 WCAG 3.0 작업 초안(2026년 3월 3일판)](https://www.w3.org/TR/2026/WD-wcag-3.0-20260303/)은 developing 단계에 도달한 요구사항을 모두 담았다. 문서는 이를 진행 중인 작업물로 규정하며, 이 문서를 작업 중인 초안 외의 것으로 인용하는 것은 부적절하다고 밝힌다. 또 WCAG 3은 WCAG 2.2의 후속이지만 WCAG 2를 폐기하지 않으며, 많은 국가에서 WCAG 2가 오래 요구될 것이라고 적고 있다.

> 지금의 실무 기준은 여전히 WCAG 2.2 AA다. WCAG 3.0 초안은 방향을 읽는 용도로 보자.

## 오늘 바로 적용할 것

- 자사 홈페이지를 axe나 Lighthouse로 돌려 WebAIM 상위 6종(대비·alt·폼 레이블·빈 링크·빈 버튼·`lang`)부터 0으로 만든다.
- 아이콘 전용 버튼과 링크에는 `aria-label`이나 보이는 텍스트를 넣는다.
- CrUX 대시보드나 PageSpeed Insights의 필드 데이터에서 INP 75번째 백분위가 200ms 이하인지 확인한다.
- 자동 검사 후에는 키보드만으로 핵심 흐름을 한 번 끝까지 통과해 본다.
