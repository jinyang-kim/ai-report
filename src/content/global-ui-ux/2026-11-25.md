## 접근성: 오류는 줄지 않고 늘었다

[WebAIM Million](https://webaim.org/projects/million/) 2026 보고서에 따르면 상위 100만 홈페이지의 페이지당 평균 오류는 56.1개로 전년(51개)보다 10.1% 늘었고, 95.9%의 페이지에서 WCAG 2 실패가 감지됐다(전년 94.8%).

| 오류 유형 | 해당 홈페이지 비율 |
| --- | --- |
| 낮은 대비 텍스트 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

이 여섯 유형이 감지된 오류의 96%를 차지한다. 즉 소수의 반복 실수를 고치는 것만으로도 큰 개선이 가능하다.

ARIA 사용도 계속 늘고 있다. [WebAIM](https://webaim.org/projects/million/)에 따르면 ARIA 사용 페이지는 82.7%(전년 79.4%)이며, ARIA가 있는 페이지의 평균 오류는 59.1개로 없는 페이지(42개)보다 많았다. `role="menu"`를 쓴 페이지의 22%는 필수 마크업이나 상호작용이 빠져 오히려 장벽을 만들었다. 다만 이는 ARIA가 있는 페이지가 더 복잡하다는 점과 섞인 상관관계이며, 인과로 단정할 수 없다.

**한계**: 이 수치는 자동 검사 도구가 감지한 오류 기준이다. 자동 검사는 WCAG 위반의 일부만 잡으므로 오류 수가 적다고 접근성이 좋다는 뜻은 아니다. 스크린리더 실사용 테스트가 필요하다.

## 성능: INP는 소폭 하락, 전체 통과율은 56%대

[Chrome UX Report 릴리스 노트](https://developer.chrome.com/docs/crux/release-notes/?hl=en)의 2026년 10월 데이터(2026-11-11 공개)는 다음과 같다.

| 지표 | 좋음 비율(origin 기준) |
| --- | --- |
| INP | 85.2% |
| LCP | 68.8% |
| CLS | 81.6% |
| 코어 웹 바이탈 전체 | 56.3% |

LCP가 가장 낮아 전체 통과율의 병목으로 보인다(이는 위 수치에서 읽은 해석이다). 이 수치는 실제 Chrome 사용자 데이터에 기반하지만, Chrome 사용자 중 일정 트래픽 이상인 origin만 포함하므로 소규모 사이트나 다른 브라우저 사용자는 반영되지 않는다.

## 기술 표준: WCAG 3는 아직 초안

W3C는 [WCAG 3 작업 초안을 2026년 3월 3일에 갱신](https://www.w3.org/WAI/news/2026-03-03/wcag3)했다. 해당 안내 페이지는 변경 내용 자체를 설명하지 않고 [WCAG 3 소개 문서](https://www.w3.org/TR/wcag3)의 진행 상태 섹션을 참조하라고 안내한다. 이번 조사에서 확인한 범위에서는 WCAG 3를 법적·계약상 기준으로 삼을 근거가 없으므로, 규정 준수 목적에는 계속 WCAG 2.x를 기준으로 삼는 것이 안전하다.

## 오늘 바로 적용할 것

- 대비 검사: 디자인 토큰 단위로 텍스트 대비 4.5:1(큰 글씨 3:1)을 CI에서 검증한다. 오류 1위(83.9%)다.
- 폼·링크·버튼 점검: 레이블 없는 입력, 이름 없는 아이콘 링크·버튼(빈 링크·빈 버튼)을 `aria-label` 또는 보이는 텍스트로 채운다.
- `<html lang>` 확인: 문서 언어 누락은 가장 고치기 쉬운 오류다.
- ARIA는 네이티브 요소로 대체 가능한지 먼저 검토한다. 메뉴 역할은 키보드 상호작용까지 구현할 때만 쓴다.
- 자사 origin의 LCP를 CrUX와 비교한다. 업계 LCP 좋음 비율이 68.8%라 개선 여지가 가장 크다.
