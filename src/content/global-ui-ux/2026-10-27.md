## 접근성

2026 WebAIM Million(상위 100만 홈페이지 자동 검사)에서 [95.9%의 페이지가 WCAG 2 위반을 보였고 전년의 94.8%보다 악화](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/)됐습니다. 페이지당 평균 오류는 56.1개로 10.1% 늘었고, 평균 요소 수는 1,437개로 1년 새 22.5% 증가했습니다. 같은 글은 페이지 복잡도 증가와 AI 보조 개발을 악화 요인으로 *추정*합니다.

| 오류 유형 | 해당 페이지 비율 |
| --- | --- |
| 저대비 텍스트 | 83.9% (전년 79.1%) |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 라벨 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 선언 누락 | 13.5% |

위 여섯 유형이 [탐지된 오류의 96%](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/)를 차지하고 7년째 상위권입니다. 또 [ARIA 를 쓴 페이지는 평균 59.1개, 쓰지 않은 페이지는 42개](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/)의 오류를 보였습니다. 인과가 아니라 상관관계이며(복잡한 페이지일수록 ARIA 도 많이 씀), 네이티브 요소를 먼저 쓰라는 원칙을 다시 확인시켜 줍니다.

**한계**: 이 수치는 자동 검사로 잡히는 오류만 센 것이라 [실제 비준수율은 더 높을 가능성이 큽니다](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/). 또 홈페이지만 대상이라 내부 페이지·로그인 이후 흐름은 반영되지 않습니다. 이번 정리는 2차 보도 기반이므로 정확한 수치는 WebAIM 원문으로 재확인하세요.

## 성능

INP 는 FID 의 후속 지표로, 첫 상호작용만 보던 FID 와 달리 [방문 중 클릭·탭·키보드 상호작용 전체의 지연](https://web.dev/articles/inp)을 봅니다. 기준은 모바일·데스크톱 각각 필드 데이터 75퍼센타일에서 **200ms 이하 좋음, 500ms 초과 나쁨**입니다. 상호작용이 많은 페이지에서는 [50번당 가장 느린 하나를 제외](https://web.dev/articles/inp)해 이상치를 줄입니다. 랩 테스트는 어떤 상호작용을 수행하느냐에 따라 값이 달라지므로 [필드 데이터를 권장](https://web.dev/articles/inp)합니다.

이번 조사에서는 2026년 HTTP Archive·CrUX 의 INP 분포 1차 자료를 확인하지 못해, 통과율 같은 산업 수치는 싣지 않습니다.

## 기술 표준

W3C 는 [2026년 3월 3일 WCAG 3 작업 초안(Working Draft)을 갱신하고 의견을 받고 있습니다](https://www.w3.org/WAI/news/2026-03-03/wcag3)(wai@w3.org 또는 GitHub 이슈). 작업 초안은 언제든 바뀔 수 있어 컴플라이언스 근거로 인용할 수 없고, 현재 실무 기준은 WCAG 2.2 입니다. 이후에 더 새로운 초안이 있다는 2차 정보도 있었으나 직접 확인하지 못했으므로 W3C 의 최신 버전 링크를 확인하세요.

## 오늘 바로 적용할 것

- 디자인 토큰의 텍스트 색 대비를 4.5:1(큰 글자 3:1) 기준으로 일괄 점검합니다. 가장 흔한 오류가 여기서 나옵니다.
- 아이콘 전용 링크·버튼에 접근 가능한 이름이 있는지, 모든 입력에 `label` 이 연결됐는지, `<html lang>` 이 있는지 확인합니다.
- 새 ARIA 를 넣기 전에 네이티브 요소(`button`, `details` 등)로 대체 가능한지 먼저 봅니다.
- INP 는 CrUX 등 필드 데이터로 확인하고, 느린 상호작용의 긴 이벤트 핸들러를 쪼개거나 지연시킵니다.
- 자동 검사 통과 후에도 키보드만으로, 스크린리더로 핵심 흐름을 직접 한 번 돌려 봅니다.
