## 접근성: 개선 흐름이 꺾였다

2026 WebAIM Million 은 상위 100만 홈페이지 중 [95.9% 에서 WCAG 2 실패가 탐지됐고 전년의 94.8% 보다 늘었다고](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/) 보고했습니다. 페이지당 평균 오류는 56.1개로 10.1% 증가했고, 평균 요소 수도 1,437개로 22.5% 늘었습니다. WebAIM 추산으로는 [장애가 있는 사용자가 요소 약 26개마다 오류 하나를 만나는 셈](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/)입니다.

| 오류 유형 | 발생 페이지 비율 |
| --- | --- |
| 낮은 명도 대비 텍스트 | 83.9% (전년 79.1%) |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 라벨 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

위 수치는 [Nexer Digital 의 요약](https://www.nexerdigital.com/news-and-thoughts/the-webaim-million-report-2026-what-it-tells-us)에서 확인한 값입니다. 같은 여섯 가지 오류 유형이 [7년째 전체 이슈의 96%](https://www.nexerdigital.com/news-and-thoughts/the-webaim-million-report-2026-what-it-tells-us)를 차지합니다. 대체 텍스트 누락과 언어 누락은 소폭 줄었습니다.

**한계**: 자동 검사는 문제의 일부만 잡습니다. 실제 비준수율은 [이보다 높을 가능성이 큽니다](https://www.nexerdigital.com/news-and-thoughts/the-webaim-million-report-2026-what-it-tells-us). 반대로 오류 0건이 곧 접근성 보장은 아닙니다. 대비 부족은 컴플라이언스 리스크로 직결되는 항목인데, 이 항목이 가장 많이 늘었습니다.

## 기술 표준: WCAG 3 는 아직 계획용

W3C 는 [2026년 3월 3일 WCAG 3 작업 초안 갱신본을 검토용으로 공개](https://www.w3.org/WAI/news/2026-03-03/wcag3)했습니다. 검색으로 확인한 2차 자료에 따르면 이번 초안에서 "Foundational Requirements" 가 "Core Requirements" 로, Outcomes 가 Requirements 로 바뀌었고 적합성 섹션이 크게 개편됐습니다. 문서 자체가 [언제든 갱신·대체·폐기될 수 있다고 명시](https://www.w3.org/TR/WCAG3/)하므로, 현재 법적·조달 기준은 WCAG 2.x 로 두는 것이 안전합니다. 최종 발행 시점은 확인하지 못했습니다.

## 성능: 절반 남짓만 통과

[2차 통계 사이트가 인용한 CrUX 2026년 1월 분석](https://www.shno.co/marketing-statistics/core-web-vitals-statistics)(원자료 직접 확인은 못 함)에서는 세 지표를 모두 통과한 origin 이 약 55.7% 였습니다. 지표별 good 비율은 LCP 68.3%, INP 87.1%, CLS 80.9% 로, 병목은 LCP 입니다. INP 기준은 75퍼센트 백분위 필드 데이터 200ms 이하입니다. INP 모바일 통과율 등 다른 수치는 출처마다 엇갈려 신뢰하기 어렵습니다. 2025 Web Almanac 의 모바일 48%·데스크톱 56% 도 2차 인용이라 원문 확인이 필요합니다.

## 오늘 바로 적용할 것

- 텍스트·배경 색 조합을 일괄 점검해 대비 4.5:1(큰 글자 3:1)을 맞춥니다. 가장 흔하고 가장 늘어난 오류입니다.
- 아이콘 버튼·아이콘 링크에 접근 가능한 이름(`aria-label` 또는 시각적으로 숨긴 텍스트)이 있는지 확인합니다.
- 입력 필드마다 `<label>` 이 연결돼 있는지, `<html lang>` 이 있는지 봅니다.
- CrUX 필드 데이터에서 LCP 요소(대개 히어로 이미지)부터 개선합니다.
- WCAG 3 는 모니터링만 하고, 자동 검사 통과 뒤에는 키보드·스크린리더 수동 점검을 병행합니다.
