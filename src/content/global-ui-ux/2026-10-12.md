## 접근성

[WebAIM Million 2026](https://webaim.org/projects/million/)(2026년 2월 기준 상위 100만 홈페이지 자동 검사)에 따르면 홈페이지당 탐지된 오류는 평균 56.1개로 전년의 51.0개보다 10.1% 늘었고, 95.9% 의 페이지에서 WCAG 2 위반이 탐지됐습니다(전년 94.8%).

| 오류 유형 | 영향 페이지 비율 |
| --- | --- |
| 낮은 대비 텍스트 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

출처: [WebAIM Million 2026](https://webaim.org/projects/million/)

- 페이지당 요소 수는 평균 1,437개로 늘어 복잡도가 높아졌습니다.
- ARIA 사용 페이지는 82.7% 로 늘었지만, ARIA 가 있는 페이지의 평균 오류는 59.1개로 없는 페이지(42개)보다 많았습니다. 이 수치는 상관관계이며 ARIA 가 오류를 만든다는 인과의 증거는 아닙니다 ([WebAIM](https://webaim.org/projects/million/)).
- 한계: 자동 검사는 WCAG 위반의 일부만 잡습니다. 실제 비준수 수준은 이보다 높을 가능성이 큽니다.

## 성능

[CrUX 릴리스 노트](https://developer.chrome.com/docs/crux/release-notes.md.txt)의 2026년 8월 데이터(9월 8일 공개)는 다음과 같습니다.

- Core Web Vitals 전체 통과 origin: 55.6% (직전 월 대비 0.2%p 하락)
- LCP 양호 68.1%, CLS 양호 81.5%, INP 양호 85.3% (INP 0.5%p 하락)

Chrome 팀은 INP 의 지속적 하락이 우려되지만 "definitive reason" 은 아직 없다고 밝혔습니다([CrUX 릴리스 노트](https://developer.chrome.com/docs/crux/release-notes.md.txt)). 통과율은 origin 단위 75퍼센타일 현장 데이터 기준이며, 트래픽이 적은 사이트는 표본에서 빠진다는 점을 감안해야 합니다.

## 기술 표준

W3C WAI 는 2026년 3월 3일 [WCAG 3 작업 초안 갱신](https://www.w3.org/WAI/news/2026-03-03/wcag3)을 검토용으로 공개했고 GitHub 와 공개 메일로 의견을 받고 있습니다. 해당 공지는 여전히 개발 중인 초안임을 밝히며, 세부 변경 내용은 공지 본문에 없고 WCAG 3 소개 문서의 상태 항목에서 확인하도록 안내합니다. 확정 전이므로 계약·컴플라이언스 기준은 계속 WCAG 2.2 로 두는 것이 안전합니다.

## 오늘 바로 적용할 것

- 텍스트 대비 점검을 CI 에 넣기: 가장 흔한 오류(83.9%)이면서 자동 검출이 쉽습니다.
- 아이콘 버튼·링크에 접근 가능한 이름 부여, 폼 입력에 `label` 연결, `<html lang>` 확인.
- 불필요한 ARIA 를 걷어내고 네이티브 요소를 우선 사용.
- 필드 데이터(CrUX)에서 INP 75퍼센타일을 확인하고 200ms 초과 상호작용부터 추적.
- 자동 검사 통과를 접근성 완료로 간주하지 말고 키보드·스크린리더 수동 점검을 병행.
