## 접근성 — WCAG 3.0, 워킹드래프트는 나왔지만 "등급"은 아직 정해지지 않았다

W3C 는 2026년 3월 3일 **WCAG 3.0 워킹드래프트**를 새로 공개했습니다
([For Review: WCAG 3 Working Draft – March 2026](https://www.w3.org/WAI/news/2026-03-03/wcag3)).
문서 자체는 "여러 해의 작업이 남아 있으며 세부 사항이 크게 바뀔 수 있다"고 명시하는 초기 단계입니다
([W3C Accessibility Guidelines (WCAG) 3.0](https://www.w3.org/TR/wcag-3.0/)).

확인 가능한 핵심은 이렇습니다.

- **요구사항이 WCAG 2 의 성공 기준(Success Criteria)보다 더 세분화**됩니다. 문서는 "요구사항 목록이
  WCAG 2 의 성공 기준 목록보다 길다"고 명시하지만, 최종 개수는 아직 확정되지 않았습니다.
- **"몇 가지 적합성 레벨이 이용 가능하다"**고만 언급될 뿐, 레벨의 이름·개수·산정 방식은 초안에
  구체화돼 있지 않습니다 — 일부 3차 자료가 언급하는 등급 명칭은 이 시점 원문에서 확인되지 않아
  이번 리포트에서는 인용하지 않습니다.
- **WCAG 2.2 레벨 A·AA 를 충족하는 콘텐츠는 WCAG 3.0 의 최소 적합성 레벨도 충족할 것으로
  예상**되지만, WCAG 3.0 은 추가 테스트와 다른 점수 산정 메커니즘을 포함하므로 "그대로 통과"는
  아닙니다.

> WCAG 2.2 AA 대응은 여전히 유효한 투자입니다 — WCAG 3.0 은 WCAG 2 를 대체하지 않고, 확정 이후에도
> WCAG 2 는 최소 몇 년간 폐기되지 않습니다.

지금 시점에서 법적 기준은 여전히 WCAG 2.x 입니다. WCAG 3.0 초안을 따라잡되, 현재 진행 중인
WCAG 2.2 AA 준수 작업의 우선순위를 낮출 이유는 없습니다.

## 성능 — Core Web Vitals, 2026년 5월 CrUX 기준 동시 통과율 55.9%로 하락

Google 의 실사용자 필드 데이터인 **Chrome UX Report(CrUX)** 2026년 5월 릴리스(2026-06-09 공개,
약 1,844만 개 오리진 측정) 기준으로, **LCP·INP·CLS 세 지표를 동시에 통과한 오리진은 55.9%**로
전월 대비 0.8%p 하락했습니다
([Core Web Vitals Benchmarks 2026 — Digital Applied](https://www.digitalapplied.com/blog/core-web-vitals-benchmarks-2026-pass-rate-reference)).

| 지표(모바일, 75th percentile) | 개별 통과율 |
| --- | --- |
| LCP (2.5초 이내) | 62% |
| INP (200ms 이내) | 77% |
| CLS (0.1 이하) | 81% |

세 지표를 개별로 보면 60~80%대로 양호해 보이지만, **세 지표를 동시에** 통과해야 하는 종합
평가에서는 55.9%까지 떨어집니다 — 한 지표만 약해도 전체가 탈락하는 구조 때문입니다. 세 지표 중
**LCP 가 가장 낮은 62%로 최대 병목**이라는 점은, 이미지·폰트·서버 응답 등 "첫 콘텐츠가 눈에
보이기까지" 걸리는 시간을 최우선으로 손봐야 한다는 뜻입니다. 원 출처는 CrUX 의 28일 롤링 윈도우·
75 백분위수 측정 방식이므로, 자사 오리진의 실제 수치는 PageSpeed Insights 나 CrUX 대시보드에서
별도로 확인해야 합니다.

## UX 리서치 — AI 리서치 도구 사용 69%, 그래도 "판단"은 사람 몫

Maze 의 연례 서베이 **"The Future of User Research Report 2026"**(2025-12-23~2026-01-13 수집,
UX/제품 리서처·디자이너·마케터 약 500명 응답)에 따르면, 리서치에 대한 조직 내 수요와 AI 활용이
동시에 급증하고 있습니다
([Maze — The Future of User Research Report 2026](https://maze.co/blog/future-user-research-2026/)).

- **리서치 수요 증가를 보고한 조직이 66%** — 전년 55%에서 뛰었습니다.
- **AI 리서치 도구를 최소 일부 프로젝트에 쓰는 응답자가 69%** — 전년 대비 19%p 증가했고, 도입
  조직의 63%는 "더 빠른 인사이트 도출", 60%는 "팀 효율성 개선"을 체감한다고 답했습니다.
- **리서치를 "전략적 필수"로 보는 조직이 8%(2025)→22%(2026)** 로 약 3배 늘었습니다. 동시에
  제품 매니저 39%·마케팅 리서처 35%·마케터 23%가 직접 리서치를 수행한다고 답해, 리서치 역할이
  전담 리서처를 넘어 조직 전반으로 퍼지고 있습니다.

다만 AI 가 대체하지 못하는 영역도 응답자들이 분명히 구분했습니다 — **뉘앙스 해석 82%, 윤리적
의사결정 80%, (좋은) 질문 설계 76%** 가 여전히 사람의 판단이 필요하다고 답한 항목입니다. AI 는
데이터 정리·전사(轉寫)·초안 작성 같은 반복 작업을 줄여주는 도구로 쓰이되, 무엇을 물을지·어떻게
해석할지는 여전히 리서처의 몫이라는 뜻입니다.

## 기술 표준 — Baseline, 2026년 6~7월 새로 지원된 기능들

**Baseline**(WebDX Community Group 관리) 기준으로 2026년 6~7월에 다음 CSS·JS 기능이 새로
"Newly available" 또는 "Widely available" 등급에 올랐습니다
([June 2026 Baseline digest](https://web.dev/blog/baseline-digest-jun-2026),
[July 2026 Baseline digest](https://web.dev/blog/baseline-digest-jul-2026)).

| 기능 | 등급 | 시점 | 용도 |
| --- | --- | --- | --- |
| `field-sizing` (CSS) | Newly available | 2026-06 | textarea·input·select 가 콘텐츠 크기에 맞춰 자동으로 늘고 줄어듦 |
| `:has()` 선택자 | Widely available | 2026-06 | 자손·형제 요소 상태에 따라 부모를 스타일링(JS 없이 조건부 스타일 구현) |
| `&` 중첩 선택자 | Widely available | 2026-06 | 네이티브 CSS 중첩에서 부모 선택자를 명시적으로 참조 |
| `@media (scripting)` | Widely available | 2026-06 | JS 비활성 환경을 감지해 대체 스타일 제공 |
| `Intl.Locale` (JS) | Newly available | 2026-07 | 유니코드 로케일 태그를 표준 방식으로 파싱·조작·조회 |
| `Array.fromAsync()` | Widely available | 2026-07 | 비동기 이터러블을 배열로 변환 |
| `rect()` (CSS 함수) | Widely available | 2026-07 | 컨테이닝 블록 기준 inset 거리로 클리핑·오프셋 경로를 간단히 정의 |

`:has()` 와 `&` 중첩이 이번에 Widely available 로 확정되면서, "조건부 스타일링을 위해 JS 클래스
토글에 의존"하던 패턴을 순수 CSS 로 옮길 수 있는 폭이 넓어졌습니다. `field-sizing` 도 자동 리사이즈
textarea 구현에 쓰던 JS 라이브러리를 대체할 수 있는 단계에 가까워지고 있습니다(Newly available —
브라우저 지원 표를 먼저 확인하세요).

## 오늘 바로 적용할 것

1. **WCAG 3.0 초안을 지켜보되, 지금 진행 중인 WCAG 2.2 AA 작업의 우선순위를 낮추지 마세요.**
   등급 체계가 아직 정해지지 않았고, 2.2 AA 충족 콘텐츠는 3.0 최소 레벨의 출발점이 될 전망입니다.
2. **LCP 부터 점검하세요.** 2026년 5월 CrUX 데이터에서 모바일 LCP 통과율(62%)이 INP(77%)·
   CLS(81%)보다 뚜렷이 낮습니다 — 이미지 지연 로딩·폰트 프리로드·서버 응답 시간이 우선순위입니다.
3. **UX 리서치에 AI 도구를 도입하되 질문 설계·해석은 리서처가 쥐고 있어야 합니다.** Maze 서베이가
   보여주듯 전사·데이터 정리는 AI 로 넘겨도, 뉘앙스 해석·윤리적 판단은 사람의 몫으로 남습니다.
4. **`:has()`·CSS 중첩·`field-sizing` 로 대체 가능한 JS 패턴이 있는지 점검하세요.** 조건부
   스타일링과 자동 리사이즈 textarea 는 이제 폴리필 없이 네이티브 CSS 로 옮길 수 있는 범위가 넓어졌습니다.
