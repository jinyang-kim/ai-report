## 접근성

[WebAIM Million 2026](https://webaim.org/projects/million/)에 따르면 상위 100만 홈페이지의 평균 감지 오류는 페이지당 56.1개로, 2025년의 51개보다 10.1% 늘었다. WCAG 2 실패가 감지된 페이지 비율도 94.8% 에서 95.9% 로 올랐다. 이는 수년간 이어진 완만한 개선 추세가 뒤집힌 결과다.

| 오류 유형 | 해당 페이지 비율 |
| --- | --- |
| 저대비 텍스트 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

출처: [WebAIM Million 2026](https://webaim.org/projects/million/)

ARIA 사용도 눈에 띈다. 페이지당 ARIA 속성이 평균 133개 이상으로 1년 새 27% 늘었는데, ARIA 가 있는 페이지는 평균 오류가 59.1개로 없는 페이지(42개)보다 많았다 ([WebAIM](https://webaim.org/projects/million/)). ARIA 는 네이티브 HTML 로 해결되지 않을 때만 쓰는 보강책이라는 원칙을 다시 확인시켜 준다.

**한계**: 이 수치는 자동 검사로 감지된 오류만 센다. WebAIM 도 "감지된 오류가 없다고 해서 페이지가 접근 가능하거나 규격에 부합한다는 뜻은 아니다"라고 밝힌다 ([WebAIM](https://webaim.org/projects/million/)). 또 대상이 홈페이지에 한정돼 서비스 내부 화면을 대표하지 못한다.

## 기술 표준

W3C 는 [2026-09-10 WCAG 3 작업 초안 갱신](https://www.w3.org/WAI/news/2026-09-10/wcag3/)을 공지하며 적합성 모델에 대한 검토 질문을 함께 내놨다. 의견은 wai@w3.org 메일링 리스트나 GitHub 로 받는다. 이 문서는 어디까지나 작업 초안이며, 실무의 컴플라이언스 판단 기준은 계속 WCAG 2.x 다. 초안의 요구사항 수나 후보 권고안 시점 같은 세부 수치는 2차 해설 글마다 다르므로, 계획을 세울 때는 W3C 원문으로 확인하는 편이 안전하다.

## 성능

[Digital Applied 의 정리](https://www.digitalapplied.com/blog/core-web-vitals-benchmarks-2026-pass-rate-reference)에 따르면 2026년 5월 CrUX 릴리스(6월 9일 공개) 기준으로 LCP·INP·CLS 를 모두 통과한 origin 은 55.9% 다. 지표별 통과율은 LCP 68.6%, CLS 81.3%, INP 86.6% 로, 개선 우선순위는 LCP 가 가장 높다. 같은 자료는 2026년 업데이트에서 임계값(LCP 2.5초, INP 200ms, CLS 0.1)은 그대로이고 INP 측정 방식과 SPA 의 soft navigation 커버리지, TTFB 진단 노출이 조정됐다고 설명한다.

**한계**: 이 자료는 CrUX 를 재인용한 2차 출처이고, 통과율은 origin 단위 집계라 개별 페이지나 사용자 체감과는 다를 수 있다. 다른 글에는 "INP 실패율 43%" 같은 상충하는 수치도 있어, 집계 기간과 단위를 확인하지 않고 비교하면 안 된다.

## 오늘 바로 적용할 것

- 자사 사이트에서 가장 흔한 WebAIM 상위 6개 오류(대비, alt, 레이블, 빈 링크·버튼, lang)를 자동 검사로 먼저 정리한다. 이 여섯 가지가 오류의 대부분을 차지한다.
- 커스텀 ARIA 를 네이티브 요소(`button`, `a`, `label`)로 대체할 수 있는지 점검한다.
- 자동 검사 통과를 접근성 달성으로 보지 말고, 키보드·스크린리더 수동 점검을 릴리스 체크리스트에 넣는다.
- CrUX 에서 LCP 부터 확인하고, 계획 수립에는 WCAG 3 초안이 아니라 WCAG 2.2 를 기준으로 삼는다.
