## 접근성

2026년 2월 스캔 기준 WebAIM Million 은 상위 100만 홈페이지의 **95.9%**에서 WCAG 2 실패가 자동 검출됐고(2025년 94.8%), 페이지당 평균 오류는 **56.1개**로 약 10.1% 늘었다고 집계했다 ([Priority Pixels 해설](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/)). 페이지 평균 요소 수도 1,437개로 1년 새 22.5% 증가해, 복잡도 상승이 오류 증가와 맞물린 것으로 보인다.

| 오류 유형 | 해당 페이지 비율 |
| --- | --- |
| 낮은 대비 텍스트 | 83.9% |
| 대체 텍스트 누락 | 53.1% |
| 레이블 없는 폼 입력 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

위 여섯 유형은 7년 연속 상위를 차지했다 ([Priority Pixels](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/)). 실제 영향은 스크린리더 사용자가 이름 없는 버튼·링크를 조작하지 못하거나, 저시력 사용자가 텍스트를 읽지 못하는 것이며, 유럽접근성법(EAA) 등 컴플라이언스 리스크로도 이어진다.

**한계:** 이 수치는 자동 검사로 잡히는 오류만 센 것이라 전체 WCAG 적합성을 뜻하지 않는다. 또 ARIA 사용 페이지의 오류가 더 많다는 결과가 있지만, 이는 ARIA 가 문제를 일으킨다는 뜻이 아니라 복잡한 페이지에서 ARIA 가 더 많이 쓰인다는 상관관계로 해석해야 한다.

## 성능

Core Web Vitals 의 "좋음" 기준은 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하다 ([Digital Applied](https://www.digitalapplied.com/blog/core-web-vitals-2026)). 그런데 INP 통과율 집계는 크게 다르다.

- State of Web Vitals 2026년 1분기: 55,913개 사이트, p75 INP 109ms, **94.7% 통과** ([corewebvitals.io](https://www.corewebvitals.io/state-of-cwv/inp)).
- Digital Applied: **43%의 사이트가 200ms 기준 미달**이라 INP 가 가장 많이 실패하는 지표라고 주장 ([Digital Applied](https://www.digitalapplied.com/blog/core-web-vitals-2026)).

두 값의 차이는 표본(어떤 사이트를 포함했는지)과 방법론 차이로 보이며, 어느 쪽도 단독으로 업계 전체를 대표한다고 단정하기 어렵다. 자기 사이트는 업계 평균이 아니라 CrUX 28일 실사용자 데이터로 판단하고, Lighthouse 같은 랩 점수는 디버깅용으로만 쓰는 것이 안전하다.

## 기술 표준

W3C 는 2026년 3월 WCAG 3 작업 초안의 검토를 요청했다 ([W3C WAI 뉴스](https://www.w3.org/WAI/news/2026-03-03/wcag3)). 규범 문서는 [W3C WCAG 3.0 페이지](https://www.w3.org/TR/WCAG30/)에서 확인할 수 있고, 작업 초안은 W3C 회원의 승인을 뜻하지 않는다. 2차 자료에 따르면 WCAG 3 는 WCAG 2 를 대체하지 않으며 당분간 WCAG 2.2 요구사항을 계속 적용해야 한다. 최종 권고 시점은 확정된 일정이 없고, 일부 2차 자료의 전망(2028년 이후)은 추정일 뿐이다.

## 오늘 바로 적용할 것

- 서비스의 주요 템플릿 3개에 대해 **대비·대체 텍스트·폼 레이블·빈 링크/버튼** 여섯 항목을 자동 검사로 먼저 점검한다.
- 아이콘 전용 버튼과 링크에 `aria-label` 또는 보이는 텍스트를 부여한다.
- INP 는 CrUX(실사용자) 기준으로 확인하고, 외부 통계는 표본과 방법론을 읽은 뒤 인용한다.
- WCAG 3 대비 준비보다 먼저, 현재 법적 기준인 WCAG 2.2 AA 충족 여부를 수동 테스트(키보드·스크린리더)로 보완한다.
