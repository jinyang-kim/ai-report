## 접근성: 2026 WebAIM Million

상위 100만 사이트 홈페이지를 자동 검사하는 WebAIM Million 2026 에서 **95.9%의 페이지가 WCAG 2 위반**을 보였습니다(2025년 94.8%). 페이지당 평균 오류는 **56.1건**으로 전년 51건에서 약 10% 늘었습니다 ([WebAIM](https://webaim.org/projects/million/)). 평균 홈페이지의 요소 수는 1,437개로 1년 새 22.5% 늘어, 페이지가 복잡해진 것이 오류 증가와 맞물린 것으로 해석됩니다 ([Priority Pixels](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/)).

| 오류 유형 | 영향받은 홈페이지 비율 |
| --- | --- |
| 저대비 텍스트 | 83.9% |
| 이미지 대체 텍스트 누락 | 53.1% |
| 폼 입력 레이블 누락 | 51% |
| 빈 링크 | 46.3% |
| 빈 버튼 | 30.6% |
| 문서 언어 누락 | 13.5% |

이 여섯 유형이 검출 오류의 약 96%를 차지합니다 ([WebAIM](https://webaim.org/projects/million/)). 대비 부족은 전년 79.1%에서 더 나빠졌습니다 ([Priority Pixels](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/)).

**한계**: 자동 검사는 WCAG 위반의 일부만 잡으므로 실제 비적합 비율은 더 높을 가능성이 큽니다. 또 홈페이지만 대상이라 서브페이지·로그인 이후 화면은 반영되지 않습니다.

## 성능: Core Web Vitals 현황

2차 자료(SEO 업체 분석)에 따르면 2026년 1월 CrUX 기준 전체 오리진의 약 55.7%가 세 지표를 모두 통과했고, 지표별로는 LCP 68.3%, INP 87.1%, CLS 80.9%가 "좋음"입니다. 임계값은 변동 없이 INP 200ms 미만, 75퍼센타일·28일 롤링 기준입니다 ([eSeoSpace](https://eseospace.com/blog/core-web-vitals-in-2026-what-changed-what-still-matters-and-how-to-pass/)). 즉 병목은 INP 보다 LCP 쪽입니다.

**한계**: 이 수치는 구글 공식 발표가 아닌 2차 인용이며 집계 방식에 따라 값이 다릅니다. 원 데이터는 CrUX·HTTP Archive Web Almanac 에서 직접 확인하세요.

## 기술 표준: WCAG 3.0 은 아직 초안

W3C 는 2026년 3월 WCAG 3 작업 초안(Working Draft)을 의견 수렴용으로 공개했습니다 ([W3C WAI](https://www.w3.org/WAI/news/2026-03-03/wcag3)). 문서 자체가 작업 중인 초안이며 언제든 바뀌거나 폐기될 수 있다고 명시합니다 ([W3C](https://www.w3.org/TR/WCAG30/)). Bronze·Silver·Gold 적합 수준 구조가 제안되어 있으나, 지침·조항 개수나 확정 시기는 자료마다 달라 확인되지 않았습니다. 법적·계약상 기준은 당분간 WCAG 2.2 로 유지하는 것이 안전합니다.

## 오늘 바로 적용할 것

- 색 대비 점검: 본문·메타 텍스트가 4.5:1 이상인지 디자인 토큰 단위로 확인합니다(가장 흔한 오류).
- 이미지 `alt`, 폼 `label`, 아이콘 전용 버튼·링크의 접근 가능한 이름을 린트 규칙으로 CI 에 넣습니다.
- 자동 검사 통과를 끝으로 보지 말고, 핵심 흐름은 키보드와 스크린리더로 직접 확인합니다.
- CrUX 에서 자기 사이트의 LCP 75퍼센타일을 우선 확인합니다.
- WCAG 3.0 은 모니터링만 하고 대응 작업은 2.2 기준으로 진행합니다.
