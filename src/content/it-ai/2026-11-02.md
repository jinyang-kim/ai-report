## 언어·컴파일러: TypeScript 이행 전략

[pkgpulse](https://www.pkgpulse.com/guides/typescript-6-rc-new-features-go-rewrite-ts7-2026)에 따르면 TypeScript 6.0 RC는 2026년 3월 6일, 최종은 3월 23일에 나왔고 JavaScript 기반의 마지막 릴리스다. 최종판에서는 strict 모드 예약어 9개가 추가되고 `--noImplicitUseStrict`, `--suppressImplicitAnyIndexErrors`가 제거됐다. Go 네이티브 7.0은 타입 검사가 약 10배 빠를 것으로 기대된다고 하나, 이 페이지는 3월 시점 자료라 7.0의 출시일은 싣지 않는다. 7.0의 정확한 출시 시점은 이번 조사에서 확인하지 못했다.

[State of TypeScript 2026](https://devnewsletter.com/p/state-of-typescript-2026/)이 정리한 7.0 관련 변경 예정 사항은 다음과 같다.

- `--strict` 기본값화, ES5 타깃 제거
- AMD·UMD·SystemJS 출력 제거, `node10` 모듈 해석 제거
- 전환기에는 플러그인용 `tsc` 6.x와 빌드용 `tsgo`를 병행하는 하이브리드 운영 권장
- Node 타입 스트리핑 흐름에 맞춰 `--erasableSyntaxOnly` 적용, enum 을 `as const` 객체로 대체

해당 페이지의 수치(예: 약 10배, 5～10배)는 표기가 일관되지 않고 Microsoft 초기 벤치마크 기반이므로 참고용으로만 본다.

## 정리

> 모델은 한 달 내내 벤더별로 분산 출시되고, 개발 도구는 네이티브 컴파일러로 옮겨가는 전환기다.

실무 관점에서는 모델 교체 비용을 줄이도록 게이트웨이 계층을 두고, TypeScript 프로젝트는 6.0 deprecation 경고부터 해소해 두는 것이 안전하다.
