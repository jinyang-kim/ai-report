- oxlint 는 팀 자체 벤치마크 기준으로 [대형 저장소에서 ESLint + typescript-eslint 대비 최대 18배 빠르다](https://voidzero.dev/posts/whats-new-jul-2026). 독립 검증된 수치는 아니므로 자사 저장소에서 직접 재 보는 편이 안전하다.

## 언어·컴파일러: TypeScript 6 → 7 전환

TypeScript 6.0 은 [기존 JavaScript 기반 컴파일러의 마지막 릴리스이자 deprecation 을 드러내는 과도기 버전](https://devnewsletter.com/p/state-of-typescript-2026/)으로 소개된다. TypeScript 7.0 은 Go 기반 네이티브 컴파일러(Project Corsa)를 싣는다. 위 VoidZero 글이 TypeScript 7.0.2 를 전제로 한 tsgolint 버전 체계를 언급하므로, 7.x 가 이미 실사용 단계에 들어갔음을 짐작할 수 있다.

[State of TypeScript 2026](https://devnewsletter.com/p/state-of-typescript-2026/) 이 정리한 주요 내용은 다음과 같다. 이 글은 7.0 출시 전 전망 성격이므로 최종 릴리스 노트와 다를 수 있다.

- 성능: 초기 벤치마크에서 VS Code 코드베이스 77.8초 → 7.5초, Playwright 11.1초 → 1.1초. 로드맵은 컴파일 5～10배, 에디터 시작 약 8배, 메모리 약 50% 절감을 제시한다.
- 예상 breaking change: `--strict` 기본 활성, `--target ES5` 제거, AMD·UMD·SystemJS 출력 제거, 클래식 `node`/`node10` 모듈 해석 제거, `baseUrl` 제거.
- 마이그레이션 제안: `--deprecation` 으로 사용 중단 기능을 먼저 찾고, CI 에서 `@typescript/native-preview` 를 시험하며, 서드파티 도구의 Corsa API 호환성을 점검한다. 플러그인용 `tsc` 6.x 와 빌드용 `tsgo` 7.0 을 섞는 하이브리드 구성도 권한다.

**실무 시사점**: 린터·번들러·컴파일러가 모두 Rust/Go 네이티브로 옮겨가면서 CI 시간이 줄어드는 대신, 컴파일러 프로그래매틱 API 에 의존하는 도구(커스텀 린트 규칙, 코드 생성기)는 호환성 점검이 필요하다.
