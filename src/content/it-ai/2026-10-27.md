## 언어·컴파일러 — TypeScript 7

[The Dev Newsletter](https://devnewsletter.com/p/state-of-typescript-2026/)(1월 15일 자)는 TypeScript 6.0 을 기존 JS 기반 컴파일러의 마지막 릴리스로, 7.0 을 Go 로 포팅한 네이티브 컴파일러로 소개했습니다. 당시 초기 벤치마크 수치는 다음과 같습니다.

- 빌드 약 10배 빠름: VS Code 코드베이스 77.8초 → 7.5초, Playwright 11.1초 → 1.1초
- 메모리 사용 약 50% 감소, 에디터 시작 약 8배 빠름
- 예고된 호환성 변경: `--strict` 기본 켜짐, `--target ES5`·AMD/UMD/SystemJS·`baseUrl` 제거

이후 [Reactiflux 7월 팟캐스트 전사](https://www.reactiflux.com/transcripts/tmir-2026-07)는 TypeScript 7 이 정식 공개되었다고 전하면서, 프로그래밍 API 가 사실상 존재하지 않는 점을 한계로 지적합니다. 위 뉴스레터가 권한 **하이브리드 운용**(플러그인이 필요한 곳은 `tsc` 6.x, 빌드는 `tsgo` 7.0)이 당분간 현실적인 선택입니다.

## 빌드 도구·린트 — 네이티브화의 확산

[VoidZero 7월 리캡](https://voidzero.dev/posts/whats-new-jul-2026)의 주요 내용입니다.

- **Oxc**: 타입 인식 린트가 7월 22일 안정화되었습니다. 대형 저장소(VS Code)에서 ESLint + typescript-eslint 대비 최대 18배 빠르고, typescript-eslint 규칙 61개 중 59개를 구현했습니다. `tsgolint` 버전은 TypeScript 7 을 따라갑니다.
- **Rolldown**: 큰 빌드의 최대 메모리 사용량이 약 21% 줄었습니다.
- **Vite**: Vite 8 다운로드가 출시 몇 달 만에 Vite 6·7 의 합계를 넘었고, 주간 다운로드는 1억 5천만 건 이상입니다.
- **Vitest**: 5.0.0-beta.7 에서 속도 개선과 Temporal 객체 모킹을 지원합니다.
- ViteConf 는 10월 15일 온라인 무료로 열렸습니다(행사 내용은 이번에 확인하지 못했습니다).

> 컴파일러·린터·번들러가 모두 네이티브로 옮겨 가면서, 이제 병목은 도구 속도가 아니라 플러그인 API 호환성입니다.

## 실무 체크리스트

1. CI 에서 TypeScript 7 로 `tsgo` 빌드를 병행 실행해 속도 이득과 오류 차이를 먼저 측정하세요.
2. `baseUrl`, ES5 타깃, 비 ESM 모듈 출력을 쓰는 프로젝트는 설정 마이그레이션이 필요합니다.
3. ESLint 의 타입 인식 규칙이 CI 시간의 큰 비중이라면 Oxc 로의 단계적 전환을 검토할 만합니다.
4. 신규 AI 모델은 가격·벤치마크를 공식 문서에서 직접 확인한 뒤 도입하세요. 이번 조사에서는 해당 수치를 확인하지 못했습니다.
