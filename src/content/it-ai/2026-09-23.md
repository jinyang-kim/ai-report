## Next.js `next/og` 원격 코드 실행 취약점 — CVSS 9.5, 즉시 패치 필요

Vercel이 9월 22일 Next.js에 **out-of-band(정기 릴리스 사이) 보안 패치**를 냈습니다. 문제는 이미지를
동적으로 생성하는 `next/og` 의 Node.js `ImageResponse` 구현에 있으며, 업스트림 SVG 렌더러 **Satori**의
이스케이프 결함(별도 권고 [GHSA-wx4j-mvgx-mqwp](https://github.com/vercel/satori/security/advisories/GHSA-wx4j-mvgx-mqwp))이
원인입니다. 공격자가 통제하는 값이 SVG 콘텐츠·속성·스타일에 그대로 들어가는 경우 원격 코드 실행으로
이어질 수 있습니다
([Next.js 보안 업데이트 블로그](https://nextjs.org/blog/nextjs-security-update-september-22-2026)).

해당 취약점은 [GHSA-vcvr-r3jv-pc5j](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j)로
추적되며 **CVE-2026-94545, CVSSv4 9.5(Critical)** 등급입니다. 영향 범위는 Next.js **16.2.0～16.3.5**이고
패치판은 **16.3.6**입니다. 15.x 계열은 이 RCE 자체의 영향을 받지 않지만, 관련 강화 조치가 담긴
**15.5.26**이 함께 나왔습니다. **Edge `ImageResponse`** 구현은 영향이 없어, Node.js 런타임에서
`next/og` 를 쓰는 애플리케이션만 확인하면 됩니다
([GHSA-vcvr-r3jv-pc5j](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j)).

```bash
npm install next@16.3.6   # 16.3 계열
npm install next@15.5.26  # 15.5 계열 (강화 목적)
```

> A critical security issue has been identified in an upstream dependency.

### 실무 영향

- `next/og`(Node.js `ImageResponse`)를 OG 이미지·소셜 카드 생성 등에 쓰면서 사용자 입력을 SVG 텍스트·
  속성·스타일에 넣는 프로젝트는 오늘 중 16.3.6(또는 15.5.26)으로 업그레이드해야 합니다 — CVSS 9.5는
  네트워크로 낮은 복잡도의 공격이 가능하다는 뜻입니다.
- Edge 런타임의 `ImageResponse` 만 쓰거나 사용자 입력을 SVG 생성에 섞지 않는다면 이번 이슈의 직접
  대상은 아니지만, 의존성 업그레이드 자체는 미루지 않는 편이 안전합니다.

## GitHub Copilot, 사흘 새 프론티어 모델 4종 추가 — Grok 4.7·GPT-6 Sol·Luna·Claude Opus 5.5

GitHub Copilot의 모델 선택지가 이번 주 들어 빠르게 늘었습니다. 9월 21일 xAI의 **Grok 4.7**이 먼저
합류했고, "에이전트 코딩과 복잡한 다단계 워크플로용"으로 소개되며 Pro·Pro+·Max·Business·Enterprise
전 플랜에 순차 롤아웃 중입니다
([GitHub Changelog](https://github.blog/changelog/2026-09-21-grok-4-7-is-now-available-in-github-copilot/)).

바로 다음 날인 9월 22일에는 OpenAI **GPT-6 Sol**·**GPT-6 Luna**와 Anthropic **Claude Opus 5.5**가
동시에 추가됐습니다. GPT-6 Sol은 "신중한 다단계 검증이 필요한 개발 작업에 적합한 균형형 모델"(Pro+·
Max·Business·Enterprise), GPT-6 Luna는 "GPT-6 계열 중 가장 저비용인 경량·고속 모델"(Pro 이상 전 플랜)로
포지셔닝됐습니다
([GitHub Changelog](https://github.blog/changelog/2026-09-22-openais-gpt-6-sol-and-gpt-6-luna-now-available/)).

Claude Opus 5.5는 "에이전트 코딩·장기 실행 에이전트 작업·지식 노동"용으로 소개됐고, GitHub은 초기
테스트에서 "Opus 5.5가 Opus 5와 비슷한 수준으로 과제를 해결하면서도 단계 수와 토큰을 훨씬 적게
썼다"고 밝혔습니다. 출력에는 의미·품질·가독성에 영향을 주지 않고 토큰·비용도 추가되지 않는 텍스트
워터마킹이 내장돼 있습니다
([GitHub Changelog](https://github.blog/changelog/2026-09-22-claude-opus-5-5-is-now-available-in-github-copilot/)).

| 모델 | 합류일 | 포지셔닝 | 플랜 |
| --- | --- | --- | --- |
| Grok 4.7(xAI) | 9월 21일 | 에이전트 코딩·다단계 워크플로 | Pro·Pro+·Max·Business·Enterprise |
| GPT-6 Sol(OpenAI) | 9월 22일 | 균형형, 신중한 다단계 검증 | Pro+·Max·Business·Enterprise |
| GPT-6 Luna(OpenAI) | 9월 22일 | 경량·최저가 | Pro·Pro+·Max·Business·Enterprise |
| Claude Opus 5.5(Anthropic) | 9월 22일 | 장기 에이전트 작업·지식 노동 | Pro+·Max·Business·Enterprise |

네 모델 모두 사용량 기반(provider list pricing) 과금이며, Business·Enterprise 관리자는 모델 정책에서
접근을 개별 통제할 수 있고 새 모델은 기본적으로 활성화됩니다
([GitHub Changelog — Grok 4.7](https://github.blog/changelog/2026-09-21-grok-4-7-is-now-available-in-github-copilot/)).

### 실무 영향

- 같은 주에 4개 벤더의 모델이 몰려 들어온 만큼, 팀 차원에서는 모델 정책으로 우선 허용 모델을 좁혀
  두고 작업 성격별로 점진적으로 넓히는 편이 비용·품질 관리에 유리합니다.
- Claude Opus 5.5처럼 "비슷한 품질을 더 적은 단계·토큰"으로 낸다는 벤더 주장은 자체 워크로드로
  실측하기 전까지는 참고 지표로만 다루는 것이 안전합니다.

## VS Code 1.138 — 로컬 Dev Container에서 에이전트 실행

9월 16일 나온 VS Code 1.138의 핵심은 **Dev Container 에이전트 세션**입니다. 에이전트가 로컬 머신
설정이 아니라 프로젝트에 정의된 Dev Container 안의 툴체인·의존성을 그대로 쓰도록 실행할 수 있게
됐고, 이 기능을 쓰려면 Docker 설치가 전제조건입니다
([VS Code 1.138 릴리스 노트](https://code.visualstudio.com/updates/v1_138)).

Codex 지원도 확장돼 에이전트 호스트에서 GitHub Copilot과 ChatGPT 구독을 전환할 수 있고, ChatGPT
앱과 VS Code 사이에서 세션을 이어갈 수 있게 됐습니다. 세션 관리 쪽에서는 완료된 세션을 "완료"로
표시하거나 보관 후 일정 기간이 지나면 자동 삭제하는 프리뷰 기능이 추가됐고, 주의가 필요한 세션은
태스크바·독 배지로 알려줍니다. 에이전트 세션에서 바로 PR을 만드는 통합 폼, 세션 인지형 음성 모드,
라이트·다크 테마별 채팅 배경 커스터마이즈도 이번 릴리스에 포함됐습니다
([VS Code 1.138 릴리스 노트](https://code.visualstudio.com/updates/v1_138)).

### 실무 영향

- 로컬 환경과 CI 환경의 툴체인이 어긋나 에이전트 실행 결과가 달라지는 문제를 겪었다면, Dev Container
  세션으로 전환해 두 환경을 일치시키는 편이 재현성 확보에 도움이 됩니다.
- ChatGPT·Copilot 구독을 함께 쓰는 팀은 Codex 세션 연동으로 에디터·앱 사이를 오갈 때 컨텍스트가
  끊기지 않는지 먼저 소규모로 검증한 뒤 팀 전체에 적용하는 것을 권합니다.
