## GitHub Copilot — 크레딧 소진 시 '차단' 대신 '요청'으로, 예산 증액 GA

GitHub Copilot 이 9월 16일 **예산 증액 요청** 기능을 정식 출시했습니다. 지금까지는 사용자가 포함된
AI 크레딧을 모두 쓰면 Copilot 기능 접근이 즉시 차단됐지만, 이제는 한계에 도달한 순간 화면에서 바로
추가 예산을 요청할 수 있습니다
([GitHub Changelog](https://github.blog/changelog/2026-09-16-copilot-budget-increase-requests-are-generally-available/)).

요청이 들어오면 관리자는 조직 또는 엔터프라이즈 설정의 'Requests from members' 화면에서 요청 내역을
확인하고, 금액을 조정한 뒤 'Approve and increase' 버튼으로 승인할 수 있습니다. 승인 즉시 사용자의
크레딧이 복구되어 별도 재배포나 세션 재시작 없이 작업을 이어갈 수 있습니다
([GitHub Changelog](https://github.blog/changelog/2026-09-16-copilot-budget-increase-requests-are-generally-available/)).
대상은 Copilot Business·Enterprise 의 사용량 기반 청구 고객입니다.

이번 기능은 갑작스러운 변경이 아닙니다. GitHub 는 8월 28일 이미 9월 1일부터 신규 Business/Enterprise
좌석에 선결제를 요구하고, 기존 고객도 10월 1일부터 같은 방식으로 전환하며, 포함 사용량을 넘기면
추가 결제가 필요하다고 예고한 바 있습니다
([GitHub Changelog](https://github.blog/changelog/2026-08-28-upcoming-changes-to-github-copilot-policies-and-billing/)).
예산 증액 요청 GA 는 이 청구 전환으로 늘어날 수 있는 '크레딧 소진 → 작업 중단' 상황을 완화하기 위한
후속 조치로 읽힙니다.

### 실무 영향

- 팀 단위로 Copilot 을 쓰는 조직이라면, 크레딧 소진으로 작업이 끊기는 대신 요청·승인 절차가 생긴
  만큼 관리자 알림 채널(이메일·Slack 연동 등)을 미리 점검해 승인 지연이 곧 개발 지연으로 이어지지
  않도록 준비할 만합니다.
- 예산 승인 권한을 가진 관리자가 휴가·부재중일 때를 대비해 승인자를 복수로 지정해두는 편이 안전합니다.

## 코드 스캐닝 AI Scan — CodeQL 기본 설정 없이도 PR 에서 동작

코드 스캐닝의 **AI Scan** 이 9월 16일부터 CodeQL default setup 이 켜져 있지 않은 저장소에서도 PR 스캔을
수행하도록 확대됐습니다. 이전에는 AI Scan 이 CodeQL default setup 이 구성된 저장소에서만 실행됐지만,
이제는 이 설정 여부와 무관하게 더 넓은 범위의 저장소에 적용됩니다
([GitHub Changelog](https://github.blog/changelog/2026-09-16-code-scanning-ai-scan-no-longer-requires-codeql-default-setup/)).

별도의 새 설정 단계는 없습니다. 코드 스캐닝과 AI Scan 은 여전히 저장소·조직·엔터프라이즈 단위로
켜져 있어야 하고, 기존 권한 계층 구조도 그대로 적용됩니다. 대상은 github.com 의 조직 소유·개인
저장소이며 GitHub Advanced Security 구독이 필요하고, 현재 퍼블릭 프리뷰 단계로 GitHub Enterprise
Server 는 지원하지 않습니다
([GitHub Changelog](https://github.blog/changelog/2026-09-16-code-scanning-ai-scan-no-longer-requires-codeql-default-setup/)).

> AI Scan for pull requests now runs across more of your eligible repositories, regardless of whether CodeQL default setup is configured.

이번 확대는 지난주 9월 10일 공개된 **AI Scan REST API**(`/orgs/{org}/code-scanning/ai-scan`,
`/repos/{owner}/{repo}/code-scanning/ai-scan`)의 연장선에 있습니다. 당시엔 조직·저장소 단위로 AI Scan
활성화 여부를 API 로 관리할 수 있게 한 것이었다면, 이번엔 그 활성화 범위 자체를 CodeQL 설정에
묶여 있던 제약에서 풀어낸 변화입니다
([GitHub Changelog](https://github.blog/changelog/2026-09-10-ai-scan-for-pull-request-apis-in-public-preview/)).

### 실무 영향

- CodeQL 을 아직 구성하지 않았지만 AI Scan 만 우선 켜보고 싶었던 저장소가 있다면, 이번 변경으로
  별도의 CodeQL default setup 작업 없이 바로 대상에 포함될 수 있으니 Advanced Security 구독 저장소
  목록을 다시 점검할 만합니다.
- 여러 저장소에 걸쳐 AI Scan 적용 범위를 관리해야 하는 보안팀은 9월 10일 공개된 REST API 와 조합하면
  "CodeQL 구성 여부"라는 예외 조건을 신경 쓰지 않고 활성화 정책을 단순화할 수 있습니다.
