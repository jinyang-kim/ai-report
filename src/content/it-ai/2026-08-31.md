## 프론트엔드 — 번들러가 Rust로 합쳐졌다

Vite 8이 **Rolldown**을 단일 번들러로 채택했습니다. 이전까지 Vite는 개발 중 트랜스폼에 esbuild를,
프로덕션 번들링에 Rollup을 쓰는 이원 구조였습니다. 이 분리가 없어졌습니다.

이원 구조가 왜 문제였는지가 핵심입니다. 개발과 프로덕션이 서로 다른 도구를 타면 **"개발에서는
되는데 빌드하면 깨지는"** 클래스의 버그가 구조적으로 발생합니다. 두 도구의 모듈 해석·트리 셰이킹
동작이 완전히 같을 수 없기 때문입니다. 번들러를 하나로 합치면 이 간극 자체가 사라집니다.

Vite 8은 `devtools` 플래그도 추가했습니다. 개발 서버에서 바로 모듈 그래프와 트랜스폼 파이프라인을
실시간으로 들여다볼 수 있습니다. 빌드가 느리거나 번들이 부풀 때 원인을 추적하는 경로가 짧아집니다.

Rolldown은 이후 **1.0으로 번들러 API를 안정화**했습니다. 플러그인을 직접 만드는 팀이라면 이제
API 변경 리스크를 덜고 붙일 수 있다는 뜻입니다.

### 도입 판단

당장 옮길 이유가 있는 팀과 없는 팀이 갈립니다.

- **옮길 만한 경우** — 빌드 시간이 실제 병목이거나, dev/prod 동작 차이로 디버깅에 시간을 쓰고 있다면
- **기다려도 되는 경우** — Rollup 플러그인 생태계에 깊게 의존한다면. 번들러 교체는 플러그인 호환성이
  실질적인 마이그레이션 비용입니다

## 언어·컴파일러 — 탈JavaScript가 패턴이 됐다

개별 뉴스로 보면 흩어져 있지만 묶어 보면 한 방향입니다.

| 도구 | 이동 | 상태 |
| --- | --- | --- |
| Vite 번들러 | JS → **Rust** (Rolldown) | Vite 8에 반영 |
| TypeScript 컴파일러 | TS → **Go** | TypeScript 7.0 베타 |
| React Compiler | JS → **Rust** | 이전 진행 중 |

JavaScript 생태계가 **성능이 중요한 인프라 계층을 체계적으로 JS 밖으로 옮기고 있습니다.**
애플리케이션 코드는 JS/TS로 쓰되, 그것을 처리하는 도구는 네이티브로 간다는 분업입니다.

TypeScript 7.0 베타는 **6.0과 나란히 설치해 돌려볼 수 있습니다.** 정식 버전은 이후 일반 `typescript`
패키지로 배포될 예정입니다. 큰 코드베이스라면 지금 병행 설치로 타입체크 시간만 먼저 재보는 것이
비용 대비 효과가 좋습니다.
