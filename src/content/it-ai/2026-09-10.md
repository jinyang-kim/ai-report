## AI 개발도구 — Cursor, 클라우드 에이전트를 자체 인프라에서 돌리는 self-hosted machines 공개

Cursor 가 9월 2일 **self-hosted machines** 를 공개했습니다. 에이전트의 추론·계획은 Cursor 클라우드에
남지만, 실제 툴 실행 환경만 사용자의 네트워크로 옮겨 코드베이스·빌드 산출물·시크릿이 내부망을
벗어나지 않게 하는 구조입니다([Cursor Changelog](https://cursor.com/changelog/self-hosted-machines)).

배포 방식은 두 가지입니다 — 개인용 노트북·VM 하나를 연결하는 **My Machines**, 그리고 수요에 따라
동적으로 확장되고 유휴 시 시스템을 하이버네이트했다가 재연결 창 안에서 복원하는 팀용 워커 큐
**Team Pools** 입니다([Cursor Changelog](https://cursor.com/changelog/self-hosted-machines)). 실행
인프라로는 AWS Lambda, Coder, Cloudflare, Daytona, Modal, Namespace, Vercel, E2B 를 그대로 쓸 수
있고, Cursor 호스팅 클라우드 에이전트와 동일하게 격리 VM·전체 개발 환경·멀티모델 하니스·플러그인을
지원합니다([Cursor Blog](https://cursor.com/blog/self-hosted-machines)).

셀프호스트 워커는 Linux·Mac 에서 **컴퓨터 사용**도 지원해, 적절한 데스크톱 패키지가 있으면 에이전트가
클릭·타이핑·스크린샷 촬영과 브라우저 조작까지 직접 수행할 수 있습니다
([Cursor Blog](https://cursor.com/blog/self-hosted-machines)).

### 실무 영향

- 소스코드·시크릿을 외부로 내보낼 수 없는 규제 산업이나 엔터프라이즈 보안 정책 아래에서도
  클라우드 에이전트형 워크플로를 도입할 여지가 생겼습니다 — 기존 인프라(AWS Lambda, E2B 등)를
  그대로 재사용할 수 있어 신규 인프라 투자 부담이 줄어듭니다.
- 유휴 시 하이버네이트하는 Team Pools 구조는 상시 가동 비용 없이 온디맨드로 에이전트 인프라를
  운영하려는 팀에 적합한지 검토할 만합니다.

## 개발 도구 — GitHub Copilot, JetBrains용 엔터프라이즈 관리 샌드박스 퍼블릭 프리뷰

GitHub 가 9월 8일 Copilot for JetBrains 에 **엔터프라이즈 관리 샌드박스 정책**을 퍼블릭 프리뷰로
공개했습니다. 관리자가 샌드박스 활성화 여부, 파일시스템·네트워크 접근, 프록시 구성, 개발자 도구
접근, macOS 키체인 권한을 중앙에서 설정할 수 있고, 관리자가 강제한 제한은 개별 사용자 설정을
덮어씁니다. IDE 안에서는 잠긴 컨트롤로 조직이 관리하는 설정임을 표시해줍니다
([GitHub Changelog](https://github.blog/changelog/2026-09-08-enterprise-managed-sandbox-in-copilot-for-jetbrains/)).

같은 릴리스에 여러 기능이 함께 들어갔습니다 — 여러 파일에 걸친 제안을 조율하는 **크로스파일 커서
내비게이션**, 프로젝트 경계를 넘어 파일·폴더를 추가할 수 있는 **글로벌 프로젝트 컨텍스트**, 조직
설정 준수 여부를 확인하는 **엔터프라이즈 정책 진단**, `/ide` 명령을 JetBrains IDE 컨텍스트에 연결하는
**터미널 CLI 통합**(퍼블릭 프리뷰)이 추가됐고, MCP 서버 안정성·OAuth 세션 유지·채팅 응답성 개선도
반영됐습니다([GitHub Changelog](https://github.blog/changelog/2026-09-08-enterprise-managed-sandbox-in-copilot-for-jetbrains/)).

### 실무 영향

- JetBrains 를 표준 IDE 로 쓰는 엔터프라이즈 보안팀은 샌드박스 정책을 통해 네트워크·파일시스템
  접근 범위를 조직 표준에 맞춰 강제할 수 있습니다 — 지금까지는 개인 설정에 의존했던 부분입니다.
- 여러 프로젝트를 오가며 작업하는 개발자는 글로벌 프로젝트 컨텍스트로 컨텍스트 전환 비용을
  줄일 수 있는지 시범 사용해볼 만합니다.

## 런타임 — Bun 1.4.2, 1.4.1 회귀 두 건 포함 7개 이슈 수정

Bun 이 9월 5일 **1.4.2** 를 릴리스해 1.4.1 에서 발생한 회귀 두 건을 포함한 이슈 7개를 고쳤습니다.
첫째는 `bun build` 가 Elysia 를 임포트하는 코드에서 중첩 변수 이름을 같은 블록의 `let` 과 충돌하게
재명명해 `SyntaxError` 로 로드 실패를 일으킨 버그, 둘째는 `store.exit()` 이나 중첩 `store.run()` 안에서
만든 타이머·`setImmediate`·대기 중 프로미스가 외부 스토어 값을 필요 이상으로 오래 살아있게 만든
`AsyncLocalStorage` 메모리 누수입니다([Bun Blog](https://bun.com/blog/bun-v1.4.2)).

그 외에도 `node:worker_threads` 의 `'online'` 이벤트 순서를 Node.js 와 맞춰 `@discordjs/ws` 같은
패키지의 행 현상을 해결했고, `Bun.Image` 가 4채널 CMYK·YCCK JPEG 를 디코드해 RGB 로 변환할 수 있게
됐습니다. JavaScriptCore 에는 `Intl`·TypedArray 수정과 `Proxy` 크래시 방지를 포함한 WebKit 커밋
약 350개가 반영됐고, musl(Alpine) 환경의 GC 스레드 크래시·행 문제, 장시간 실행 프로세스에서
JIT 최적화 코드의 캐시된 프로퍼티 조회로 인한 드문 크래시도 함께 수정됐습니다
([Bun Blog](https://bun.com/blog/bun-v1.4.2), [GitHub Releases](https://github.com/oven-sh/bun/releases/tag/bun-v1.4.2)).

### 실무 영향

- Elysia 로 빌드하거나 `AsyncLocalStorage` 로 요청 컨텍스트를 추적하는 팀은 1.4.1 사용 중이었다면
  즉시 1.4.2 로 업그레이드해야 합니다 — 두 문제 모두 프로덕션에서 발견하기 어려운 종류의 회귀입니다.
- Alpine(musl) 배포 환경에서 장시간 실행 중 GC 관련 크래시를 겪었다면 이번 패치로 해소되는지
  확인할 가치가 있습니다.
