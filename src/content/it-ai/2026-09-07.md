## AI 모델 — Claude Fable 5.1·Mythos 5.1, 캐시 75% 인하와 함께 마이그레이션 필수 항목 3가지

Anthropic 이 9월 1일 **Claude Fable 5.1** 과 **Claude Mythos 5.1** 을 공개했습니다. 둘은 같은 기반
모델에 안전장치 수준만 다른 관계로, Fable 5.1 은 승인 절차 없이 바로 쓸 수 있는 일반 버전이고
Mythos 5.1 은 Project Glasswing 을 통해 승인된 사이버보안·생명과학 전문 고객에게만 제한 없이
제공됩니다([Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-1)). 가격은 입력 100만
토큰당 10달러·출력 50달러로 Fable 5 와 동일하지만, **프롬프트 캐시 읽기 비용만 0.25달러로 75%
인하**됐습니다. 벤치마크는 Terminal-Bench-Science 0.1 에서 Fable 5 의 24.7%→ **52.6%** 로,
Terminal-Bench 4.0 에서는 Fable 55.8%·Mythos 60.9% 를 기록했습니다
([MarkTechPost](https://www.marktechpost.com/2026/09/01/anthropic-releases-claude-fable-5-1-and-claude-mythos-5-1-52-6-on-terminal-bench-science-and-75-cheaper-cache-reads/)).

마이그레이션 가이드는 하위호환이 깨지는 지점 세 가지를 명시합니다. 첫째, `tool_choice` 를
`{type: "any"}` 나 `{type: "tool", name: "..."}` 로 강제 지정하면 400 에러가 반환됩니다 — 대신
`tool_choice: "auto"` 를 두고 `strict: true` 로 스키마를 강제하는 방식으로 바꿔야 합니다. 둘째,
Fable 5.1 은 Opus 5·Fable 5·Mythos 5 등 이전 모델이 만든 사고(thinking) 블록을 읽을 수 있지만,
역으로 이전 모델은 Fable 5.1 의 사고 블록을 읽지 못합니다. 셋째, 앞선 턴을 편집하면 그 시점 이후의
사고 블록이 무효화됩니다
([Claude Platform Docs](https://platform.claude.com/docs/en/models/fable-5-1/migration-guide)).

### 실무 영향

- `tool_choice: "any"`/`"tool"` 로 도구 호출을 강제하던 코드는 400 에러를 마주치기 전에 `auto` +
  `strict: true` 조합으로 먼저 바꿔야 합니다.
- 멀티턴 에이전트 루프에서 여러 모델을 섞어 쓰거나 과거 턴을 재작성하는 구조라면, 사고 블록
  하위호환 규칙 때문에 이번 마이그레이션에서 캐시 히트율이 예상보다 떨어질 수 있어 사전 점검이
  필요합니다.

## AI 모델 — Google Gemini 3.8 Flash, 6주 사이 세 번째 Flash 출시

Google 이 9월 2일 **Gemini 3.8 Flash** 를 출시했습니다. 6주 만에 나온 세 번째 Flash 라인업
갱신으로, 보안 업무 전용으로 잠금 처리된 파생 모델 **3.8 Flash Cyber** 도 함께 공개됐습니다
([The Register](https://www.theregister.com/ai-and-ml/2026/09/02/with-gemini-38-flash-google-reminds-everyone-its-still-in-the-race/5294049)).
가격은 입력 100만 토큰당 0.75달러·출력 3.75달러로 3.7 Flash 와 동일한 도입가이며, 이 가격은
2027년 1월 1일부터 두 배로 오릅니다. Artificial Analysis Intelligence Index 기준 3.7 Flash 의 56점에서
**59점**으로 올라 "동급에서 가장 저렴한 모델"이라는 평가를 받았습니다. 다만 Claude Opus 5 의
63점에는 못 미치고, Google 스스로도 3.8 Flash 는 새 기반 모델이 아니라 3.7 Flash 위에서 더 많은
사고 토큰을 태워 성능을 끌어올린 것이라며 효율 우선 워크로드에는 3.7 Flash 를 계속 권장했습니다
([9to5Google](https://9to5google.com/2026/09/02/gemini-3-8-flash-launch/)).

Cyber 변형은 Fairwind 프로그램을 통해 정부·핵심 인프라 기관·소프트웨어 유지관리자에게만 제공되며,
취약점 탐지·대응에 특화된 학습을 거쳤습니다.

### 실무 영향

- 태스크당 비용은 3.8 Flash 가 낮지만 토큰 소모량 자체가 늘 수 있어, 실제 비용 절감 폭은 워크로드별로
  다시 측정해야 합니다.
- 도입가는 2027년 초 두 배로 오르므로, 장기 계약이나 대량 트래픽 전환을 검토 중이라면 가격 인상
  시점을 일정에 반영해야 합니다.

## 언어·컴파일러 — TypeScript 7.1 일정 확정, Angular·Vue·ESLint 발목 잡던 API 공백을 메운다

TypeScript 7.0(Go 네이티브 포트)이 7월 정식 출시됐지만, 내부 **Programmatic Compiler API**
(`ts.createProgram`, `ts.transform`, `ts.factory` 등)를 노출하지 않아 Angular·Vue·ESLint 같은 AST를
직접 다루는 툴체인은 업그레이드가 막혀 있었습니다. 프레임워크 유지관리자들은 대응으로 TS 7.0 을
피어 의존성에서 명시적으로 제외했습니다
([DEV Community](https://dev.to/the-modern-web/why-angular-vue-and-eslint-cant-upgrade-to-typescript-70-yet-and-why-ts-71-changes-441g)).

Microsoft 가 공개한 **TypeScript 7.1 반복 계획**에 따르면 베타 준비는 10월 2일, 베타 출시는
**10월 6일**, RC 는 11월 10일, 정식 출시는 **11월 24일**입니다. 핵심은 Content Mapper API·Emit
API·Language Service API 등 프로그래매틱 인터페이스 안정화로, AST 파서와 트랜스포머 팩토리
함수를 외부 도구에 공개해 프레임워크가 `tsgo` 의 네이티브 속도를 그대로 쓰면서 커스텀 변환도
유지할 수 있게 합니다. 이 밖에 import attributes 의 `type` 한정자 지원, Node 26 Package Maps 조사,
ES2026 라이브러리 타깃, `Promise.allKeyed`/`Promise.allSettledKeyed` 추가도 예정돼 있습니다
([GitHub Issue #63703](https://github.com/microsoft/TypeScript/issues/63703)).

> "언어 릴리스는 컴파일러만의 사건이 아니라 생태계 전체의 사건이다 — 프레임워크·린터·파서·플러그인·
> 에디터 툴링이 모두 변화를 흡수해야 팀들이 이를 일상적인 업그레이드로 받아들일 수 있다."

### 실무 영향

- Angular·Vue·ESLint 등 AST 를 직접 다루는 툴체인을 쓰는 프로젝트는 TypeScript 6.0.3 유지가
  현재로선 안전하며, 11월 24일 7.1 정식 출시와 각 프레임워크의 후속 지원 공지를 함께 확인한 뒤
  전환하는 편이 낫습니다.
- 순수 타입 체크·빌드 속도만 필요한 프로젝트(AST 훅 없는 경우)는 7.0 의 10배 가까운 속도 이득을
  이미 누릴 수 있어, 툴체인 의존성 여부로 전환 시점을 나눠 판단해야 합니다.
