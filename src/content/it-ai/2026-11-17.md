## 이번 호의 성격

오늘 조사에서는 11월 중순 신규 AI 모델 출시를 공식 출처로 확인하지 못했다. 집계 사이트의 모델 출시 정보는 서로 충돌하고 1차 출처가 없어 싣지 않는다. 대신 공식 블로그와 기술 매체로 확인된 언어·런타임·도구의 구조적 변화를 정리한다.

## 언어·컴파일러: TypeScript 6.0 → 7.0

TypeScript 6.0은 2026년 3월 23일 공개됐고, 팀은 이것이 "현재 JavaScript 코드베이스 기반의 마지막 릴리스"가 될 것이라고 밝혔다. 7.0은 Go로 작성한 새 컴파일러·언어 서비스를 쓰며 병렬 타입 체크를 지원한다. [Announcing TypeScript 6.0](https://devblogs.microsoft.com/typescript/announcing-typescript-6-0/)

6.0의 변경 대부분은 7.0 이행 준비다. [Announcing TypeScript 6.0](https://devblogs.microsoft.com/typescript/announcing-typescript-6-0/)

| 항목 | 6.0의 변화 |
| --- | --- |
| `strict` | 기본값 켜짐 |
| `module` / `target` | `esnext` / 현재 연도 ES 버전(현재 es2025) |
| `types` | 기본값 `[]` — `"node"` 등을 명시해야 함 |
| 폐기 | `target: es5`, `moduleResolution node`, AMD·UMD·SystemJS, `baseUrl`, `outFile` 등 |
| 신규 | `#/` 서브패스 임포트, `--stableTypeOrdering`, Temporal 타입, `RegExp.escape` |

폐기 옵션은 `"ignoreDeprecations": "6.0"`으로 임시로 숨길 수 있지만 7.0에서 제거된다. 같은 글은 7.0이 완성에 가깝다고 설명한다. 한 개발 도구 정리 글은 7.0 소식을 7월 8일자로 전하며 언어 서비스가 네이티브 바이너리로 바뀌었다고 적었다. [Developer tools news](https://builder.aws.com/content/3Ga4Y4JeFLYQRcIvNUbyRCgm8o1/developer-tools-news-today-latest-updates-and-releases)

**실무 포인트**: 지금 6.0에서 `tsconfig`의 폐기 옵션을 정리하고 `types` 명시 여부를 점검해 두면 7.0 전환 비용이 줄어든다.

## 런타임: Node.js 26 LTS

한 기술 매체에 따르면 Node.js 26은 10월 28일 LTS가 되었고 Node 24 LTS는 2027년 4월까지 지원된다. [Node.js 26 LTS](https://byteiota.com/nodejs-26-lts-october-28-temporal-typescript-what-breaks/)

- **Temporal**: 플래그 없이 전역으로 쓸 수 있다. 같은 글은 `Date`보다 연산 비용이 약 19배 높다고 지적해 스케줄링·타임존 처리에만 쓰기를 권한다.
- **TypeScript 직접 실행**: `node app.ts`가 안정화됐다. 타입 주석만 제거하고 컴파일하지 않으므로 enum, 런타임 값이 있는 namespace, 생성자 파라미터 프로퍼티 등은 동작하지 않거나 달라질 수 있다. `--experimental-transform-types`는 제거됐다.
- **브레이킹 체인지**: `http.Server.prototype.writeHeader()` 제거, 레거시 `_stream_*` 모듈 6개 제거, 네이티브 애드온 재빌드 필요(ABI 147).
- **릴리스 정책**: Node 26이 짝수/홀수 방식의 마지막이다. Node 27부터 연 1회 메이저 릴리스, 모든 릴리스가 LTS, 버전은 연도에 맞춰진다.

> Node 26은 "TypeScript를 그냥 실행"할 수 있게 된 첫 LTS이지만, 컴파일이 아니라 타입 제거일 뿐이라는 점이 전환의 함정이다.

## 개발 도구: 에이전트 중심 재편

7월 시점 정리 글 기준으로 도구 쪽 변화는 다음과 같다. [Developer tools news](https://builder.aws.com/content/3Ga4Y4JeFLYQRcIvNUbyRCgm8o1/developer-tools-news-today-latest-updates-and-releases)

- **VS Code 1.129**(7월 15일): 에이전트 세션을 별도 호스트 프로세스에서 실행해, 에이전트가 죽어도 에디터는 유지된다. 에이전트 브라우저 도구는 정식 출시(GA)됐다.
- **Visual Studio 2026 7월 업데이트**: MCP 서버 신뢰 검증이 기본 켜짐, Copilot 사용량 추적이 사용량 기반 과금을 반영한다.
- **GitHub Copilot**: 첫 오픈 웨이트 모델로 Kimi K2.7 Code가 모델 선택기에 추가됐고, GitHub Code Quality는 7월 20일부터 유료(활성 커미터당 월 $10), GitHub Models는 7월 30일 종료됐다.
- **Google Antigravity 2.0**과 서브에이전트용 CLI, Chrome 149의 WebMCP 오리진 트라이얼이 소개됐다.

흐름을 요약하면 에이전트의 격리·권한(MCP 신뢰)·과금이 기능 경쟁만큼 중요한 차별 요소가 되고 있다. 위 도구 정보는 7월 기준이라 현재 버전은 각 공식 릴리스 노트로 다시 확인해야 한다.

## 이번 주 체크리스트

1. 프로젝트의 `tsconfig`에서 6.0 폐기 옵션과 `types` 설정을 점검한다.
2. CI 매트릭스에 Node 26을 추가하고, 네이티브 애드온 재빌드와 `_stream_*` 사용 여부를 확인한다.
3. `node app.ts`를 쓸 경우 enum·namespace 등 타입 제거로 처리되지 않는 문법을 린트로 막는다.
4. 에이전트 도구는 MCP 서버 신뢰 정책과 사용량 과금 정책을 팀 차원에서 정리한다.
