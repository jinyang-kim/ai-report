## 언어·컴파일러: TypeScript 7.0 이후의 현실

TypeScript 7.0은 Go로 포팅된 네이티브 컴파일러의 첫 안정판이다. 패키지 이름은 그대로 `typescript`이고 새 `tsc` 실행 파일이 제공된다. [InfoQ](https://infoq.com/news/2026/08/typescript-7-released/)에 따르면 전체 빌드는 통상 8～12배 빨라졌다. VS Code 코드베이스는 125.7초에서 10.6초(11.9배)로 줄었고, 메모리 사용량은 약 18% 감소했다. Slack은 CI 타입 검사가 약 7.5분에서 1.25분으로 줄었다고 보고했다.

| 항목 | 내용 |
| --- | --- |
| 안정 프로그래밍 API | 7.0에는 없음, 7.1 예정 |
| 영향받는 도구 | typescript-eslint, Vue, Svelte, Astro, MDX, Angular 도구, webpack 로더 |
| 병행 사용 | `@typescript/typescript6`(`tsc6`)로 6.0 병행 가능 |
| 기본값 변경 | `strict`·`esnext`가 기본값, 6.0 deprecation은 하드 에러 |

실무 시사점: 팀은 먼저 6.0으로 올려 deprecation을 정리한 뒤 7.0으로 넘어가는 것이 권장된다. [InfoQ](https://infoq.com/news/2026/08/typescript-7-released/) 속도 이득은 CI에서 즉시 얻을 수 있지만, 린트·프레임워크 도구는 7.1 전까지 6.x 경로를 유지해야 한다.

## 런타임·표준: Node.js 릴리스 모델 변경

[ecorpit의 정리](https://ecorpit.com/nodejs-one-release-per-year-node-27-lts-upgrade-cadence-2026/)에 따르면 Node.js는 반기 메이저 대신 매년 4월 메이저 1회로 바꾸고, 모든 릴리스를 10월에 LTS로 승격한다. 홀수/짝수 구분은 사라진다. 10월부터 3월까지 6개월 알파 채널이 열리며 라이브러리 작성자와 CI용이다. 이 글은 일정이 확정이 아니라며 Release 저장소의 `schedule.json`을 기준으로 삼으라고 안내한다.

- Node 26: 2026년 4월 릴리스, 10월 LTS 진입, 2029년 4월 EOL
- Node 27: 10월 알파 시작, 2027년 4월 Current, 2027년 10월 LTS, 2030년 4월 EOL
