## Claude Opus 5.5 vs GPT-6 Sol·Luna — 90분 간격 공개

**9월 22일**, Anthropic이 **Claude Opus 5.5**를 공개했습니다. 1백만 토큰당 입력 $4·출력 $20(Opus 5
대비 20% 인하), 캐시 읽기 $0.20(60% 인하)로 가격을 낮추면서 출력 속도는 30% 이상 빨라졌고,
Terminal-Bench 4.0 66.4%(Opus 5: 52.3%)·OSWorld 2.0 81.8%(Opus 5: 74.0%) 등 에이전틱 코딩·컴퓨터
사용 벤치마크가 크게 올랐습니다. AWS·Google Cloud·Microsoft Azure·Claude Platform에서 즉시
제공됐습니다([Anthropic](https://www.anthropic.com/claude-opus-5-5)).

**그로부터 약 90분 뒤** OpenAI가 **GPT-6 Sol·GPT-6 Luna**를 발표했습니다. GPT-6 Astra 공개 19일
만에 나온 하위 라인업으로, Sol은 입력 $2·출력 $10(GPT-5.6 Sol 대비 50% 인하), Luna는 입력
$0.10·출력 $0.50(GPT-5.6 Luna 대비 입력 50%·출력 58.3% 인하)로 책정됐습니다. OpenAI 대변인은
VentureBeat에 이 가격이 "프로모션이 아닌 영구 가격"이라고 확인했습니다
([VentureBeat](https://venturebeat.com/technology/openai-releases-gpt-6-sol-and-luna-models-slashing-api-costs-50-or-more)).

> Anthropic이 Claude Opus 5.5를 공개한 지 약 90분 만에 OpenAI가 GPT-6 Sol·Luna를 발표하며 두 회사의
> 경쟁이 정면으로 부딪혔습니다.

OpenAI는 AutomationBench 1.0.6에서 Sol이 33.2%(작업당 $0.27)를 기록해 Opus 5의 26.9%(작업당
비용은 11배)를 앞섰고, Luna는 DeepSWE 1.1 코딩 벤치마크에서 66.6%를 기록하며 비교 가능한 Opus
구성 대비 작업 비용을 93% 낮췄다고 주장했습니다. Sol은 코드 리뷰·디버깅·데이터 분석 같은 복잡한
반복 작업을, Luna는 요약·추출 같은 고빈도 단순 작업을 겨냥합니다. 두 모델은 ChatGPT Work·Codex,
Plus·Pro·Business·Enterprise·Edu 등급에 당일 배포됐고 Luna는 Free·Go 등급 데스크톱 앱에도
제공됐습니다([TechCrunch](https://techcrunch.com/2026/09/22/openai-launches-gpt-6-sol-and-luna/)).

### 실무 영향

- 코딩 에이전트·CI 파이프라인에 Opus 5나 GPT-5.6 Sol을 쓰고 있다면, 같은 날 나온 두 모델 모두
  가격이 크게 낮아졌으니 벤치마크·비용을 다시 측정해볼 시점입니다.
- Luna·Sol처럼 저가·고빈도 작업 전용 모델이 늘어나는 추세이므로, 워크로드를 작업 난이도별로
  나눠 서로 다른 모델에 라우팅하는 전략이 비용 절감 폭을 키울 수 있습니다.

## GitHub Copilot·VS Code 1.139 — 에이전트가 원격 Dev Container 안에서 직접 빌드

GitHub Copilot이 **9월 21~25일 주간 릴리스**에서 Claude Opus 5.5·GPT-6 Sol·GPT-6 Luna·Grok 4.7 네
신규 모델을 Pro·Pro+·Max·Business·Enterprise 등급별로 추가했습니다. Copilot 앱에는 에이전트의
파일·네트워크·자격 증명 접근을 제한하는 **로컬 샌드박싱**(퍼블릭 프리뷰)과 엔터프라이즈 모니터링용
OpenTelemetry 연동이 들어왔고, JetBrains IDE에는 위험도 낮은 도구 호출을 자동 처리하는 **승인
보조**(퍼블릭 프리뷰)가 추가됐습니다
([GitHub Changelog](https://github.blog/changelog/2026-09-25-github-copilot-weekly-releases-september-21/)).

같은 주 **VS Code 1.139**(9월 23일)는 에이전트가 **SSH·Tunnel·WSL 원격 호스트의 Dev Container**
안에서 직접 실행되도록 지원을 넓혔습니다 — 로컬에 별도 환경을 꾸리지 않고도 프로젝트가 요구하는
도구·의존성 그대로 빌드·테스트할 수 있습니다. 세션 관리도 개선돼 약 645개 세션 기준 초기 로딩이
약 12배, 새로고침이 약 4배 빨라졌고, Compact View·세션 즉석 이름변경·빈 그룹 필터링이 추가됐습니다
([VS Code 1.139](https://code.visualstudio.com/updates/v1_139)).

### 실무 영향

- Copilot을 여러 모델로 나눠 쓰고 있다면 새로 추가된 balance·intelligence 등급을 팀 예산 정책에
  맞춰 재조정할 필요가 있습니다.
- 원격 개발 환경(devcontainer.json)을 이미 운영 중이라면, 에이전트가 로컬 리소스를 소모하지 않고
  같은 컨테이너에서 빌드·테스트하도록 전환해 CI와 에이전트 결과의 재현성을 맞출 수 있습니다.

## Claude Code 2.1.280 — Opus 5.5 기본 전환, Auto Mode 서버사이드 기본화

Claude Code **2.1.280**(9월 22일)이 Claude Opus 5.5를 `claude-opus-5-5`로 추가하며 **Pro·Team
Standard 플랜의 기본 모델**로 전환했습니다(1M 토큰 컨텍스트, 1백만 토큰당 입력 $4·출력 $20, 캐시
읽기 $0.20). 같은 릴리스에서 VS Code 확장에 Status·Sandbox·Claude in Chrome·Export 대화상자와
`/plan` 명령이 추가됐습니다
([Claude Code Changelog](https://code.claude.com/docs/en/changelog)).

Auto Mode도 기본값이 바뀌었습니다. 직접 Anthropic API를 쓰는 세션은 클래식 분류기 과금 없는
**서버사이드 분류기**가 기본이 되어(`CLAUDE_CODE_AUTO_MODE_SERVER=0`으로 옵트아웃 가능) 읽기 전용·
샌드박스 셸 명령을 서버 쪽에서 판단하고, 위험한 `rm` 명령은 2분 대기 후 자동 거부로 바뀌었습니다
([Claude Code Changelog](https://code.claude.com/docs/en/changelog)).

### 실무 영향

- Pro·Team Standard 플랜에서 별도 설정 없이 Sonnet을 기본으로 쓰고 있었다면, 이번 전환으로
  기본 모델이 Opus 5.5로 바뀌어 비용·응답 속도 프로파일이 달라집니다. `/model`이나
  `ANTHROPIC_DEFAULT_MODEL`로 팀 정책에 맞게 재설정할 필요가 있습니다.
- Auto Mode를 쓰는 CI·자동화 스크립트가 있다면 서버사이드 분류기 기본 전환으로 판단 지연이나
  거부 패턴이 달라질 수 있으니, `CLAUDE_CODE_AUTO_MODE_SERVER` 값을 확인해두는 편이 안전합니다.
