## OpenAI, 오늘 Sora Videos API 종료 — 권장 대체 모델은 지정하지 않음

OpenAI가 3월 24일 개발자에게 예고했던 대로, **오늘(9월 24일) Sora Videos API를 API에서 완전히
제거**합니다. 대상은 `sora-2`·`sora-2-pro` 모델 별칭과 날짜가 붙은 모든 스냅샷이며, 종료 이후에는
해당 모델을 호출하는 모든 요청이 실패합니다
([Deprecations | OpenAI API](https://developers.openai.com/api/docs/deprecations)).

공식 Deprecations 페이지의 "권장 대체 모델" 칸은 이번 항목에서 비어 있습니다 — OpenAI는 "2026년
3월 24일, Videos API와 Sora 2 비디오 생성 모델 별칭·스냅샷의 폐기와 9월 24일 API 제거를 개발자에게
통보했다"고만 밝혔을 뿐, 후속 모델을 지정하지 않았습니다
([Deprecations | OpenAI API](https://developers.openai.com/api/docs/deprecations)).

Sora 제품 자체의 웹·앱 경험은 이보다 앞선 **4월 26일**에 이미 종료됐고, 오늘은 API만 남아 있던
마지막 접점이 끊기는 시점입니다. OpenAI 헬프센터는 Sora에서 만든 콘텐츠를
`sora.chatgpt.com/sunset` 에서 지금 바로 내보내라고 안내하며, 종료 뒤 최종 내보내기 기간(제공될
경우)이 지나면 Sora 이용과 관련된 데이터를 영구 삭제한다고 명시합니다
([Sora discontinuation | OpenAI Help Center](https://help.openai.com/en/articles/20001152-what-to-know-about-the-sora-discontinuation)).

### 실무 영향

- Sora API로 영상 생성 파이프라인을 운영 중이라면 오늘부로 해당 엔드포인트 호출이 전부 실패합니다.
  대체 모델을 자체 기준(가격·해상도·라이선스)으로 검증해 둔 상태가 아니라면 서비스 중단 범위부터
  먼저 확인해야 합니다.
- 공식 후속 모델이 없다는 점은 OpenAI 생태계 안에서 텍스트-투-비디오를 계속 쓰려면 타사 모델로
  전환하거나 당분간 해당 기능을 보류해야 함을 뜻합니다 — 벤더 종속 리스크를 재평가할 계기입니다.

## GitHub Copilot 앱, 로컬 세션 샌드박싱 프리뷰 — 파일·네트워크·자격증명 제한

GitHub이 9월 23일 GitHub Copilot 앱에 **로컬 리포지토리·워킹트리 세션용 샌드박싱**을 프리뷰로
공개했습니다. 목적은 의도치 않은 명령이 로컬 머신에 미치는 영향을 줄이는 것이고, 프로젝트 단위로
설정합니다
([GitHub Changelog](https://github.blog/changelog/2026-09-23-local-sandboxing-in-the-github-copilot-app/)).

설정 항목은 세 갈래입니다 — **파일시스템**(추가 읽기/쓰기 폴더, 추가 읽기전용 폴더, 접근 거부
폴더 목록), **네트워크**(아웃바운드 인터넷·로컬 네트워크 접근 제어), **자격증명**(Git 자격증명·
GitHub CLI 인증 관리). 활성 세션에서는 `/sandbox on` 명령으로도 켤 수 있습니다
([GitHub Changelog](https://github.blog/changelog/2026-09-23-local-sandboxing-in-the-github-copilot-app/)).

샌드박싱은 **기본값이 off**이고, 클라우드 샌드박스 세션이나 원격 호스트 세션에는 적용되지 않으며
Copilot CLI 의 샌드박스 설정은 별도입니다. 운영체제가 요청한 정책을 강제할 수 없는 경우 샌드박스
없이 실행하는 대신 **에러로 중단**하도록 설계됐고, Enterprise 관리 설정이 프로젝트 단위 정책보다
더 제한적인 규칙으로 이를 덮어쓸 수 있습니다
([GitHub Changelog](https://github.blog/changelog/2026-09-23-local-sandboxing-in-the-github-copilot-app/)).

### 실무 영향

- 로컬에서 에이전트가 임의 셸 명령을 실행하게 두는 워크플로를 쓰고 있다면, 기본값이 off라는 점을
  주의하고 프로젝트별로 명시적으로 켜야 합니다.
- "정책 강제 실패 시 에러로 중단"이라는 설계는 조용히 무방비 상태로 넘어가는 것을 막는 안전장치이니,
  CI가 아닌 로컬 세션에서 자격증명·네트워크 접근이 민감한 리포지토리부터 우선 적용해볼 만합니다.

## Gemini API Antigravity 하네스 `-09-2026` — 툴 파라미터 표기·파일 편집 방식 변경

Google이 9월 17일 Gemini API의 매니지드 에이전트 하네스를 **`antigravity-preview-09-2026`**으로
갱신하며 기존 `antigravity-preview-05-2026`을 대체·폐기했습니다. 기본 모델은 **Gemini 3.8 Flash**이고,
Interactions API·AI Studio를 통해 무료·유료 티어 프로젝트 모두에 프리뷰로 제공됩니다
([Antigravity agent | Gemini API](https://ai.google.dev/gemini-api/docs/antigravity-agent)).

원격 샌드박스에서 출력 텍스트나 모델 출력 스텝만 읽던 사용자는 에이전트 문자열만 새 버전으로
바꾸면 되지만, 툴을 로컬에서 직접 실행하거나 `function_call` 스텝을 파싱하던 개발자는 대응이
필요합니다 — 내장 툴의 파라미터가 **스네이크케이스에서 파스칼케이스로**, 파일 편집 방식이
**전체 재작성에서 라인 범위 치환으로** 바뀌었습니다
([Release notes | Gemini API](https://ai.google.dev/gemini-api/docs/changelog)).

### 실무 영향

- Antigravity 하네스의 function_call 응답을 직접 파싱하는 통합 코드가 있다면, 파라미터 키 표기와
  파일 편집(diff) 형식이 바뀌었으므로 버전 전환 전에 파싱 로직을 함께 업데이트해야 합니다.
- 원격 샌드박스 기반으로 출력 텍스트만 소비하는 단순 연동이라면 에이전트 문자열 교체만으로 충분해
  마이그레이션 부담이 낮습니다.
