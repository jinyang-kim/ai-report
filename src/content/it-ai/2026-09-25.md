## Next.js, ImageResponse RCE 긴급 패치 — CVSS 9.5 Critical

Next.js가 **9월 22일 out-of-band 보안 업데이트**로 `v16.3.6`(Active LTS)과 `v15.5.26`(Maintenance
LTS)을 배포했습니다. 두 버전 모두 업스트림 의존성(특히 Satori)을 올려 원격 코드 실행으로 이어질 수
있는 문제를 해결했고, 15.5.26 쪽은 RCE 자체의 영향은 받지 않지만 관련 하드닝을 포함합니다
([Next.js Security Update](https://nextjs.org/blog/nextjs-security-update-september-22-2026)).

원인은 `next/og`의 **Node.js `ImageResponse` 구현**입니다. Satori가 생성하는 SVG 출력이 특정
조건에서 제대로 이스케이프되지 않아, 다른 업스트림 의존성의 취약점과 결합하면 원격 코드 실행으로
이어질 수 있습니다. 이 이슈는 `CVE-2026-94545`로 추적되며 **CVSS 9.5(Critical)**, 영향 범위는
`Next.js >=16.2.0 <16.3.6`입니다
([GHSA-vcvr-r3jv-pc5j](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j)).

> Edge 런타임의 `ImageResponse`나 `ImageResponse`에 신뢰할 수 없는 입력을 전달하지 않는 애플리케이션은
> 이번 RCE 의 영향을 받지 않습니다.

Next.js 팀은 "`next` 의존성을 패치해 애플리케이션 보안을 유지하라"고 명시하며 `npm install
next@16.3.6`(16.3 계열) 또는 `npm install next@15.5.26`(15.5 계열, 하드닝만)로 올릴 것을 권고합니다
([Next.js Security Update](https://nextjs.org/blog/nextjs-security-update-september-22-2026)).

### 실무 영향

- `next/og`의 Node.js `ImageResponse`를 쓰면서 사용자 입력(쿼리 파라미터, 폼 값 등)을 이미지 생성에
  반영하는 서비스라면 **오늘 바로 패치**해야 합니다 — CVSS 9.5는 이 리포트가 다뤄온 최근 이슈 중
  가장 높은 축에 속합니다.
- Edge 런타임만 쓰거나 `ImageResponse`에 고정된 정적 콘텐츠만 넘긴다면 우선순위는 낮지만, 15.x
  계열도 하드닝이 포함된 만큼 정기 업데이트 주기에 맞춰 올려두는 편이 안전합니다.

## GitHub Copilot 런타임, AI 에이전트가 TypeScript 43만 줄을 Rust 83만 줄로 재작성

GitHub가 9월 16일 공개하고 9월 23일 갱신한 글에서, Copilot 런타임을 TypeScript/Node.js 기반에서
**Rust 프로덕션 코드 83만 2,378줄(+테스트 46만 8,689줄)**로 전량 재작성한 과정을 공개했습니다.
원래 약 43만 줄이던 TypeScript 코드를 **5월 12일부터 8월 21일까지 약 3.5개월**에 걸쳐 옮겼습니다
([GitHub Blog](https://github.blog/ai-and-ml/generative-ai/migrating-the-github-copilot-runtime-to-rust-using-copilot/)).

Rust로 옮긴 이유는 성능·이식성입니다. 기존 런타임은 시작 속도가 느리고 메모리 오버헤드가 컸으며,
SDK 사용자마다 별도 Node.js 런타임이 필요해 VS Code·Visual Studio·Excel 등 다양한 환경에 내장하기
어려웠습니다. Rust는 "최소한의 의존성·오버헤드, 성능, 확장성, 신뢰성이 우수하고 C ABI를 통한
상호운용이 뛰어나다"는 점이 선택 이유로 제시됐습니다
([GitHub Blog](https://github.blog/ai-and-ml/generative-ai/migrating-the-github-copilot-runtime-to-rust-using-copilot/)).

작업은 **128개 PR·총 135회 릴리스**(하루 평균 1.3회)로 나눠 개별 구성 요소를 원자적으로 교체하는
방식으로 진행됐고, AI 어시스턴트와의 세션에서 이벤트 1,276만 건·AI 어시스턴트 메시지 138만 건이
오갔으며 **프롬프트 캐시 히트율 96.22%**를 기록했습니다. 작업 시간의 대부분(44%)은 코드 탐색에,
23%는 검증에 쓰였습니다
([GitHub Blog](https://github.blog/ai-and-ml/generative-ai/migrating-the-github-copilot-runtime-to-rust-using-copilot/)).

### 실무 영향

- Copilot 런타임의 SDK 표면이나 CLI 내부 동작에 의존하는 통합을 만들어 뒀다면, 인프로세스 호스팅
  확대 등 후속 변경이 이어질 수 있으니 체인지로그를 주시할 필요가 있습니다.
- 단일 개발자가 AI 에이전트 지원으로 수 년 걸릴 대규모 언어 마이그레이션을 몇 달 만에 끝낸 사례로,
  자체 레거시 코드베이스의 언어 전환·리라이트 작업에 에이전트 기반 접근을 검토할 근거 자료로
  참고할 만합니다.

## Anthropic, Claude Opus 5.5 공개 — 비용 40%↓·Terminal-Bench 66.4%

Anthropic이 9월 22일 **Claude Opus 5.5**를 공개했습니다. 가격은 1백만 토큰당 입력 $4·출력 $20으로
Opus 5 대비 20% 인하됐고, 캐시 읽기는 $0.20으로 60% 낮아졌습니다. 속도는 출력 기준 30% 이상
빨라졌습니다
([Introducing Claude Opus 5.5](https://www.anthropic.com/claude-opus-5-5)).

벤치마크는 에이전틱 코딩·컴퓨터 사용 작업에서 뚜렷한 상승을 보입니다 — Terminal-Bench 4.0
**66.4%**(Opus 5: 52.3%), FrontierCode v1.1 **54.4%**(Opus 5: 48.0%), OSWorld 2.0 **81.8%**(Opus 5:
74.0%), GDPval-AA v2.1 **1846 Elo**(Opus 5: 1708)
([Introducing Claude Opus 5.5](https://www.anthropic.com/claude-opus-5-5)).

Claude Opus 5.5는 AWS·Google Cloud·Microsoft Azure·Claude Platform에서 즉시 이용할 수 있습니다
([Introducing Claude Opus 5.5](https://www.anthropic.com/claude-opus-5-5)).

### 실무 영향

- 에이전틱 코딩·터미널 자동화 워크로드를 운영 중이라면 Terminal-Bench·OSWorld 상승폭이 커서,
  기존 Opus 5 기반 파이프라인의 비용·정확도를 재측정해볼 가치가 있습니다.
- 캐시 읽기 가격이 60% 낮아진 점은 긴 시스템 프롬프트·대형 컨텍스트를 반복 재사용하는 워크로드의
  실질 비용을 크게 낮추므로, 프롬프트 캐싱 전략을 다시 설계해볼 만합니다.
