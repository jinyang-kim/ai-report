## GitHub Copilot — 모델 선택 지능화: 비용/품질 3단계 + 실험적 자동 라우팅

GitHub 가 9월 14일 Copilot 자동 모델 선택에 사용자가 비용과 품질의 균형을 직접 고를 수 있는 3단계
설정을 추가했습니다. 빠르고 단순한 작업에 맞춰 비용을 최소화하는 **효율성(efficiency)**, 비용·품질·
지연을 함께 고려해 일상 업무에 적합한 **균형(balance)**, 복잡한 작업을 위해 품질을 우선하는
**지능(intelligence)** 세 단계로 나뉘며, VS Code·Copilot CLI·Copilot 앱에 순차 적용됩니다
([GitHub Changelog](https://github.blog/changelog/2026-09-14-configure-cost-and-quality-in-copilot-auto-model-selection/)).

세 단계 모두 같은 모델 풀에서 프롬프트 단위로 최적 모델을 고릅니다. intelligence 를 선택해도 기존
함수에 문서 주석을 추가하는 것처럼 단순한 요청은 더 가벼운 모델로 처리될 수 있습니다. 유료
구독자는 auto 가 최종적으로 고른 모델 기준 사용량 청구액에서 10% 할인을 받습니다
([GitHub Changelog](https://github.blog/changelog/2026-09-14-configure-cost-and-quality-in-copilot-auto-model-selection/)).

이 흐름은 9월 10일 공개된 실험적 기능 **"Project HydraFusion"**과 맞닿아 있습니다. Copilot CLI 전용
기능으로, 로컬·클라우드·복합(compound) 모델 사이에서 성능·비용·지연을 종합해 워크플로를 자동
라우팅합니다 — 사용자가 모델을 수동으로 고르지 않아도 작업 성격에 맞춰 알아서 전환하는 방식입니다
([GitHub Changelog](https://github.blog/changelog/2026-09-10-github-copilot-weekly-releases-september-7/)).

### 실무 영향

- 팀 단위로 Copilot 사용량 비용을 관리한다면, 반복적이고 단순한 작업이 많은 팀은 efficiency, 복잡한
  리팩터링·설계 작업이 많은 팀은 intelligence 로 기본값을 나눠 예산과 품질을 함께 조정할 수 있습니다.
- HydraFusion 은 아직 실험 단계라 프로덕션 워크플로에 바로 의존하기보다는, 모델 선택 자동화가 CLI
  까지 확장되는 방향성을 참고해 두는 정도가 안전합니다.

## 보안 — npm, 복구 코드 로그인 후 72시간 보안 홀드를 전체 계정으로 확대

npm 이 9월 9일 계정 탈취를 늦추기 위한 보안 조치를 전체 계정으로 넓혔습니다. 지금까지는 다운로드
비중이 큰 "고영향" 계정에만 적용되던 **복구 코드 로그인 후 보안 홀드**가 이제 모든 npm 계정에
적용됩니다
([GitHub Changelog](https://github.blog/changelog/2026-09-09-npm-extends-recovery-code-security-holds-to-all-accounts/)).

복구 코드로 로그인에 성공하면 72시간 동안 게시(publish)와 접근 토큰 발급을 비롯한 보안 민감 작업이
일시 정지됩니다. 로그인 자체나 패키지 열람·설치는 평소대로 가능하고, 홀드는 별도 조치나 지원 요청
없이 72시간 뒤 자동으로 풀립니다. 탈취된 복구 코드로 로그인해 악성 패키지를 게시하는 공격 경로를
차단하려는 목적입니다
([GitHub Changelog](https://github.blog/changelog/2026-09-09-npm-extends-recovery-code-security-holds-to-all-accounts/)).

### 실무 영향

- 2단계 인증 복구 코드를 최근에 써서 로그인한 메인테이너는, 이후 72시간 동안 릴리스 게시가 막힐 수
  있다는 점을 감안해 배포 일정을 미리 조정할 필요가 있습니다.
- CI 에서 npm 토큰을 자동 발급·회전하는 파이프라인이 있다면, 복구 코드 로그인 직후 토큰 발급이
  막히는 시점을 장애로 오인하지 않도록 팀에 미리 공유해 둘 만합니다.

## GitHub Copilot — 앱에 Jira 연동 추가, VS Code 는 에이전트 작업 예약·음성 모드 실험

GitHub 가 9월 10일 자 Copilot 주간 릴리스에서 Copilot 앱에 **Jira 연동**을 추가했습니다. Jira 이슈를
공유 캔버스로 가져와 어떤 이슈를 진행할지 고르면, Copilot 이 그 맥락을 조사·구현·PR 준비 단계까지
그대로 이어받습니다
([GitHub Changelog](https://github.blog/changelog/2026-09-10-github-copilot-weekly-releases-september-7/)).

같은 릴리스에 포함된 **VS Code 1.137** 은 세 가지 기능을 새로 얹었습니다 — 반복 에이전트 작업을
시간·일·주 단위로 예약하는 기능, 음성으로 Copilot 과 상호작용하는 실험적 보이스 모드, 저장소를 열지
않고도 이슈·PR 상세를 띄우는 실험적 에이전트 창입니다. JetBrains 는 엔터프라이즈 관리자가 샌드박스
활성화·파일시스템/네트워크 접근·프록시·macOS 키체인 접근을 정책으로 중앙 관리할 수 있게 됐습니다
([GitHub Changelog](https://github.blog/changelog/2026-09-10-github-copilot-weekly-releases-september-7/)).

### 실무 영향

- Jira 로 이슈를 관리하는 팀은 이슈 트리아지부터 PR 준비까지 컨텍스트 전환 없이 이어가는 흐름을
  시범 적용해볼 만합니다.
- 반복 에이전트 작업 예약 기능은 코드 정리·의존성 업데이트처럼 주기적으로 반복되는 저위험 작업부터
  맡겨보고, 결과를 리뷰하는 루틴을 먼저 만드는 편이 안전합니다.
