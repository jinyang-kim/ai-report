## AI 모델 — Anthropic, Claude Fable 5.1·Mythos 5.1 공개

Anthropic 이 9월 1일 코딩·지식노동용 신형 모델 **Claude Fable 5.1** 과 **Claude Mythos 5.1** 을
공개했습니다. 두 모델은 동일한 기반 모델에 안전장치 수준만 다르게 적용한 형제 모델로, Fable 5.1 은
일반 공개되고 Mythos 5.1 은 사이버보안·생명과학 분야에 특화된 안전장치를 갖춰 신뢰받는 접근
프로그램을 통해서만 제공됩니다([Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-1)).

핵심 벤치마크인 **Terminal-Bench-Science 0.1** 에서 Fable 5.1 은 **52.6%** 를 기록해, 전작 Fable 5 의
24.7%, Opus 5 의 29.0% 를 크게 앞섰습니다. 다양한 벤치마크에서 Fable 5·Opus 5·OpenAI GPT-5.6 Sol 을
능가했다고 Anthropic 은 설명했습니다([MarkTechPost](https://www.marktechpost.com/2026/09/01/anthropic-releases-claude-fable-5-1-and-claude-mythos-5-1-52-6-on-terminal-bench-science-and-75-cheaper-cache-reads/)).

가격 면에서는 캐시 읽기 요금이 1백만 토큰당 **1달러에서 0.25달러로 75% 인하**돼, 일반 워크로드
기준 약 25%, 에이전트 성격이 강한 작업에서는 최대 45% 저렴해졌습니다
([MacRumors](https://www.macrumors.com/2026/09/01/anthropic-claude-fable-5-1/)). 안전장치 측면에서는
Claude Code 사용 중 발생하는 사이버보안 오탐지가 **약 60% 감소**했고, 생성 텍스트에 무형 워터마크가
추가돼 탐지 API 가 사적 미리보기 단계로 제공됩니다. 지식 컷오프는 2026년 6월입니다
([Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-1)).

### 실무 영향

- 캐시 읽기 비용이 큰 폭으로 낮아진 만큼, 긴 컨텍스트를 반복 재사용하는 에이전트형 워크플로는
  비용 재계산을 해볼 만합니다.
- 사이버보안 오탐 감소로 Claude Code 를 CI/보안 스캔 파이프라인에 걸어둔 팀은 알림 피로가
  줄어들 것으로 기대할 수 있습니다.

## 빌드 도구·런타임 — Bun 1.4, Zig에서 Rust로 전면 재작성

JavaScript 런타임 **Bun** 이 8월 20일 배포한 **1.4** 버전에서 코어를 Zig 에서 **Rust 로 전면
재작성**했습니다. Anthropic 의 Claude Code 가 이미 수개월째 이 Rust 포트를 프로덕션에서 써 왔고,
Prisma 도 이를 기반으로 Prisma Compute 를 출시했다고 밝혔습니다([Bun Blog](https://bun.sh/blog/bun-v1.4)).

성능 수치는 다음과 같습니다 — fastify 기준 메모리 사용량이 233MB 에서 120MB 로 **48% 감소**했고,
시작 시간은 Windows 에서 39.0ms → 15.5ms(**2.5배**), Linux 에서 10.9ms → 5.1ms(**2배**) 단축됐습니다.
유휴 상태 CPU 사용량은 5배 줄었고, Claude Code 프로덕션 환경에서 p99 CPU 사용률이 24%에서
10%로 떨어졌습니다([Bun Blog](https://bun.sh/blog/bun-v1.4)).

기능 면에서는 Puppeteer/Playwright 없이 브라우저를 자동화하는 **Bun.WebView**, Sharp 대비 1.38배
빠른 이미지 처리 **Bun.Image**, node-pty 없이 PTY 를 다루는 **Bun.Terminal**, `Bun.markdown`·
`Bun.cron()` 등이 새로 내장됐습니다. `bun install --linker=isolated` 글로벌 가상 스토어는 1,400개
패키지 기준 웜 CI 설치를 최대 7배 빠르게 합니다([Bun Blog](https://bun.sh/blog/bun-v1.4)). 이후
9월 4일 1.4.1, 9월 5일 1.4.2 가 잇따라 배포돼 `Bun.serve()` HTTP/2 지원과 Elysia·
`AsyncLocalStorage` 리그레션 등을 수정했습니다([Bun v1.4.2](https://bun.sh/blog/bun-v1.4.2)).

### 실무 영향

- 네이티브 애드온이나 Zig 내부 API 에 의존하던 도구는 1.4 업그레이드 전에 호환성을 점검할
  필요가 있습니다 — 코어 전체가 재작성됐습니다.
- 이미지 처리·브라우저 자동화용 외부 패키지(Sharp, Puppeteer 등)를 쓰던 Bun 프로젝트는 내장
  API 로 전환해 의존성을 줄일 수 있습니다.

## 표준·API — WebGPU·WGSL, 나란히 Candidate Recommendation Draft로 승격

W3C 의 GPU for the Web 워킹그룹이 **WGSL(WebGPU Shading Language)** 을 8월 31일,
**WebGPU** 본체를 9월 1일 각각 **Candidate Recommendation Draft(CRD)** 로 승격했습니다. 두 표준
모두 Chrome·Edge·Firefox·Safari 전 주요 브라우저에서 이미 지원되고 있어, 최종 권고안을 향한
막바지 단계에 들어섰습니다([W3C](https://www.w3.org/TR/webgpu/)).

CRD 는 이전 Candidate Recommendation 이후 반영된 변경 사항을 통합한 초안으로, 워킹그룹이
다음 Candidate Recommendation Snapshot 에 포함할 계획인 내용을 담습니다. 명세는 최소 두 개
이상의 배포된 브라우저가 최신 GPU 시스템 API 를 사용해 구현을 시연할 것을 요구합니다
([W3C](https://www.w3.org/TR/webgpu/)).

### 실무 영향

- 브라우저 내 GPU 연산·ML 추론에 WebGPU 를 프로덕션 도입하려던 팀은 CRD 단계 진입을
  계기로 폴리필·플래그 의존을 줄이고 안정 API 전환을 검토할 시점입니다.
- WGSL 셰이더 코드를 작성하는 팀은 CRD 반영 변경분이 최종 권고안에 가까워지고 있으므로,
  구버전 초안 기준 문서를 최신화해둘 필요가 있습니다.
