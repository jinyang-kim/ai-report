## GitHub Copilot 런타임, 83만 줄 러스트로 — AI 에이전트가 128개 PR을 직접 썼다

GitHub이 CLI·앱·SDK를 아우르는 Copilot 에이전트 런타임을 TypeScript에서 러스트로 완전히 이전한
과정을 9월 16일 공개했습니다. 대상은 약 43만 줄의 프로덕션 TypeScript였고, 결과물은 83만 2천 줄의
프로덕션 러스트에 46만 9천 줄의 유닛 테스트가 더해졌습니다
([The GitHub Blog](https://github.blog/ai-and-ml/generative-ai/migrating-the-github-copilot-runtime-to-rust-using-copilot/)).

빅뱅 전환 대신 **컴포넌트 단위 원자적 치환**을 택했습니다 — TypeScript 셰임이 러스트 구현을 호출하는
방식으로 조각조각 이전하면서, 다른 개발자의 작업을 멈추지 않고 메인 브랜치를 계속 배포 가능한 상태로
유지했습니다. 5월 12일부터 8월 21일까지 14.5주간 128개의 이전 PR이 병합됐고, 사전 릴리스 100회·
정식 35회 합쳐 총 135회(하루 평균 1.3회)가 나갔습니다. 이 작업은 사실상 Stephen Toub 한 명이 감독했지만,
에이전트가 대부분의 코드를 작성했습니다
([The GitHub Blog](https://github.blog/ai-and-ml/generative-ai/migrating-the-github-copilot-runtime-to-rust-using-copilot/)).

투입 비용은 총 1,363억 토큰·약 12만 달러였고, 이 중 1,306억 토큰이 캐시된 입력이라 프롬프트 캐시
적중률이 96.22%에 달해 비용을 약 90% 낮췄습니다. 세션 로그는 1,276만 건의 이벤트, 3만 1,247개의
사용자 메시지(이 중 사람이 직접 입력한 것은 약 2,600개뿐) 를 남겼습니다 — "에이전트는 코드를 바꾸는
시간보다 증거를 모으는 시간을 훨씬 더 많이 썼다"는 탐색:변경 비율 10:1이 이를 뒷받침합니다
([The GitHub Blog](https://github.blog/ai-and-ml/generative-ai/migrating-the-github-copilot-runtime-to-rust-using-copilot/)).

The Register는 이 작업을 따로 취재해 성능 수치를 재확인했습니다 — 10-클라이언트 에이전트 배치 기준
메모리 사용량이 1,383MB에서 126MB로, 벤치마크 처리량은 초당 7.55에서 120 lifecycle로 15.9배
개선됐습니다. 다만 컴파일이 성공했다고 정확성까지 보장되는 것은 아니어서, 실제로는 수십 건의 회귀가
발생했다가 프로덕션 전에 수정됐습니다 — 모호한 의미(예: `42.0`과 `42`의 구분), 타임존·환경변수 같은
암묵적 동작, 짝을 이뤄야 할 연산의 한쪽만 이전된 경우, 핸들이 인스턴스보다 오래 살아남는 생명주기
불일치가 반복되는 패턴이었습니다
([The Register](https://www.theregister.com/devops/2026/09/18/microsoft-agentically-ports-copilot-runtime-to-rust-for-120k/5297549)).

> Adding, changing, or removing an API method touches the engine's dispatch table but never touches the ABI.

SDK 표면은 프로세스 내부 호출에도 JSON-RPC를 그대로 써서, 6개 언어 SDK에 걸쳐 수백 개의 메서드
바인딩을 중복 구현하지 않으면서도 향후 최적화 여지를 남겼다고 설명합니다. `unsafe` 블록은 158개가
전부 C ABI(32.3%)·Windows API(31.0%)·POSIX/libc(29.1%)·SQLite(4.4%) 같은 외부 경계에만 몰려 있었고,
회귀 중 `unsafe` 코드가 원인인 사례는 없었습니다
([The GitHub Blog](https://github.blog/ai-and-ml/generative-ai/migrating-the-github-copilot-runtime-to-rust-using-copilot/)).

### 실무 영향

- 강타입 컴파일러가 이름 해석·누락 메서드·타입 불일치 같은 오류의 약 84%를 잡아냈다는 점은, 대규모
  AI 주도 이전을 고려하는 팀이라면 러스트처럼 타입 체크가 엄격한 언어를 목적지로 택할 유인이 됩니다.
- 반대로 컴파일 통과를 정확성의 증거로 오인하면 안 됩니다 — 타임존·숫자 표현처럼 소스 언어에 암묵적으로
  깔려 있던 동작은 에이전트가 놓치기 쉬우므로, 이전 후에도 동작 동등성 테스트를 별도로 두어야 합니다.

## Node.js 26.9.0 — FFI 기본 활성화, DTLS·VFS·Web Workers 실험 추가

9월 16일 나온 Node.js 26.9.0은 그동안 실험 단계였던 FFI(외부 함수 인터페이스) 모듈을 **기본으로
활성화**했습니다. 네이티브 라이브러리를 별도 빌드 도구 없이 자바스크립트에서 직접 호출할 수 있는
경로가 표준으로 자리잡았다는 뜻입니다. 같은 릴리스에 실험적 DTLS(Datagram TLS) API가 상호운용
테스트와 함께 추가됐고, 가상 파일시스템(VFS)이 CJS·ESM 모듈 로더에 통합돼 `ZipProvider`로 zip 파일을
마운트하거나 마운트된 파일시스템에서 네이티브 애드온을 로드할 수 있게 됐습니다. Web Workers API 구현도
이번에 들어와 멀티 글로벌 WPT(Web Platform Tests)를 지원합니다
([Node.js 26.9.0 릴리스 노트](https://nodejs.org/en/blog/release/v26.9.0)).

| 기능 | 상태 | 내용 |
| --- | --- | --- |
| FFI 모듈 | 기본 활성화 | 네이티브 라이브러리 직접 호출 |
| DTLS API | 실험적 | 상호운용 테스트·통계 지원 |
| VFS 모듈 로더 통합 | SEMVER-MINOR | CJS/ESM 로더 연동, ZipProvider |
| Web Workers | SEMVER-MINOR | 멀티 글로벌 WPT 지원 |
| `node:bench` | 실험적(`--experimental-bench`) | 벤치마크 CLI·리포터 |

보안 쪽에서는 `Hmac.digest()`가 초기화되지 않은 메모리를 반환하던 문제를 막았고, `X509Certificate`의
상태 보안도 강화됐습니다. 이 외 멀티프라임 RSA JWK 처리, ECDH 키 페어 캐싱, 디렉터리 트리 복사,
재귀적 watch, HTTP/HTTP2 쓰기 데드락 수정 등 광범위한 버그 수정이 포함됐습니다
([Node.js 26.9.0 릴리스 노트](https://nodejs.org/en/blog/release/v26.9.0)).

### 실무 영향

- FFI가 기본 활성화되면서 네이티브 애드온을 N-API 대신 FFI로 새로 작성하는 선택지가 넓어졌습니다 —
  기존 네이티브 모듈을 유지보수하는 팀은 마이그레이션 비용 대비 이점을 검토해볼 만합니다.
- DTLS·`node:bench`는 아직 실험 플래그 뒤에 있으므로 프로덕션 의존은 이르지만, UDP 기반 보안 통신이나
  내장 벤치마크 도구가 필요한 프로젝트라면 지금부터 실험해볼 가치가 있습니다.

## GitHub Copilot auto 모델 선택 — 효율·균형·지능 3단계로 세분화

GitHub Copilot이 9월 14일부터 `auto` 모델 선택에 **효율(efficiency)·균형(balance)·지능(intelligence)**
3단계 설정을 추가했습니다. 세 단계 모두 같은 모델 집합을 쓰지만, 프롬프트마다 비용·품질·응답 속도를
얼마나 우선할지가 달라집니다. 효율은 비용을 낮게 유지하며 빠르고 단순한 작업에, 균형은 비용·품질·
지연을 함께 고려해 일상 업무에, 지능은 품질을 우선해 복잡한 작업에 맞춰져 있습니다. 지능 단계를
택해도 함수에 docstring을 추가하는 것처럼 단순한 작업에는 여전히 작고 효율적인 모델이 선택될 수
있습니다
([GitHub Changelog](https://github.blog/changelog/2026-09-14-configure-cost-and-quality-in-copilot-auto-model-selection/)).

과금은 단계 설정과 무관하게 `auto`가 실제로 고른 모델 기준으로 이뤄지며, 유료 구독자는 `auto` 경유
사용량에 기존 10% 할인을 그대로 적용받습니다. 이번 업데이트는 VS Code·Copilot CLI·GitHub Copilot 앱에
순차 롤아웃 중이며, GitHub은 이를 "선택 과정의 트레이드오프를 더 투명하게 보여주는 방향으로 가는
첫 단계"라고 설명했습니다
([GitHub Changelog](https://github.blog/changelog/2026-09-14-configure-cost-and-quality-in-copilot-auto-model-selection/)).

### 실무 영향

- 팀 단위로 Copilot 비용을 관리해야 한다면, 리뷰·문서화처럼 반복적인 작업에는 효율 단계를, 아키텍처
  설계나 복잡한 리팩터링에는 지능 단계를 프로젝트별로 나눠 지정하는 정책을 세워볼 만합니다.
- 어떤 단계를 고르든 과금은 실제 선택된 모델 기준이므로, "지능 단계 = 항상 비쌈"으로 오해하지 말고
  작업 성격에 맞는 단계를 실험적으로 비교해보는 편이 낫습니다.
