# 설계 스펙: 카테고리 4종 추가 (전자기기·의료·맛집여행·게임)

작성일: 2026-09-01
상태: 확정 (구현 계획 작성 단계로 이행)

## 1. 목표

기존 3개 카테고리(kr-daily·it-ai·global-ui-ux)에 **4개를 추가**해 총 **7개**로 확장한다.
7개 모두 평일 아침 GitHub Actions cron 으로 자동 생성된다.

| 신규 ID | 이름 | short | 범위 |
| --- | --- | --- | --- |
| `electronics` | 전자기기 | 전자 | 한국 가전·모바일·반도체·IT기기 출시·리뷰·업계 |
| `health` | 의료·헬스케어 | 의료 | 한국 의료·바이오·제약·헬스케어·건강 정책 |
| `food-travel` | 맛집·여행 | 맛집 | 한국에서 화제인 맛집·여행지 (인스타·블로그 트렌드 + 검증 정보 균형) |
| `gaming` | 게임 | 게임 | 온라인·모바일·콘솔 게임 출시·업데이트·업계 |

(사용자 결정: 전자기기·의료 분리, 4개 한 번에 추가, 7개 전부 평일 매일, 맛집·여행은 한국 중심 트렌드+검증 균형.)

## 2. 아키텍처 — 카테고리 하드코딩 지점

CLAUDE.md 기준, 카테고리 ID 는 아래에 하드코딩된다. 신규 4개를 **모든 곳에** 등록해야 하며,
하나라도 빠지면 빌드 실패 또는 조용한 스타일 누락으로 이어진다.

| 파일 | 추가할 것 |
| --- | --- |
| `src/lib/categories.ts` | `CATEGORY_IDS` 에 4개 + `CATEGORIES` 에 항목(id/name/short/description/accent/accentDark) |
| `src/content.config.ts` | `collections` 맵에 4개 컬렉션 |
| `src/lib/reports.ts` | `AnyEntry` 유니온에 4개 |
| `src/styles/global.css` | 색 토큰 4세트 × **3개 테마 블록** + `.card--<id>` 규칙 4개 |
| `scripts/publish.py` | `CATEGORIES` 집합에 4개 |
| `scripts/make-og.py` | `CARDS` 딕셔너리에 4개 → 실행해 `public/og/<id>.png` 4장 생성 |
| `.github/prompts/<id>.md` | 신규 4개 (도메인 역할·리서치 + 공유 출력·금지 섹션) |
| `.github/workflows/generate.yml` | schedule cron 4줄 + `case` 매핑 4개 + 검증 case 4개 |
| `src/content/<id>/` | 빈 콘텐츠 폴더 4개(첫 생성 전까지 비어 있음 — 빈 컬렉션 허용 확인 필요) |

**자동 반영(추가 작업 불필요)**: RSS 전체·카테고리별 피드, 홈, 아카이브, 카테고리 목록, sitemap,
네비게이션(Header/Footer), JSON-LD — 전부 `CATEGORY_LIST`/`getAllReports` 를 소비하므로 등록만 하면 붙는다.

## 3. 색 시스템 (핵심 난이도)

각 카테고리는 **3개 테마 블록**(라이트 `:root` / OS다크 / 수동다크)마다 4개 토큰이 필요하다.

| 토큰 | 용도 | 대비 요건 |
| --- | --- | --- |
| `--cat-<id>` | 테두리·좌측 바·불릿 등 장식 | 2.8~4.4:1 (텍스트 배경 금지) |
| `--cat-<id>-solid` | 흰 글자 얹는 배경(takeaway 번호 등) | **≥ 4.7:1 (흰 글자)** |
| `--chip-<id>-bg` / `--chip-<id>-fg` | 카테고리 칩 배경/글자 | fg/bg 대비 **≥ 4.5:1** |
| categories.ts `accent` / `accentDark` | 라이트/다크 accent | 장식용 |

기존 색: kr-daily 주황(#eb6834), it-ai 파랑(#2a78d6), global-ui-ux 초록(#1baf7a).
**신규는 기존과 구분되는 색상(hue)** 을 쓴다 — 제안 계열:

| ID | 계열 | 이유 |
| --- | --- | --- |
| electronics | teal/cyan(청록) | 파랑·초록과 구분되는 시안 계열 |
| health | rose/자홍 | 의료의 관습색(적십자 계열)이자 미사용 hue |
| food-travel | amber/골드 | 따뜻하되 주황(kr-daily)과 구분되는 앰버 |
| gaming | violet/보라 | 게임의 관습색, 미사용 hue |

**정확한 hex 는 구현 계획에서 확정하고, `--cat-*-solid`·chip 대비는 Quality 게이트(pa11y WCAG2AA)
로컬 dry-run 으로 검증**한다(미달 시 조정). 색 토큰은 3블록에 모두 넣어야 하며, 하나만 빠뜨리면
두 다크 경로 중 하나에서만 깨진다.

## 4. cron 스케줄

기존 3개(09:05/09:10/09:15) 뒤에 신규 4개를 5분 간격으로 잇는다. cron 은 UTC.

| 카테고리 | cron(UTC) | KST |
| --- | --- | --- |
| electronics | `20 0 * * 1-5` | 09:20 |
| health | `25 0 * * 1-5` | 09:25 |
| food-travel | `30 0 * * 1-5` | 09:30 |
| gaming | `35 0 * * 1-5` | 09:35 |

`generate.yml` 은 `concurrency: generate-main` 으로 **직렬 실행**되므로 7개가 09:05부터 차례로
~3분씩 돈다(총 ~21분). `github.event.schedule` → 카테고리 매핑에 4줄 추가.

## 5. 프롬프트

신규 4개 프롬프트(`.github/prompts/<id>.md`). 각자 `# 역할`·`# 리서치`(도메인별)만 다르고,
`# 출력`·`# 금지` 는 기존 3종과 **바이트 동일**(인라인 각주 필수 + 출처 정확성 지침 포함)해야 한다.

- electronics: 한국 가전·모바일·반도체 신제품/리뷰/업계. 공식 발표·기술매체·리뷰 소스.
- health: 한국 의료·바이오·제약·건강정책. 공신력 있는 매체·기관 발표. **의학적 조언 아님** 고지 톤.
- food-travel: 한국 화제 맛집·여행지. 인스타·블로그·매체의 트렌드 신호 + 위치·운영정보 등 검증 사실. 과장·광고성 표현 지양.
- gaming: 온라인·모바일·콘솔 게임 출시·업데이트·이스포츠·업계. 공식·게임매체 소스.

## 6. OG 이미지

`scripts/make-og.py` 의 `CARDS` 에 4개(색·이름·문구) 추가 후 실행 → `public/og/<id>.png` 4장 생성·커밋.
헤드리스 Chrome + `sips` 사용(기존 방식). 색은 §3 accent 와 일치.

## 7. 빈 컬렉션 처리

첫 생성 전까지 `content/<id>/` 는 비어 있다. Astro glob loader 가 빈 컬렉션을 허용하는지,
빈 카테고리에서 홈·목록·RSS 가 깨지지 않는지 확인해야 한다(빈 상태 페이지 `.empty` 처리 존재).
빈 폴더는 git 이 추적 안 하므로 `.gitkeep` 또는 첫 리포트 생성으로 채운다.

## 8. 검증

- `npm run build`(zod) + `npm run check`(타입) — 7개 컬렉션·유니온·색토큰 정합.
- **Quality 게이트 pa11y 로컬 dry-run** — 신규 색(칩·solid)이 WCAG2AA 대비 통과하는지. 실패 시 색 조정.
- 신규 카테고리 페이지(빈 상태)·홈·아카이브가 깨지지 않는지 브라우저 확인.
- 가동: 각 신규 카테고리 `workflow_dispatch` e2e 1회로 첫 리포트 생성·커밋 확인(비용 감안, 순차).
